# 기존 토픽 대본·연관 자료 리페어 프로세스

기준일: 2026-09-12

이 문서는 앞으로 기존 기준으로 제작된 토픽을 하나씩 개정할 때 따르는 작업 교본이다. 대본만 교체하고 낡은 이미지·설명문·자막을 남기는 것을 방지하는 것이 목적이다. 신규 제작은 [신규생성프로세스.md](신규생성프로세스.md)를 따른다.

## 1. 필수 원칙

1. 한 번에 수정 대상을 명확히 지정한다. 제목만으로 찾지 않고 사용자, 토픽 ID, 프로젝트 ID를 확인한다.
2. 수정 전 원본을 백업하고, 읽을 수 있는 전체 수정 대본을 사용자에게 제시한다. 승인 전 저장 대본을 교체하지 않는다.
3. 승인한 대본 버전을 기준으로 자막·대사·이미지·프롬프트·메타데이터·썸네일을 재검증한다.
4. 사용자 승인과 자동 품질 검수 통과는 별개다. 승인 사실을 독립 검수 통과 증거로 대체하지 않는다.
5. 장면 ID·순서·개수를 유지한다. 기존 53씬을 글자 수 초과 때문에 55씬으로 자동 확장하는 식의 변경을 금지한다. 53씬은 모든 토픽의 공통 상한이 아니다.
6. 구조 변경이 반드시 필요하면 이유와 매핑 변경안을 제시하고 별도 승인받는다. 이미지를 번호순으로 밀어 연결하지 않는다.
7. 없는 이미지나 실패한 이미지를 다른 장면 이미지로 대신 채우지 않는다. 미완료 상태를 명시한다.
8. 사용자 업로드 파일은 임의로 삭제하지 않는다. 새 대본과 맞지 않는 연결의 해제·재검증과 원본 파일 삭제를 구분한다.
9. 영상클립 제작은 범위 밖이다. 전체 장면 이미지와 첫 12씬 영상 프롬프트까지만 다룬다.
10. 한 토픽의 적용·검증 결과와 남은 작업을 보고한 뒤 다음 토픽으로 넘어간다. 같은 제목의 다른 프로젝트를 함께 고치지 않는다.

## 2. 작업 시작: 대상과 원본 고정

다음 항목을 작업 기록에 남긴다.

- 사용자 식별 정보, 토픽 ID, 프로젝트 ID, 제목
- 현재 프로젝트 상태와 기존 제출 건 식별 정보
- 원본 대본 버전 또는 해시, 장면 수, 장면 ID·순서
- 현재 자막·대사 판별·음성 연결 상태
- 캐릭터 이미지, 장면 이미지, 첫 12씬 영상 프롬프트의 실제 상태
- 메타데이터, 썸네일 원본 배경·레이어·완성본 상태
- 원래 토픽 패키지가 저장된 로컬 위치, Supabase 연결, Drive 파일·폴더 식별 정보
- 백업 위치와 복구에 필요한 원본 데이터

저장 위치는 추측하지 않고 실제 기존 연결을 조회해 확정한다. 다른 폴더에 고립된 개정본을 만들고 기존 패키지까지 갱신됐다고 보고하지 않는다.

## 3. 대본 분석·제안·승인

### 분석 기준

- 카테고리에 맞는 화법인가? 억지 구연체, 기계적인 어미 순환, 지나치게 잘린 문장이 없는가?
- 인물의 행동과 선택에 원인이 있고, 사건의 결과가 다음 장면으로 이어지는가?
- 인물 관계·시간·소품·설정이 모순되지 않는가?
- 시니어가 화면 없이 들어도 인물과 상황을 따라갈 수 있는가?
- 재미를 과장·자극성만으로 판단하지 않고 갈등, 궁금증, 감정 변화와 결말의 설득력으로 검토했는가?
- 실제 사실을 다루는 카테고리에서 근거 없는 주장이나 단정이 없는가?

### 제안과 승인

1. 문제 장면과 원문 근거를 제시한다.
2. Astra로 전체 수정 대본을 작성하고, 사용자가 읽을 수 있는 문서로 제시한다.
3. 줄거리·인물·결말·장면 구조의 주요 변경과 예상되는 이미지 재작업 범위를 함께 알린다.
4. 사용자가 승인한 정확한 버전과 승인 시점을 기록한다.
5. 승인 후 의미 있는 내용 변경이 추가로 필요하면 수정안을 다시 제시한다.

3197의 사용자 선호 사례는 참고 사례일 뿐이다. 그 줄거리·문장·어미·길이를 다른 카테고리에 복제하지 않는다. 독립 검수에는 사용자가 선호했다는 힌트를 넣어 통과를 유도하지 않는다.

## 4. 승인 대본 적용

1. 개연성·시니어 청취·자연스러움·재미 및 구조 검수를 수행하고 결과를 기록한다. 미해결 문제는 숨기지 않는다.
2. 적용 직전에 원본 버전이 그대로인지 다시 확인한다. 사용자가 그사이 편집했다면 덮어쓰지 말고 충돌 내용을 확인한다.
3. 승인 대본과 장면별 텍스트를 같은 버전으로 저장한다. 전체 대본과 장면 텍스트가 누락·중복 없이 일치하는지 검사한다.
4. 장면 ID·순서·개수가 보존됐는지 확인한다. 문장 중간에서 잘려 의미 없는 꼬리 장면이 생기지 않게 한다.
5. 해당 프로젝트와 토픽 패키지의 갱신 대상을 명시한다. 다른 사용자 프로젝트, 사용자 수정본 또는 제출본으로 자동 전파하지 않는다.

## 5. 대사·자막·음성 정리

1. Astra가 최종 대본 전체를 읽고 실제 대사·화자·정확한 원문 위치를 새로 판별한다.
2. 이전 대본의 대사 판별 결과를 재사용하지 않는다. 원문 버전과 판별 결과의 일치를 확인한다.
3. 대사와 나레이션을 별도 자막 블록으로 나누고, 화자가 바뀌어도 블록을 분리한다.
4. 확정 대사만 노란색으로 표시한다. 불확실한 부분을 규칙으로 추측해 확정하지 않는다.
5. 분리 전후 전체 텍스트, 장면 연결, 시간 범위 보존을 확인한다.
6. 수정·분리로 맞지 않게 된 기존 TTS 및 블록 음성 연결은 무효화한다. 음성을 재생성하지 않았다면 음성 완료라고 보고하지 않는다.

## 6. 이미지와 프롬프트 영향 평가

각 장면에 대해 다음 기준으로 유지·수정·재생성을 결정하고 기록한다.

| 변경 내용 | 필요한 처리 |
| --- | --- |
| 말투·어미만 변경되고 사건·인물·장소·행동이 동일 | 기존 이미지와 프롬프트를 대본과 대조한 뒤 유지 가능 |
| 행동·소품·장소·시간대·감정 표현 변경 | 해당 이미지 프롬프트 수정, 기존 이미지 적합성 검수 후 필요한 이미지 재생성 |
| 주요 인물 외형·정체성 변경 | 캐릭터 참고 이미지 재검토 및 해당 인물이 나오는 장면 전체 영향 평가 |
| 줄거리·사건 순서·결말 변경 | 관련 장면 이미지와 프롬프트, 메타데이터, 썸네일까지 재검토 |
| 첫 12씬 내용 변경 | 해당 영상 프롬프트도 수정. 영상클립은 생성하지 않음 |
| 승인된 장면 구조 변경 | 이전·이후 장면 ID 대응표 작성 후 모든 연결 재검증 |

실제 이미지 제작 시 캐릭터 참고 이미지와 카테고리별 이미지 스타일을 적용한다. 프롬프트 파일이 있다는 사실은 실제 이미지가 생성됐다는 증거가 아니다.

## 7. 메타데이터와 썸네일 수정

- 제목·설명문·태그 등에서 이전 대본의 인물·소품·줄거리가 남았는지 확인한다.
- 썸네일 문구가 새 대본과 일치하는지 검수하고, 거짓 반전이나 내용과 무관한 클릭 유도를 제거한다.
- 새로 만드는 썸네일은 글자 없는 원본 배경과 편집 가능한 문구 레이어로 분리한다.
- 배경 주소에는 영구 저장 URL을 사용한다. `blob:` 주소나 합성 완성본을 편집용 배경으로 저장하지 않는다.
- 배경 준비만으로 최종 완료 처리하지 않는다. 사용자가 저장할 때 1280×720 최종 이미지를 렌더링한다.
- 사용자 확정 썸네일을 교체해야 한다면 변경 범위를 설명하고 승인받는다. 저장된 사용자 디자인을 무조건 덮어쓰지 않는다.

## 8. 패키지 저장·제출 건 처리

1. 개정 대본과 구조, 대사 판별 결과, 프롬프트, 이미지 연결, 메타데이터, 썸네일 편집 데이터를 같은 개정 버전으로 묶는다.
2. 기존 토픽의 패키지 저장 위치에 개정본을 연결한다. 로컬·Supabase·Drive 중 실제 사용 중인 저장 대상을 확인하고 각 반영 여부를 기록한다.
3. 파일은 버전 또는 콘텐츠 해시가 구분되는 경로로 저장해 이전 원본을 보존한다.
4. DB 저장 응답뿐 아니라 재조회한 값과 실제 파일 접근을 검증한다.
5. 유저웹이 읽는 대상 프로젝트에 같은 버전이 연결됐는지 확인한다. 큐만 수정하고 웹까지 반영됐다고 보고하지 않는다.
6. 기존 제출 건이 있다면 프로젝트 데이터와 업로드용 스냅샷을 별도로 비교한다. 동기화 권한과 작업 상태를 확인한 뒤 처리한다.
7. 이미 업로드됐거나 처리 중인 제출 건을 무조건 다시 제출하거나 재업로드하지 않는다. 필요한 조치를 사용자에게 설명한다.

## 9. 최종 검증 체크리스트

- [ ] 사용자·토픽·프로젝트가 정확하고 다른 프로젝트는 변경되지 않았다.
- [ ] 원본 백업과 사용자 승인 버전이 기록돼 있다.
- [ ] 저장된 전체 대본과 장면별 텍스트가 승인본과 일치한다.
- [ ] 장면 수·ID·순서가 유지되거나 별도 승인된 대응표와 일치한다.
- [ ] 끝부분을 포함해 각 장면 이미지가 해당 장면 내용과 맞는다.
- [ ] 이미지 누락을 다른 장면 이미지로 대체하지 않았다.
- [ ] 캐릭터 참고 이미지와 실제 장면 이미지의 접근·연결을 확인했다.
- [ ] 첫 12씬 영상 프롬프트가 최종 대본과 일치한다.
- [ ] 대사 판별이 최신 대본 기준이며 대사·나레이션·화자별 블록이 분리돼 있다.
- [ ] 오래된 음성 연결을 정리하고 재생성 필요 여부를 표시했다.
- [ ] 메타데이터와 썸네일에 이전 줄거리의 잔재가 없다.
- [ ] 썸네일 원본 배경과 문구를 재편집할 수 있고 최종 저장 상태가 정확하다.
- [ ] 기존 패키지 저장 위치와 웹 연결 데이터의 개정 버전이 일치한다.
- [ ] 기존 제출 건의 동기화 필요 여부와 처리 결과를 별도로 기록했다.
- [ ] 대상 사용자 웹에서 재접속 후 표시를 확인했다. 로그인 검증이 불가능했다면 미확인으로 기록했다.

API 조회·파일 접근 확인만 수행했다면 실제 사용자 화면을 확인했다고 표현하지 않는다. 미확인 항목이 있는 동안에는 전체 완료로 보고하지 않는다.
