# 모든 이미지 씬의 선택적 소재 재사용

앞으로 로컬 대본 워커에서 새로 예약하는 신규/근거 기반 대본 작업은
`reuse_check_policy=compatible_first_v3`를 요청에 저장한다.
기존 v2 요청은 원래 판단 방식과 큐를 유지한다.
기존 작업·토픽·완성 이미지·매니페스트는 변경하지 않는다. 이전 작업의 재시도는 저장된
정책을 유지한다. 수정 모드에는 새 정책을 강제로 추가하지 않는다.

최종 대본을 만드는 공통 로컬 워크플로에서 `03b_optional_reusable_scene_assets`가
모든 이미지 씬을 검토한다. `script_only` 경로 및 50씬 이하의 짧은 작업에도 적용한다.
씬 번호나 집중 효과 범위로 제한하지 않는다. 업로드 영상은 재생성/합성 대상에서 제외한다.

`structure.reusable_scene_assets`의 새 형식은 `reusable-scenes-v2`다.
각 이미지 씬에 `reuse_check` 판단 이유와 다음 중 하나를 저장한다.

- `mode=compose`: 공용 배경과 투명 캐릭터 포즈를 조합한다. 배경만 공유하고 포즈를 새로
  만들거나, 포즈만 공유하고 배경을 새로 만들 수 있다.
- `mode=standalone`: 호환 소재가 없거나 독립 그림이 더 적합하면 기존 기본 이미지 생성
  경로를 사용한다. 공용 소재가 하나도 없는 계획도 유효하다.

같은 장소 이름만으로 재사용하지 않는다. 시간·조명·원근·카메라 구도 및 인물의 정체성·복장·
자세·표정·행동·위치·소품이 맞는지 먼저 확인한다. 최소 재사용 수량이나 비율을 강제하지 않는다.
복잡한 상호작용이나 미등록 단역은 새 완성 이미지로 생성할 수 있다. 환경 씬에는 인물을
추가하지 않고, 합성 씬에는 정확한 등장인물과 앞뒤 순서를 유지한다.
검증 오류는 거절된 응답과 오류를 전달해 최대 3회까지 수정한다.

제출 전에는 기본 씬 이미지만 준비·게시하고, AE용 레이어/PSD 제작·검수는 제출 후 제작
워커에서 처리한다. 새 계획의 `layer_production_stage=post_submission`을 매니페스트까지
보존한다. 공용 투명 포즈는 기본 이미지의 합성 소재이며 AE 레이어 검수 완료를 뜻하지 않는다.
기본 이미지 게시 과정에서 깊이 프록시나 PSD 전파도 실행하지 않는다.

`cowork_scene_assets.py export`가 계획을 내보내고, `crop` 또는
`generate-independent-scenes`가 선택된 합성 씬만 처리한다. 복구 큐는 공용 합성으로만
구성된 그리드를 요청하지 않는다. 혼합 그리드에서는 standalone 씬 패널만 사용한다.
`shared-assets/`에는 원본 캐릭터와 계획 해시에 연결된 PNG 및 생성 영수증이 남는다.
씬별 `scene-NNN-shared.json`에는 실제 소재 경로·해시·조합표가 남는다.
재실행 시 검증된 소재를 재사용하며 기존 결과나 변경된 원본을 덮어쓰지 않는다.
최종 `scene-NNN.png`는 기존 웹 씬 가져오기·게시·렌더 경로를 사용한다.

기존 `reusable-scenes-v1`의 51씬 이후 전체 매핑 계약은 그대로 해석한다.
기존 파일을 새 형식으로 자동 변환하거나 다시 계획하지 않는다.

합성은 고정 카메라·전체 화면 방식이다. 자동 재조명·관절 변형은 수행하지 않는다.
실제 작품의 구도·행동·조명 검토와 품질 노트는 기존 제작 절차에서 별도로 기록한다.
테스트는 합성용 이미지와 가짜 생성기를 사용하므로 실제 이미지 품질 및 최종 AE 렌더
완료와는 구분한다.


새 작업의 생성량 최적화는 추가 모델 호출 없이 로컬 계산으로 수행한다.
호환된 소재 공유 그룹별로 필요한 배경·포즈 수와 남은 이미지 씬의 2×2 요청 수를 더해,
전부 기본 이미지로 생성할 때보다 예상 호출 수가 적은 그룹만 선택한다. 동률이거나 더
많으면 standalone으로 둔다. 최적화가 원래 호환성 판단이나 대본 내용을 변경하지 않는다.
이 계산은 생성 요청 횟수의 보수적 추정이며 실제 크레딧 가격·실행 시간의 보장이 아니다.
`generation_optimization`에 기준 호출 수·선택 후 호출 수·예상 절감 수를 기록한다.

`image_request_policy=reuse_excluded_v1` 매니페스트에는 `image_requests`가 함께 저장된다.
생성기는 원본 `grids`가 아니라 복구 큐의 runnable 요청만 실행한다. 재사용 씬과 업로드
영상을 제외한 나머지를 씬 순서대로 4개씩 다시 묶는다. 마지막 1씬은 단일 이미지,
2~3씬은 재사용 씬을 끌어오지 않고 마지막 새 씬 패널로 채운 2×2 요청을 사용한다.
품질 오류로 개별 씬으로 나눌 때는 채움 패널을 중복 생성하지 않는다. 원본 씬별 프롬프트와
해당 씬의 캐릭터 참조를 유지하며, 새 생성·크롭·게시 대상은 정확히 같은 씬 집합을 따른다.
기존 정책 없는 매니페스트와 진행 중 작업의 큐·해시·생성 결과는 재편성하지 않는다.
