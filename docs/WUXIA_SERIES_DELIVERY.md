# 무협 연작의 회차 완료와 재개

2026-11-04 사용자 지시. 대상은 「나 혼자 무공을 진화시킨다」 연작이다.

다른 컴퓨터에서 이어받을 때는 [현재 상태와 복원 절차](WUXIA_HANDOFF_2026-11-04.md)를 먼저 읽는다. 1·2화 텍스트 원본과 원격 자산 복원 지문은 `docs/wuxia-handoff/`에 보존했다.

## 확인한 중도 종료 원인

1. 대본, 원화, 연출 패키지 등 중간 산출물에서 응답을 끝내고 다음 지시를 기다렸다. 이는 실행 실패가 아니라 감독자의 범위 추적 실패였다.
2. 웹 등록과 후속 음성·AE 렌더를 혼동해 등록 완료와 무관한 단계를 제약처럼 제시했다.
3. 제목·디스크립션·썸네일·번역·자산 업로드를 처음부터 회차 작업 목록에 포함하지 않아 마지막에 별도 작업이 됐다.
4. 파일별 생성 이력이 세션 메모리에 의존했고, 오래 걸리는 이미지 요청을 회차 상태와 분리해 추적하지 못했다.
5. 등록 확인서는 성공인데 script-summary의 등록 상태는 false로 남았다. 상태를 여러 곳에 하드코딩해 보고가 어긋났다.
6. 업로드용 로컬 환경에서 requirements-script.txt의 psd-tools와 google-auth가 설치되지 않아 뒤늦게 보완했다. 계정이나 AE PC의 문제가 아니었다.
7. 2화 검토 번역에서 UTF-8 원본은 정상인데 하위 Windows 도구의 한글 전달이 대체문자로 변했다. 단계 입력 JSON을 ASCII 유니코드 이스케이프로 저장해 원문을 보존하고, 번역은 작은 묶음마다 원문 인덱스와 함께 체크포인트를 남긴다.

## 이번 연작의 실행 계약

- 기존 확정값: 50화 오리지널 성장 서사, 한국어·가상 전근대 강호, wuxia_webtoon, 영상클립 0, 상태 원화+AE, 고정 카메라, 느린 줌 없음. 상황에 맞는 타이포와 실제 대사 말풍선을 분리한다. 음악은 프롬프트만.
- 사용자가 다음 회차 시작을 지시하면 이 설정과 등록까지의 범위를 이어받는다. 설정 변경이나 필수 정보 충돌이 있을 때만 해당 부분을 확인한다.
- 순서: 직전 회차의 확정 결말/부상/소품 확인 → 대본 및 독립 검수 → 실제 원화·필요 레이어와 연출 → 검토 번역 → 제목·설명·편집 가능한 썸네일 및 공통 렌더러 저장 → 자산 업로드/해시 검증 → 웹 준비 판정 → 중복·소유권 확인 → 등록 → 저장 재조회.
- 모든 단계의 산출물과 원문 지문을 파일에 보존한다. 이미지 호출은 자산 ID별로 기록하고, 진행 중 요청을 중복 실행하지 않는다. 복구 시 존재하는 파일을 먼저 검증하고 재사용한다.
- 품질 우려는 품질 기록에 사실대로 남기며 승인된 제작을 계속한다. 깨진 파일·유실된 저장·소유권 충돌은 완료로 표시하지 않고 안전하게 복구한다. 취소 요청은 즉시 보존한다.
- 실제 파일은 등록 전에 완성한다. `registration-receipt.json`의 ID·본문 해시·장면 수·실제 자산 수와 재조회 결과가 맞아야 회차 납품 완료다. 프리뷰, 프롬프트 수, POST 응답만으로 완료로 표시하지 않는다.
- 이미지 응답을 수십 장씩 한 도구 출력에 쌓지 않는다. 자산별로 즉시 저장하고 원본 경로·해시를 기록한다. 도구 표시 용량 오류와 실제 저장 실패를 구별하며, 이미 저장된 원화를 중복 생성하지 않는다.
- 후속 음성·AE 렌더는 회차 등록을 기다리게 하는 조건이 아니다. 관리자 게시와 YouTube 업로드는 이 범위에 포함하지 않는다.
- 진행 중에는 다음 승인된 단계를 실행하며 상황을 알린다. 중간 산출물을 전체 완료로 보고하거나 ‘계속할까요’로 종료하지 않는다.
- 현재 등록 상태는 회차별 packaging/registration-receipt.json과 등록 재조회 원본을 기준으로 한다. 이전 단계의 불변 원본 스냅샷은 덮어쓰지 않으며 요약 상태만 최신 확인서로 재생성한다.
