# 무협 생성 개선 지침의 실행 경로

## 실제로 연결한 범위

- `script_worker_guidance.load_production_guidance`: 매 호출마다 문서와 `wuxia_generation_gate`의 현재 규칙을 읽는다. 이전 작업 시작 시의 문자열만 재사용하지 않는다.
- 수동 단계 및 씬별 프롬프트 생성: 적용 정책 SHA와 범위를 결과에 기록하고 이전 문제 기록을 생성 입력으로 전달한다. 사용자 텍스트 저장은 적용/검수 통과로 표기하지 않는다.
- 로컬 대본워커: 실행 지침, 개선 지침 저장·적용, 씬별 문제 기록, 실제 이미지 생성 입력 점검을 제공한다. 기존 프롬프트에 적용 버전이 없거나 다르면 재검토 필요로 표시한다.
- 실제 이미지 입력: `/api/jobs/{id}/scene-quality`의 `prepare_arguments` 동작을 호출한다. 현재 대본/프롬프트/정책 버전, 준비 계획과 미해결 문제를 확인한 후에만 도구 인자와 준비 영수증을 반환한다. 반환된 도구 인자를 그대로 사용한다. 이 API가 image_gen 자체를 호출하거나 이미지를 승인하는 것은 아니다.
- 근거 검증: 실제 파일·SHA·이미지 디코딩, 필요한 파손 상태, 직전 원화 관찰, 인물/석상 상태표, 접촉의 원인/결과, 화풍·구조 참조가 필요하다. 기본 도구 참조는 최대 5개다.
- 실제 픽셀 재검수: 파일과 정책 SHA에 연결된 세부 검수만 유효하다. 실패·불확실·누락·기존 SHA와 불일치하면 사용 제외. 문제 해결 메모만으로 원화가 통과되지 않는다.
- 기존 자동 해부학 검수: 정책 SHA를 검수 캐시 키에 포함하므로 지침 변경 후 옛 결과를 그대로 재사용하지 않는다. 현재 규칙을 실제 원화 검수 입력에도 포함한다.
- 이 컴퓨터의 AE native timeline 준비: 사용자 지적으로 사용 제외된 원본 SHA를 거절한다. 기존 정상 확정 회차를 일괄 재작성하지 않는다.

## 수정/갱신과 보존

기본 항목은 `docs/wuxia-generation-rules.json`, 명시적 로컬 운영자 추가 규칙과 이력은 `output/codex-local-console/wuxia-rule-updates/`에 저장된다. 이 로컬 실행 지침은 이 컴퓨터에 적용되며 다른 컴퓨터에 자동 배포됐다는 의미가 아니다. 기존 DB의 대본 개선안 승인 흐름과 별개이며, DB 대기 개선안을 자동 승인하지 않는다.

문제 기록은 작업의 `manual_workflow.quality_control[scene_id]`에 저장·동기화된다. 실제 파일의 사용 제외 SHA는 로컬 정책 저장소에도 남긴다. 명시적 사용자 수정 요구에 따른 기록/갱신은 Codex가 수행할 수 있다. 모델 출력이나 원화 속 문구는 활성 지침을 변경하는 권한이 없다.

## 한계와 검증 범위

검사 코드는 증거의 존재·형식·버전·파일 일치를 검증한다. 손의 좌우나 접촉의 설득력을 자동으로 완벽하게 판별한다고 주장하지 않는다. 실제 그림을 열어 관찰하고 불명확한 경우 제외하는 검수는 여전히 필요하다. 자유로운 외부 image_gen 호출 자체를 전역 차단하는 기능은 아니며, Codex 수동 제작도 AGENTS.md의 준비 경로를 따라야 한다.

이번 1~5씬의 종전 검수 완료 판정은 철회했고 파일은 보존하면서 사용 제외했다. 재생성·원화 재검수·렌더를 이 변경의 검증 결과로 보고하지 않는다.

## 영구 적용 강화 (2026-11-24)

- 석상 손 구조, 틈의 기능 설명, 단검의 손잡이–가드–칼날 축 검사를 공통 기본 규칙에 포함했다. 로컬 갱신 이력은 유지하며 같은 ID의 로컬 항목은 중복 추가하지 않고 병합한다.
- 모든 새 생성 계획은 각 현재 규칙별 `rule_applications`를 갖춰야 한다: 실제 참조에서 관찰한 `observation`, 입력에 구체적으로 반영할 `input_action`, 새 픽셀에서 확인할 `verify_after_generation`. 빈 기록이나 누락이 있으면 생성 인자를 반환하지 않는다. 이 기록은 검수 통과가 아니다.
- 반려된 원화를 `previous_art`에 넣어 다음 컷의 기준으로 사용하는 경로를 차단한다. 수정 대상 첨부 예외로 다음 컷 참조 제한을 우회할 수 없다. 수정 대상은 문제 확인용이며 승인 자산이 아니다.
- 워커 배포 묶음에 공통 규칙 JSON과 실행 경로 문서를 포함한다. 다른 컴퓨터의 설치·적용은 별도로 확인해야 하며 이 변경만으로 원격 배포를 주장하지 않는다.

## 모든 대본 워커 공통 등록

`scripts/publish_wuxia_generation_guidance.py --apply --env-file worker/connection.env`는 사용자가 명시적으로 승인한 공통 규칙을 기존 `script_guideline_versions` 경로에 등록하고 승인 상태를 읽어 확인한다. 내용 기반 ID로 재실행 중복을 막고, 거절/폐기된 규칙을 자동 재활성화하지 않는다. 전체 카테고리/언어에 전달하되 무협 작업에만 무협 설정을 적용하도록 명시한다. 연결된 기존 대본 워커는 새 작업 시작 시 `approved_guidelines`에서 이 지침을 받는다. 기존 실행 중 작업의 입력을 소급 변경하거나 각 컴퓨터의 실행 코드까지 자동 교체하는 기능은 아니다. 실제 공통 등록과 컴퓨터별 새 코드 설치/재시작은 각각 확인한다.

## 한 컷의 초점과 입력 범위 (2026-11-24 사용자 정정)

모든 새 준비 계획은 `render_focus`에 `event`, `reader_takeaway`, `visible_subject_ids`, `one_instant:true`, `cut_count:1`을 기록한다. 전체 씬의 동작 단계를 관성적으로 여러 이미지로 늘리지 않는다. 화면에 보일 대상으로 확인되지 않은 인물의 자료를 붙이지 않는다.

생성 전 검사는 전체 상태표와 모든 규칙을 읽지만 이미지 모델에 보내는 상태표는 별도다. `prepare_scene_imagegen_arguments`는 화면 등장 ID에 해당하는 상태만 보내고, 다음 씬 방향/화면 밖 인물/전체 대본을 그대로 덤프하지 않는다. 생성 지시는 각 규칙의 이번 컷 `input_action`으로 좁히고 `applicability:not_visible` 항목의 설명을 그림 요구로 넣지 않는다. 실제 픽셀 검수는 여전히 전체 필수 규칙에 근거를 남긴다. 필터/영수증 검증은 새 이미지의 정상 판정과 별개다.

이번 2씬은 사용자가 새로 지정한 배경·인물 없는 석상 파열 한 장으로 대체한다. 이전 불량 인물 원화를 잘라 수리한 것이 아니며 그 원화는 계속 사용 제외한다. 투명 배경 선택도 계획/실제 도구 인자에 기록한다.
