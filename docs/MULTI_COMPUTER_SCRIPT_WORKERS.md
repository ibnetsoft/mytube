# 여러 컴퓨터에서 대본 워커 운영

2026-11-01부터 서로 다른 컴퓨터가 서로 다른 대본을 동시에 생성할 수 있습니다.
웹에서 등록한 토픽은 기존처럼 로컬 워커의 검토/승인 화면에서 선택합니다.
자동으로 모든 대기 대본을 가져가거나 중단된 다른 컴퓨터의 작업을 인계하는 기능은 아닙니다.

## 각 컴퓨터 준비

1. 모든 컴퓨터에서 최신 `main`을 pull하고 실행 중인 대본 워커를 재시작합니다.
2. 각 컴퓨터에 Python 환경, 워커 의존성, Codex CLI를 설치하고 `codex login`을 완료합니다.
3. `worker/connection.env.example`을 참고해 같은 운영 DB의 URL과 service-role 키를 **각 컴퓨터의 로컬 설정 파일**에 입력합니다. 실제 키는 Git에 커밋하거나 배포 번들에 넣지 않습니다.
4. 워커 ID는 기본적으로 컴퓨터 이름과 프로젝트 경로에서 생성됩니다. 직접 지정할 경우 `AIR_SCRIPT_WORKER_ID=studio-mac-01`처럼 컴퓨터마다 다른 값을 사용하고, 운영 중에는 유지합니다.

Mac/Linux 실행 예:

```sh
.venv-script/bin/python -m worker.launch --role script --env-file worker/connection.env
```

Python 실행 파일 경로는 각 컴퓨터의 가상환경에 맞게 변경합니다.
각 컴퓨터에서 `http://127.0.0.1:3003`을 열어 사용합니다. 다른 컴퓨터에서 이 주소로 접속하면 그 컴퓨터 자신의 워커가 열립니다.
`--check`는 Python 모듈과 CLI 설치 검사이며, 실제 DB 연결/대본 생성 성공 검사는 아닙니다.

## 동시 실행 규칙

- 컴퓨터별 대본 1건, 컴퓨터 간에는 병렬 실행합니다.
- 다른 컴퓨터의 실행 중인 작업을 조회해도 이 컴퓨터의 시작 버튼을 차단하지 않습니다.
- 같은 웹 토픽, 같은 대본 원본의 수정 작업, 같은 실패 작업의 재시도는 중복 실행을 차단합니다.
- 결과 저장은 DB revision을 검사합니다. 다른 컴퓨터가 먼저 수정한 버전을 오래된 로컬 복구본으로 덮어쓸 수 없습니다.
- 저장 응답만 유실된 동일 요청은 이미 저장된 revision을 돌려주므로 다시 AI 작업을 실행하지 않습니다.
- 자막 번역은 기존 DB 원자적 선점(`FOR UPDATE SKIP LOCKED`)을 유지하고 로컬 Codex CLI로만 처리합니다.
- 이미지/좌표/PSD 준비는 기존 작업 선점과 heartbeat를 유지합니다. 영역 레이어 준비는 소유권 상실 시 저장을 중지하고 시도별 출력 경로를 사용합니다.
- 재시작은 해당 워커의 실행 작업만 중단으로 표시합니다. 다른 컴퓨터의 작업을 임의로 재실행하지 않습니다.
- 장별 중간 산출물은 로컬에 남으므로 긴 대본을 이어서 작업하려면 원래 컴퓨터에서 재시도하는 것이 좋습니다. 다른 컴퓨터로 이동할 때는 로컬 복구 폴더도 보존해야 합니다.

## DB 적용 및 검증

`supabase/migrations/20261101092756_multi_computer_script_workers.sql`을 운영 DB에 적용해야 합니다.
이 변경은 전역 실행 제한을 워커별 제한으로 바꾸고 `save_script_worker_job` RPC와 revision을 추가합니다.
기존 워커를 최신 코드로 함께 업데이트해야 버전 충돌 보호를 사용할 수 있습니다.

검증 SQL: `tests/sql/multi_computer_script_workers.sql`.
테스트용 작업만 생성한 뒤 rollback하며 실제 모델 호출이나 사용자 콘텐츠 변경은 하지 않습니다.
독립 작업 허용, 같은 워커/수정 원본/웹 토픽/재시도 중복 차단, 오래된 저장 거부, 응답 유실 재시도, RPC 접근 권한을 검사합니다.

## 이번 검증

- 운영 DB의 마이그레이션 적용과 rollback 전용 SQL 검사를 완료했습니다.
- 대본 콘솔/저장/웹 토픽/영역 작업/자막 번역 관련 Python 테스트 65개가 통과했습니다. 두 워커 실행기의 동시 실행은 모델을 대체한 테스트로 확인했습니다.
- 서로 다른 실제 컴퓨터에서 Codex 대본을 동시에 생성하는 실기 검증은 아직 하지 않았습니다.
- 이 Mac의 `worker/connection.env`에는 DB URL과 키가 비어 있어 워커를 시작하지 않았습니다.
