# PSD 기반 AE 장면 연출

기존 수동 영상 업로드 → TTS 생성 → 제출 순서를 유지하면서, 선택한 씬을 PSD 원화로 애니메이션화하는 경로다. 영상 생성 API는 필요하지 않다. PSD 작업이 선택된 씬은 준비된 AE 출력이 최종 화면이 되고, 업로드한 영상은 연출 참고 자료로 사용된다. 선택하지 않은 씬은 기존 제작 경로를 따른다.

## 사용자 흐름

1. AIR Studio 프로젝트의 자료 영역에서 **PSD로 AE 장면 연출**을 연다.
2. 씬별 PSD/PSB 원본을 올리고 원하는 카메라, 움직임, 빛, 다음 컷 연결을 입력한다.
3. **레이어·연출 준비**를 누른다. 로컬 작업자가 실제 원화와 레이어를 확인하고, 필요하면 빈 배경만 정지 이미지로 복원한다. 분리되지 않은 부위나 없는 신체 그림이 필요하면 보완을 요청한다.
4. 준비가 완료되면 기존 순서대로 음성과 자막을 확정하고 제출한다. 준비 작업 자체는 최종 TTS 이전에도 할 수 있다.
5. 제출 작업은 확정 음성 길이에 맞춰 AE 장면을 만들고, 실제 출력 프레임과 음성 무결성 및 인접 컷을 검사한 후 최종 합성으로 넘어간다. 실패하거나 오래된 검수 자료로는 기존 영상에 자동 대체하지 않는다.

PSD 연출을 해제하려면 **이 씬의 PSD 연출 사용 안 함**을 선택한다. PSD, 참고 영상, 해당 씬이나 인접 씬의 대본이 바뀌면 다시 준비해야 한다. 음성 길이만 바뀌는 경우 원화 준비 결과를 재사용하고 출력 검수는 새로 수행한다.

## 지원 범위와 한계

- 원화 안에서의 카메라 이동·확대, 레이어 위치·회전·불투명도, 분리된 레이어의 시차, 제한된 빛과 컷/페이드 전환을 지원한다.
- 이미 분리된 머리카락·옷자락은 CC Bend It으로 제한된 변형을 적용한다. 임의의 PSD를 자동으로 Puppet 리깅하거나 새로운 얼굴 각도·신체 동작을 만드는 기능은 아니다.
- 현재 PSD 카메라/레이어 좌표와 기존 입모양·눈깜빡임 패치 좌표를 함께 처리하지 않는다. 같은 씬에 명시적으로 선택한 기존 입모양 또는 수동 눈깜빡임 작업이 있으면 제출을 차단하고 정리를 안내한다.
- 실제 프레임 샘플 검수와 디코딩한 음성 비교를 사용한다. 모든 프레임의 수동 검수나 음성을 직접 청취했다는 의미는 아니다.
- 인접한 일반 장면은 최종 합성에서 선택할 원본과 합성 설정을 기준으로 검수한다. 최종 크롭·팬·반복 재생까지 렌더한 화면은 아니므로, 그 변환에 따라 달라지는 정확한 동작 연결을 확인할 수 없으면 승인을 중단한다. 전체 합성 영상 검수와 구분한다.
- 원하는 연출에 원화가 부족하면 준비 실패로 표시한다. 검수 실패를 자동 승인하지 않는다.

## 실행 구성

- 웹: `auth-web/app/api/std/projects/[projectId]/ae-scene/route.ts`와 `StdAeScenePreparation` 컴포넌트.
- 준비 큐: 기존 `std_project_assets`의 `metadata.kind = ae_scene_preparation`. 별도 DB 마이그레이션은 없다. 준비/사용 안 함 전환은 새 레코드로 남는다.
- 로컬 준비: `worker/ae_scene_preparation.py`. `local_media_supervisor.py`에 준비 작업 역할을 등록했다. 기존 로컬 Codex CLI 실행기와 정지 이미지 생성 경로를 사용한다.
- 제출 후 렌더: 기존 v2 제출 파이프라인에서 `ae_scene_production.py`와 `ae_scene_animation.py`를 호출한다. PSD/레이어/연출/음성/출력의 식별정보와 검수 기록이 일치해야 재사용한다.
- 작업자 환경에 `worker/requirements-script.txt`의 의존성을 설치하고, 최신 코드를 로드하도록 supervisor를 재시작해야 한다. 네이티브 렌더에는 After Effects, aerender, CC Bend It과 기존 FFmpeg/Codex/저장소 설정이 필요하다. 웹 배포만으로 AE 실행 환경이 설치되지는 않는다.
- Windows 데스크톱 제품, 설치 파일, 릴리스는 변경하지 않는다. 관리자 게시와 YouTube 업로드도 기존 별도 단계로 유지한다.

## 검증

웹 테스트는 준비 재사용/무효화, 인증·소유권·재시도, 제출 및 출력 검수 조건을 검사한다. 브라우저 테스트는 PSD 업로드 → 연출 요청 → 대기 → 해제를 실제 컴포넌트로 실행하며, 외부 API는 테스트 응답을 사용한다. Python 테스트는 PSD 레이어 준비, JSX 생성, 실제 FFmpeg 영상/음성 및 장면 연결 검수를 포함한다.

개발 컴퓨터에 After Effects가 없어 네이티브 AE 렌더는 실행하지 못했다. 실제 PSD를 사용한 첫 장면은 AE가 설치된 작업자에서 출력까지 확인해야 한다. 자동 테스트 통과만으로 특정 원화의 시각 품질을 보장하지 않는다.
