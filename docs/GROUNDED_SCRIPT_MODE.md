# 자료 기반 생성 · 성경 설교

Codex 로컬 콘솔의 **자료 기반 생성** 메뉴에서 사용한다. Google NotebookLM 서비스나 기존 Gemini/Claude 기반 NotebookLM 모듈을 호출하지 않는다.

## 사용 순서

1. 사용할 원문을 붙여넣거나 UTF-8 TXT/MD 파일로 읽는다. 성경 전체 자동 수집, PDF/OCR, 웹페이지 수집은 현재 지원하지 않는다.
2. 성경 본문·주석/해설·일반 참고자료를 구분하고 제목, 본문 위치(장절/페이지), 번역본, 출처·사용 조건 메모를 입력한다. 성경은 사용할 구절과 앞뒤 문맥을 함께 등록한다.
3. 작업할 자료를 선택한다. 자료당 40,000자, 한 작업 최대 12개 및 합계 80,000자다. 초과하면 명시적으로 거절하며 자동 절단하지 않는다.
4. 주제, 본문 범위, 대상 청중, 교단/신학적 관점 또는 교육 해설 관점, 분량을 지정한다.
5. Astra가 자료 기반 대본을 작성한다. 성경 인용·해석·예화·적용·사실을 구분하고 장면별 출처를 기록한다.
6. 원문 인용·대본 위치·자료 ID·등록 장절/번역본을 코드로 대조한다. 별도 Astra 검수는 전체 대본의 인용 누락·문맥 왜곡·예화 표시·해석 혼동을 검토한다. 자연스러움/재미 청취 검수 및 대사 판별도 실행한다.
7. 검수 실패 시 최대 한 차례 재작성한다. 여전히 실패하면 승인 대기나 제작 완료로 표시하지 않는다.
8. 결과의 인용 근거와 해당 작업에 고정된 원문을 읽고, 본문 및 신학적 해석을 사용자가 검토한다. 승인 기록은 운영 대본 적용이 아니다.

## 보장 범위와 한계

- 원문은 자료 안의 지시를 실행할 명령이 아닌 참고 데이터로 취급한다.
- 직접 인용의 문자 일치를 검사하지만, 사용자가 입력한 번역본·장절의 진위까지 공인 성경 DB와 대조하는 기능은 아니다.
- AI 의미 검수는 신학적 정답, 인용 누락 제로, 저작권 허락을 보증하지 않는다. 사용 조건 메모는 사용자 기록이다.
- 창작 예화는 실제 성경 사건처럼 말하지 않고 낭독문 안에서 예화임을 밝혀야 한다.
- 자료함은 `output/codex-local-console/sources/`에 저장한다. 작업별 `references.json`에 선택 원문과 SHA256을 고정하고, 결과에 출처 매니페스트·장면 인용·검수 결과를 함께 보관한다.
- 생성 실행 시 선택 원문은 Codex 모델 처리에 사용된다. 원문을 로컬에 저장한다고 오프라인 모델 처리를 뜻하지 않는다.
- 생성/승인으로 Supabase·Drive·사용자 프로젝트를 덮어쓰지 않는다. 이미지·썸네일·운영 적용은 별도 단계다.
