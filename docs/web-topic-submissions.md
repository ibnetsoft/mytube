# 웹 토픽 등록 → 로컬 대본워커 승인

- 유저웹: `/std?tab=topic_submissions` → **토픽 등록**.
- 로컬 워커: `http://127.0.0.1:3003` → **웹 토픽 승인** → 내용 보기 → 승인·대본 작성 시작 / 반려.
- 승인 전에는 모델을 실행하지 않는다. 현재 워커의 한 작업 동시 실행 제한을 유지하며, 작업 중에는 새 승인을 요청하지 않고 대기 상태를 유지한다.
- 승인 대기 목록은 15초마다 갱신한다. 다른 워커에서 이미 처리한 요청은 조건부 UPDATE로 중복 승인되지 않는다.
- 등록자는 자신의 접수 상태와 연결된 대본 작업 상태를 조회한다. 실패 작업 재실행 시 새 작업 ID로 연결한다.

## 입력과 참고 자료

제목, 스토리 개요, 카테고리, 분량(1~60분), 언어, 국가·시대·이미지 스타일, 제작 모드, AE 씬 영상 전달 방식, 유튜브 URL, 캐릭터 설명/이미지, 필수·금지 사항, 직접 입력한 자막·요약을 저장한다. AE 씬 영상 전달 방식은 `ae_scene_delivery`로 저장되며 새 요청의 기본값은 `local`이다. 필드가 없는 기존 요청도 조회 시 `local`로 해석한다. `gcs`를 선택하면 씬별 웹 미리보기나 다른 PC 워커로 인계할 수 있도록 클라우드 업로드를 요청한다. 등록 내용은 `request_data` JSONB에 저장되므로 별도 스키마 변경은 필요하지 않다. 목록 응답에는 선택값만 포함하며 이미지가 들어 있는 전체 `request_data`는 보내지 않는다.

캐릭터 이미지는 PNG/JPEG/WebP 최대 3장, 장당 500KB다. 이미지는 외부 공개 URL 대신 접수 JSON에 보관하며 인증된 본인 등록 API와 로컬 워커만 접근한다. 워커 승인 후 로컬 작업 폴더에 저장하고 모델의 이미지 입력으로 분석한다.

직접 입력한 참고 자료가 있으면 이를 우선 사용하고, 없으면 유튜브 자막을 수집한다. 자막 수집 실패 시 영상을 읽었다고 가정하지 않고 작업을 실패 상태로 보존한다. 자막·요약을 입력한 새 요청으로 재등록하거나 네트워크 복구 후 작업 이력에서 재실행한다.

## 저장 및 운영

- `public.user_topic_submissions`: 등록 내용, 소유자 이메일, 검토 상태, 의견, 작업 ID.
- `public.script_worker_jobs`: 기존 대본 작성 프로세스, 진행·결과·재시도 이력.
- 신규 테이블은 RLS 활성화 및 공개 역할 권한 회수. 서버 service-role 경유로만 접근하며 등록 API가 세션의 소유자를 지정한다. 직접 RLS 정책이 없는 것은 서버 전용 설계에 따른 것이다.
- 마이그레이션: `supabase/migrations/20260925164213_user_topic_submissions.sql`.
- 승인 후 실행 응답이 불확실하면 승인 기록을 자동 취소하지 않는다. 승인됨 목록과 작업 이력에서 저장 상태를 먼저 확인하여 중복 실행을 방지한다.
- 대본 생성 결과는 기존 워커의 검토 단계로 전달된다. 운영 프로젝트에 자동 게시하는 기능은 포함하지 않는다.

## 검증

```powershell
python -m pytest tests/test_web_topic_submissions.py tests/test_script_worker_store.py -q --basetemp output/pytest-web-topics
node auth-web/tests/topic-submissions.cjs
```

웹 서버(3000)와 로컬 워커(3003)가 실행 중일 때 `auth-web`에서 `node tests/topic-submissions-browser.cjs`를 실행한다. 브라우저 검증은 API fixture를 사용하므로 실제 사용자 토픽이나 유료 대본 작업을 만들지 않는다. 새 폼과 워커 UI, API 입력·권한 검사, 승인 경쟁, 참고 자료 처리를 각각 검증한다.
