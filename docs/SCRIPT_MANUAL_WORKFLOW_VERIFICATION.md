# 단계별 수동 대본워커 검증 — 2026-11-24

## 확인한 결과

- 새 대본 기본값은 수동 네 단계다. 저장된 기존 작업의 재실행 정책은 유지한다.
- 1단계는 대본과 해당 결과 검토만 호출한다. 승인 후에도 다음 단계 호출이 발생하지 않는다.
- 각 단계에 명시적 생성, 수정 저장, 확정, 다음 단계 열기를 제공한다. 영상 컷은 체크박스로 선택·해제할 수 있고 선택 0개도 유효하다.
- 앞 단계 수정은 후속 결과를 보존하면서 확정을 해제하고 재검토 상태로 표시한다. 오래된 화면의 저장/확정, 순서 건너뛰기와 다른 컴퓨터의 변경을 거절한다.
- 실패한 단계만 재시도하며 앞 단계 확정 결과를 보존한다. Database 예약 실패 시 CLI를 시작하지 않는다. 사용자 편집은 수정 전 자동 검토를 무효화한다.
- 자동 납품 supervisor는 수동 작업을 제외한다. 네 단계 종료는 대본/프롬프트/AE 계획 작성 완료이며 실제 이미지·영상·음성·AE 렌더 또는 주제 등록 완료가 아니다.

## 검증 근거와 범위

Python API/상태 전이 회귀 검사와 JavaScript 구문 검사, 격리한 활성 `auth-web` 프로덕션 빌드를 확인했다. `tests/test_script_manual_workflow.py`는 기본 시작, 선행 확정, 무자동진행, 영상 0개, 편집 무효화, 오래된 요청/다른 소유자 거절, 단계별 실패 복구, 저장 실패, 검토 실패의 정직한 기록과 기존 작업 재실행 보존을 검사한다.

별도 localhost 검증 서버에서 실제 UI와 실제 단계 전이 API를 연결했다. 모델 결과만 고정된 fixture로 대체했으며 운영 DB에 새 대본 작업을 만들지 않았다. 브라우저에서 대사 수정·저장, 각 단계 확정/다음 단계 수동 시작, 영상 선택/프롬프트 수정, AE 지침 확정, 페이지 재접속 후 복원, 첫 대본 수정 후 2~4단계 재검토 표시를 확인했다. 이는 단계 제어 검증이며 새로운 회차의 실제 CLI 생성 결과나 원화·음성·렌더 검증이 아니다.

이 컴퓨터의 로컬 워커에도 반영하여 새 단계 안내와 JavaScript 자산 HTTP 200을 확인했다. 새 단계 API는 잘못된 입력을 422로 거절하는 실제 스키마 검사를 확인했다. 워커 교체 전에 실행 중인 대본 작업과 자식 프로세스가 없음을 확인하고 작업 기록 복구본을 보존했다. 브라우저 검증 화면은 `output/manual-workflow-qa-20261124/`에 보관했다.

## 품질 메모

단계별 자동 검토는 대본과 계획만 다룬다. 사용자 수정 뒤의 자동 검토는 새 검토를 했다고 표시하지 않으며, 사용자가 수정본을 직접 확정할 수 있다. 실제 원화의 해부학/정체성/소품/문자 보호와 최종 음성 시점, 실제 AE 출력은 각 제작 단계에서 별도로 확인해야 한다.
