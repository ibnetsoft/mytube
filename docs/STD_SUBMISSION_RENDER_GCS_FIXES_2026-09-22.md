## 2. 제출 성공인데 렌더링이 시작되지 않은 문제

### 원인과 수정

1. 워커는 제출 작업을 정상적으로 감지했으나, 설정을 읽는 즉시 `KeyError: 'bucket'`으로 실패했다.
   - `config_storage_source`와 개별 `storage_source`는 `gcs_bucket`, `gcs_path`, `gcs_signed_url`을 사용했다.
   - 존재하지 않는 `bucket` 키를 직접 참조하던 두 곳을 수정했다.
2. 제출 목록의 이미지 준비 표시가 꺼져 있었다.
   - 프로젝트 목록 API의 에셋 조회에서 `id`, `metadata`가 누락됐다.
   - 준비 상태 계산에 필요한 에셋 ID와 저장 위치가 전달되도록 조회 필드를 보완했다.
3. 렌더 설정에서 처음 12개 영상클립이 누락돼 있었다.
   - 영상 복구 경로가 Supabase 위치만 기록하고 GCS 파일 복사를 하지 않았다.
   - 영상 파일을 GCS에 복사한 뒤 렌더 에셋으로 등록하도록 수정했다.
   - 씬 미디어를 찾지 못하면 빈 항목을 넣고 진행하지 않고 오류를 반환하도록 변경했다.

### 복구 결과

- 기존 실패 패키지: 파일 42개, 앞부분 영상클립 누락.
- 복구 패키지: 파일 54개, 영상클립 12개를 포함한 씬 53개, 누락 0개.
- 프로젝트 준비 상태: 이미지/영상 53/53, 음성·자막·썸네일 완료.
- 워커 재빌드·재시작 후 최근 실패 작업 한 건을 재시도했고 이후 완료됐다.

**주의:** 제출 API의 성공은 작업 등록 성공을 의미한다. 최종 영상 완료 여부는 큐의 `status`, `progress`, `error_message`, 결과 저장 상태로 확인해야 한다. 이미 제출된 프로젝트를 처리하는 모든 분기를 이번에 재설계한 것은 아니다.

## 4. 미리보기 화면이 음성보다 빨리 넘어간 문제

저장된 전체 음성을 재생하면서 화면은 기존 씬 시간표를 사용했다. 확인한 프로젝트에서 첫 씬의 실제 음성은 약 7.63초였지만 화면은 5초 기준으로 넘어갔다.

- 합쳐진 MP3의 실제 프레임 길이로 자막 구간별 시간표를 만든다.
- 전체 음성 에셋의 `metadata.subtitle_timeline`에 시간표를 저장한다.
- 현재 자막의 텍스트·성우와 시간표가 일치하는지 검증한 뒤 사용한다.
- 미리보기는 음성의 `currentTime`을 기준으로 자막과 장면을 전환한다.
- 기존 음성 복구 시에는 조각을 합친 바이트가 전체 음성과 정확히 일치하는지 확인하고 시간표를 반영했다.

이 수정은 음성 속도를 늘이거나 줄이는 작업이 아니다. 또한 MP3 조각의 시작·끝 시점과, 조각 내부의 실제 글자별 발화 시점은 구분해야 한다.

관련 파일:

- `auth-web/lib/stdJoinMp3.ts`
- `auth-web/lib/stdStoredNarration.ts`
- `auth-web/lib/stdPreviewAudio.ts`
- `auth-web/app/std/page.tsx`
- `auth-web/app/api/std/projects/[projectId]/tts/generate/route.ts`

## 5. 같은 성우인데 3씬 첫 자막의 발화가 달랐던 문제

- 문제 문구: “그 집 대문 안에서는 남편 덕수가”.
- 현재 저장본 약 3.53초, 다른 생성본 약 2.35초였다.
- 2.35초 파일을 3.53초로 늘인 것이 아니라, 별도로 생성된 파일의 발화 길이가 달랐다.
- 당시 생성 기록은 같은 성우, 속도 0.9, 안정성 0.35, 스타일 0.45였다.
- 사용자 요청으로 STD 웹과 생성 API의 안정성 기본값을 0.7로 변경했다.
- 3씬의 두 자막을 한 문장으로 한 번에 생성하고, 제공된 타임스탬프를 기준으로 자막용 조각을 나눴다.
- 전체 미리보기 음성과 시간표를 갱신했다. 나머지 311개 음성 조각은 그대로 유지했음을 검증했다.
- 원본 파일은 보존하고 새 파일을 Supabase와 GCS에 저장했다.

이후 `18edac29`에서 STD 렌더 계획과 워커의 계획값 누락 시 기본 안정성도 0.7로 맞췄다. 명시적으로 저장한 설정값이 있으면 그 값을 우선한다. 별도 범용 `VoicePreset` 및 일부 함수 인자 기본값에는 0.62가 남아 있어, 모든 TTS 경로의 기본값을 일괄 변경한 것으로 해석하면 안 된다.

## 6. 완성 영상의 자막 싱크가 맞았다가 어긋난 문제

### 확인한 원인

워커는 자연스러운 내레이션을 위해 여러 자막을 문장 단위로 합쳐 TTS를 생성했다. 그러나 생성된 문장 안의 자막 시간은 글자 수 비율로 다시 배분했다. 실제 발화 속도·쉼이 균일하지 않아 문장 중간에서는 어긋나고 문장 끝에서는 다시 맞을 수 있었다.

최근 8차 렌더의 `audio_provenance`에서 워커 TTS 사용과 대체 음성 미사용을 확인했다.

### 수정 내용

- ElevenLabs 호출을 `/with-timestamps`로 변경했다.
- 생성 음성과 함께 글자별 발화 시작·끝 시점을 받는다.
- 타임스탬프의 텍스트 일치, 배열 길이, 유효한 수치와 순서를 검증한다.
- 음성 합성 결과와 캐시에 alignment를 보존하고, 혼합 오디오의 구간 시작 위치에 더해 자막 시간을 계산한다.
- 음성 정규화에 명시적 속도 보정이 있는 경우에만 동일 비율로 타임스탬프를 변환한다. ElevenLabs가 이미 적용한 속도를 이중 적용하지 않는다.
- 이전 캐시와 구분하도록 VoiceStudio 처리 버전을 갱신했다.

이번 프로젝트의 ElevenLabs 경로에 적용했다. 타임스탬프가 없는 다른 제공자의 경로에는 기존 추정 방식이 남아 있다. 워커 TTS 실패 시 제출 음성으로 돌아가는 기존 대체 처리도 남아 있으므로, 문제 재발 시 `audio_provenance.fallback`을 확인해야 한다.

## 10. 재발 시 점검 순서

1. 웹에서 선택한 렌더 버전과 큐 작업 ID가 같은지 확인한다.
2. 제출 응답과 별개로 큐의 실제 상태·오류·완료 시각을 확인한다.
3. 준비 표시 문제는 프로젝트 목록 API가 `id`, `metadata`를 포함하는지 확인한다.
4. `asset_manifest`의 씬 미디어 수와 실제 씬 수, 영상클립 누락 여부를 확인한다.
5. 웹 조회 오류는 Supabase 응답이 파일 부재인지 권한/서비스 오류인지 구분한다.
6. 렌더 싱크 문제는 `audio_provenance`, 워커 TTS 대체 여부, `voice-studio.json`의 alignment 유무를 확인한다.
7. 검증 없이 음성 전체 속도나 자막 전체 오프셋을 바꾸지 않는다. 구간별 발화 경계가 문제인지 먼저 확인한다.

로컬 조사 스크립트·오디오와 임시 로그는 `.pytest_tmp/`에 두었으며 이 문서와 함께 커밋하지 않는다. 인증키, 서비스 계정 비밀키, 서명된 다운로드 URL도 문서에 포함하지 않는다.
