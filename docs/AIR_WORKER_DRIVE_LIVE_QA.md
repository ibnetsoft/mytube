# AIR Worker — 실제 Google Drive 라이브 QA (AIR-0227D)

- 상태: **미실행 - 테스트 자격증명 없음. 이 문서 §1이 CTO에게 요청하는 사전 준비물 보고임**
- 관련 문서: [STAGING_E2E_QA](./AIR_WORKER_STAGING_E2E_QA.md), 기존 `docs/AIR_WORKER_DRIVE_ADAPTER.md`(AIR-0227C, 어댑터 코드 자체는 이미 구현됨 - `worker/drive_adapter.py`)

## 1. CTO(또는 인프라 담당자)가 준비해야 하는 항목

**아래 항목이 없으면 §2의 테스트 매트릭스를 전혀 실행할 수 없다 - 이 세션은 그때까지
대기한다.**

1. **테스트 전용 Google 계정 또는 서비스 계정** - 운영 계정과 완전히 분리. 서비스 계정을
   권장(사람 로그인/2FA 개입 없이 워커가 자동으로 인증 가능, `worker/drive_adapter.py`가
   이미 서비스 계정 인증 경로를 지원하는지는 재확인 필요 - 없다면 OAuth 토큰 파일 방식으로
   대체).
2. **격리된 전용 Drive 폴더 2개** (입력용/출력용, 또는 하위 폴더로 분리된 1개) - 운영
   콘텐츠 폴더와 물리적으로 다른 폴더여야 한다(작업 지시서 12/13단계의 명시적 금지사항).
3. **위 폴더의 폴더 ID** (Drive URL의 `/folders/<ID>` 부분).
4. **최소 권한** - 서비스 계정에는 그 폴더에 대한 편집자(Editor) 권한만, Drive 전체
   접근이나 다른 폴더 접근 권한은 부여하지 않는다. `worker/drive_adapter.py`가 폴더
   스코프를 벗어난 접근을 막는 방어 코드를 이미 갖고 있는지는 AIR-0227C에서 "구현
   완료"로 보고됐으나 실 자격증명 없이는 그 방어 코드 자체도 실행 검증되지 않았다 -
   라이브 테스트의 핵심 목적 중 하나가 바로 이 방어 코드의 실측 검증이다.
5. **다운로드용 입력 픽스처 파일** 1~2개 (테스트용 이미지/오디오, 운영 콘텐츠 아님) -
   위 입력 폴더에 미리 업로드.
6. **자격증명 저장 위치** - 서비스 계정 JSON 키 또는 OAuth 토큰 파일을 이 세션에
   붙여넣지 말고, 로컬 파일 경로(예: `worker/fixture/drive_test_credentials.json`,
   `.gitignore`에 이미 걸려있는 경로인지 사전 확인 필요) 또는 환경변수로 전달해달라 -
   **원문 자격증명은 대화·코드·로그·Git 어디에도 출력하지 않는다.**

## 2. 준비되면 실행할 테스트 매트릭스 (작업 지시서 12단계)

| # | 시나리오 | 확인 방법 |
|---|---|---|
| 1 | 입력 파일 다운로드 | 실제 바이트가 로컬에 저장됨 |
| 2 | 파일 크기 확인 | `drive_adapter.py`의 크기 검증 로직이 실제로 호출됨(로그) |
| 3 | MIME/확장자 검증 | 의도적으로 잘못된 확장자 파일을 폴더에 넣고 거부되는지 |
| 4 | 해시/무결성 확인 | 다운로드 전후 체크섬 비교 |
| 5 | 렌더링 | 다운로드한 실제 입력으로 fixture와 동일한 렌더 파이프라인 실행 |
| 6 | 결과 업로드 | 업로드 성공, 출력 폴더에 실제 파일 생성 |
| 7 | 업로드 결과 파일 ID 확인 | `remote_render_queue.result_reference`/`result_file_id`와 실제 Drive file id 일치 |
| 8 | 재다운로드 + ffprobe | 업로드된 파일을 다시 받아 h264/aac 등 스트림 정보 확인(로컬 E2E와 동일 기준) |
| 9 | 동일 이름 충돌 | 같은 파일명으로 두 번 업로드 시도, 덮어쓰기/버전 처리 동작 확인 |
| 10 | 업로드 중 네트워크 오류 | 업로드 도중 연결 끊김 시뮬레이션, 부분 업로드가 결과로 오인되지 않는지 |
| 11 | 인증 오류 | 만료/잘못된 자격증명으로 401/403이 프로세스를 크래시시키지 않는지(§LEASE_PROTOCOL.md §5와 동일한 non-fatal 원칙 적용 여부) |
| 12 | quota/429 처리 | Drive API 429 응답 시 백오프하는지(코드 경로 존재 여부부터 확인 필요 - AIR-0227C 시점엔 미검증) |
| 13 | 부분 업로드 정리 | 실패한 업로드의 임시/부분 파일이 Drive에 남지 않는지 |
| 14 | 경로 traversal 방어 | 악의적 파일명(`../../etc`류)이 로컬 저장 경로를 벗어나지 못하는지 |

## 3. 결과가 나오기 전까지의 상태

`worker/drive_adapter.py`(AIR-0227C)는 코드로는 완성되어 있고 정적 리뷰는 거쳤지만,
**단 한 번도 실제 Drive API를 호출해본 적이 없다.** 위 14개 항목 중 어느 것도 이 세션에서
검증되지 않았다 - Go/Conditional Go/No-Go 판정에서 이 부분은 명시적으로 "미검증"으로
분류한다(§AIR_WORKER_OPERATIONS.md 최종 보고 참고).
