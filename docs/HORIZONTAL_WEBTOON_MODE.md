# 가로 웹툰 컷 모드

사용자 웹의 영상·자막 화면 → 제작 모드 → **가로 웹툰 컷 모드 · AE · 16:9** → 제작 모드 저장 → 최종 자막·TTS 확정 → **가로 웹툰 컷 연출 준비** → 모든 씬 준비 완료 후 기존 제출.

## 제작 계약

- 기존 씬에 등록한 원본 PNG/JPG/WebP/PSD를 사용한다. 씬마다 한 원본이며, 긴 원본 안의 여러 컷을 분석할 수 있다. 서로 다른 파일의 컷을 한 씬에 섞는 편집은 이번 계약에 포함하지 않는다.
- PSD는 저장된 합성 화면을 사용한다. 원본 레이어를 수정하거나 새 자세·표정을 생성하지 않는다. PSD 레이어 리깅은 기존 AE 준비 경로의 별도 기능이다.
- 대본워커의 로컬 Codex CLI가 실제 원본 개요와 세로 구간 이미지를 보고 컷 경계·말풍선·읽기 순서·자막 구간을 분석한다. 원본 텍스트는 명령이 아닌 비신뢰 창작 자료로 취급한다.
- 씬별 최대 32개 샷, 한 화면 최대 3개 컷, 좌우 배치·단일 컷·순차 등장·제한적 확대를 계획한다. 원본 crop과 화면 frame은 정규화 좌표다. 겹친 화면 배치, 원본 밖 좌표, 빈 시작, 250ms 미만 샷, 음성 구간의 빈틈·중복을 거절한다.
- 시각 근거와 출처 파일 SHA-256, 원본 에셋 정보, 최종 음성·자막·시간의 지문을 묶는다. 소스나 확정 음성이 바뀌면 다시 준비해야 한다. 모호한 컷·문자·화자는 추측하지 않고 보완 필요로 멈춘다.
- 준비 완료 결과는 제출 시 동결한다. 제작 워커는 준비된 컷 좌표와 시간을 바꾸지 않는다. 원화 복사본을 잘라 AE 프리컴프에 배치하고 고정된 음성 시간으로 렌더한다. 확대 최대치에서도 contain으로 맞춰 임의의 추가 잘림을 피한다.
- 영상 생성 API를 호출하지 않는다. AE/aerender가 없으면 실행을 중단한다. 편집 가능한 `.aep`, 컷 PNG, 실행 계획·출처 해시를 작업 디렉터리에 남긴다.
- 최종 음성·자막·BGM·효과음은 기존 자동 제작 조립 경로를 사용한다. 실제 출력 검수는 컷 경계와 순차 등장 직후도 샘플링하며, 원본·이전 씬·실제 영상·확정 음성의 디코딩 증거를 사용한다. 게시·유튜브 업로드는 별도다.

## 워커와 큐

제출 전 준비는 기존 `motion_preview`의 `task=direction`, `horizontal_webtoon=true`로 대본워커가 처리한다. 구형 워커는 새 입력을 처리할 수 없으므로 사무실에서 최신 코드를 pull한 뒤 대본워커와 통합 제작 워커를 재시작해야 한다.

제출 후에는 전용 `horizontal_webtoon_automation` 큐를 사용한다. 감독 워커는 `motion_automation_worker.py --engine webtoon --once`로 실행하며 기존 supervisor가 자동으로 호출한다. 구형 일반 AE/EffectCraft 워커는 이 큐를 집어가지 않는다. 원화의 신체 움직임을 생성하거나 새 효과 소재를 만드는 모드가 아니다.

## 검증 경계

TypeScript 설정·출처/음성 지문·컷 검증, Python 원본 crop·AE 스크립트 생성·불확실한 분석 거절과 기존 자동 제작 회귀 테스트를 수행한다. 이는 실제 AE 실행이나 완성 영상 품질 검증을 대체하지 않는다. 사무실 AE 호스트의 업데이트와 대표 원본/확정 음성으로 만든 실제 `.aep`/MP4 확인이 남아 있다. 다른 원본 파일 사이의 복수 컷 조합, 고급 캐릭터 리깅, 자동 생성 효과 소재는 범위 밖이다.

기존 `test_local_media_supervisor.py`의 6개 실패는 업데이트 전 원격 HEAD에서도 동일하게 재현됐다. 이번 큐 추가와 분리해 기록했으며, 해당 묶음을 전체 통과로 보고하지 않는다.
