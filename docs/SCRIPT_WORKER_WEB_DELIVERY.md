# 대본워커 제작물의 유저웹 등록 절차

2026-11-26 사용자 지시. 파천무혼 2화의 실제 등록·수정 절차를 다른 작업에도 재사용한다. 이 문서는 제작을 감독하는 Codex와 각 컴퓨터의 로컬 대본워커가 함께 사용한다. 현재 사용자 요청과 승인된 작업 범위가 우선한다.

## 1. 범위와 진행 제어부터 확정

- 신규 작업은 기존 설정 확인 규칙에 따라 제작 종류·소재·길이·언어·배경·이미지 스타일·영상/레이어/연출 범위를 확인하고 명시적인 시작 지시를 받는다. 기존 회차 수정·복구에는 승인된 설정을 이어받는다.
- 수동 방식은 **① 대본 → ② 이미지 프롬프트 → ③ 영상으로 만들 컷 선택 및 영상 프롬프트 → ④ AE 작업 지침**으로 나누고, 사용자가 각 단계 결과를 확인해 다음 진행을 선택한다. 한 단계 요청을 다음 단계 실행 권한으로 확대하지 않는다.
- 이미지 생성·파일 등록·유저웹 연결은 별도 실행 작업이다. 프롬프트를 저장했다고 이미지가 존재하는 것으로 처리하지 않는다. 사용자가 등록까지 일괄 지시한 경우에는 이미 승인된 범위 안에서 끝까지 진행한다.
- ‘유저웹에 등록’은 주제·대본·실제 이미지·썸네일·성우 설정·제작 지침의 저장과 표시 확인을 뜻한다. 실제 음성 생성·영상 생성·AE 실행·관리자 게시·YouTube 업로드는 각각 별도 권한이다. 대본워커가 준비한 지침을 실제 영상/AE 결과로 보고하지 않는다.

## 2. 기존 자료 보존과 기준 수집

1. 기존 대본·후보·설정·이미지·음성·썸네일·등록 상태를 읽고, 수정 전 원본을 별도 버전으로 보존한다. 원본 SHA-256, 장면 수, 주제/프로젝트/작업 ID를 기록한다.
2. 사용자 제공 JSON/컷 목록을 실제로 읽고 컷 번호·순서·설명과 저장 파일을 대조한다. 예전 16씬과 새 120컷처럼 인덱스가 다르면 숫자만으로 연결하지 않는다.
3. 직전 회차 결말, 승인된 얼굴·복장·소품·부상 좌우·소유권·공간·사건 상태를 확인한다. 무협은 제작 기본 지침과 소품 기준을 함께 읽는다. 과거 제목은 별칭으로 보존하되 현재 승인된 작품명을 사용한다.
4. 존재하는 파일의 읽기·크기·형식·해시를 확인해 재사용한다. 누락·표시 제외·검수 불확실·실제 생성 실패를 구분한다. 추측으로 누락 원인을 확정하지 않는다.

## 3. 컷 전개와 대본 맞추기

- 모든 컷에 고유 `cut_id`를 유지하고, `scene_number`, 제목, `visual_action`, `spoken_blocks`, 이미지 프롬프트를 구분한다. 사용자가 요구한 컷 수와 순서를 검증하되 예시의 120컷을 다른 작업에 강제하지 않는다.
- 화면 설명에는 실제 보일 구도·행동·접촉·상태를 적는다. 내레이션은 화면에 없는 인과·맥락·심리를 압축하고 눈에 보이는 행동을 중계하지 않는다. 대사는 인물과 실제 문장을 분리하며, 무음 컷·화면 글자·SFX를 발화 원고에 섞지 않는다.
- 원인 → 행동/접촉 → 결과가 이해되는지 확인한다. 순간 동작을 불필요한 여러 장면으로 늘리거나 모든 등장인물·배경을 매 컷에 넣지 않는다.
- TTS용 통합 원고에는 발화만 들어가야 한다. 화면 설명이나 프롬프트가 음성 필드로 흘러들지 않게 검증한다. 계획 시간은 추정치로 표시하고 실제 녹음 시간으로 보고하지 않는다. 목표 분량을 맞추려고 정지 컷을 늘리지 않는다.
- 대본 수정은 해당 컷과 관련 지침에만 반영하고 확정 음성·다른 회차·사용자 편집을 보존한다.

## 4. 이미지 생성과 실제 원화 검수

1. 이미지 생성 전에 해당 컷 지침, 기존 원화, 앞뒤 컷과 필요한 승인 참조를 실제로 연다. 참조는 역할과 파일을 기록하고 생성 도구에 실제 첨부한다. 텍스트에 이름을 적는 것은 참조 첨부가 아니다.
2. 승인된 얼굴·복장·소품·사건 상태와 재사용 가능한 구조를 유지한다. 무협은 최종 2D 웹툰 스타일을 유지한다. 이미지 생성은 내장 image_gen 경로를 기본으로 사용한다.
3. 실제 출력 전체와 필요한 확대 부위를 검토한다. 얼굴 정체성, 머리-목-몸통, 어깨-팔꿈치-손목-엄지, 손가락, 골반-무릎-발, 파지·접촉·무기 직선과 좌우를 확인한다. 가린 부위는 확인했다고 쓰지 않는다. 손가락 수만으로 정상 판정하지 않는다.
4. 결함을 구체적으로 기록하고 국소 수정 또는 더 읽기 쉬운 자세로 새 버전을 만든다. 같은 실패를 두 번 넘겨 반복하지 않고 자세를 단순화한다. 새 픽셀을 다시 검토한다. 불확실·실패 원화는 무협 웹 미리보기/AE에 정지 대체로도 넣지 않고 나머지 작업을 계속한다.
5. 검수 기록은 실제 파일 SHA, 판정, 확인 가능한 부위와 한계, 이전 버전, 생성 참조에 연결한다. 수정본에는 이전 원화의 입모양·마스크·효과 승인을 재사용하지 않는다.
6. 원본은 보존하고 새 버전을 저장한다. 앞뒤 컷과 얼굴·복장·부상·무기·배경 상태가 이어지는지 확인한다. 얼굴이 없는 손 상세 컷을 얼굴 검수 완료로 보고하지 않는다.

## 5. 성우·썸네일·제작 지침 연결

- 성우는 가능한 경우 직전 회차의 현재 저장 설정을 조회해 같은 캐릭터와 내레이터에만 재사용한다. 이름이 비슷한 다른 인물을 같은 화자로 추정하지 않는다. 신규 화자는 미지정으로 기록한다. 설정 저장과 실제 음성 생성은 별개다.
- 썸네일은 승인된 전 회차 디자인과 현재 인물 얼굴을 참고하고 이번 내용에 맞는 문구를 사용한다. 실제 파일의 글자·회차·얼굴·가독성을 확인한 뒤 저장한다.
- 영상 프롬프트, 이미지 내부 AE 지침, 컷 사이 전환, 패럴럭스, 선택 말풍선을 명시적 컷 ID로 연결한다. 영상 선택 구간과 중복되는 움직임을 피하고 사용자가 정한 효과 범위를 지킨다. 무협에는 느린 전체 화면 줌을 추가하지 않는다.
- 타이밍은 시작·지속·종료 또는 접촉/발화 앵커로 기록한다. 실제 녹음 전 절대 시간을 확정된 동기화로 보고하지 않는다. 원화 교체 시 영향받은 인접 전환의 SHA와 보류 상태를 갱신하고, 원화에 묶인 효과는 재검토 필요로 남긴다.

## 6. 저장소 업로드와 데이터베이스 등록

1. 실제 사용할 이미지·썸네일·대본·검수/등록 근거를 버전 있는 경로로 업로드한다. 업로드 응답뿐 아니라 다시 내려받은 바이트의 SHA를 확인한다. 이 컴퓨터의 로컬 경로만으로 다른 워커가 읽을 수 있다고 처리하지 않는다.
2. 작업 ID → 주제 ID → 프로젝트 ID → 컷 ID → 원화 SHA/저장소 경로의 연결을 기록한다. 데이터베이스·대본워커·유저웹에서 같은 수정본을 가리켜야 한다.
3. 기존 등록 ID를 먼저 조회해 재사용한다. 이미 사용자가 가져간 주제·프로젝트의 소유권과 편집을 보존한다. 가져가기 과정에서 출처 표식이 사라졌다고 새 주제를 중복 생성하지 않는다. 작업 ID와 발화 원고 SHA 등 남은 근거를 대조한다.
4. 변경할 필드만 저장하고 최신 버전/갱신 시각을 확인해 동시 편집을 덮어쓰지 않는다. 이미지 수정으로 대본·성우·음성·자막·렌더 설정 전체를 오래된 사본으로 교체하지 않는다.
5. 큰 프로젝트 조사에는 알려진 ID와 제한된 필드를 사용한다. 큰 JSON을 자막마다 반복 확장하거나 동일 프로젝트의 무거운 진단을 동시에 실행하지 않는다.
6. DB 연결 실패는 실제 오류와 로컬 보존 상태를 기록한다. 응답이 유실된 쓰기는 알려진 ID로 먼저 재조회하고 무작정 재전송하지 않는다. 로컬 저장·클라우드 동기화·주제 등록을 각각 확인한다.

## 7. 등록 후 재조회와 실제 유저웹 확인

- 데이터베이스를 다시 읽어 컷 수·순서·발화·이미지 경로·썸네일·성우·지침이 저장 입력과 일치하는지 확인한다. 이미지 수는 저장 파일 수와 사용 가능한 수를 구분한다.
- 실제 로그인된 유저웹에서 정확한 주제/프로젝트를 연다. 대본 입력칸에 원고가 보이고 이미지/썸네일이 로딩되며, 수정 컷 번호의 미리보기가 새 파일인지 확인한다. 저장된 전환 지침이 해당 컷에 보이는지 확인한다.
- 유저웹에서 보이는지 확인하는 것은 파일 업로드·DB 저장과 다른 검증이다. HTTP 성공, 테스트, 로컬 갤러리만으로 웹 표시 완료를 보고하지 않는다. UI 필드 연결 문제를 발견하면 저장 원고를 덮어쓰지 말고 표시 경로를 바로잡고 필요한 빌드·배포를 검증한다.
- 데이터 수정만 필요한 경우 불필요한 제품 배포를 하지 않는다. 실제 AE 출력 확인은 AE가 명시적으로 배정된 단계에서만 수행한다.

## 8. 최종 확인서와 보고

등록 확인서에는 최소한 다음을 기록한다.

- 계약명 `script_worker_web_delivery/v1`, 작업/주제/프로젝트 ID와 확인 시각
- 원본 보존 경로·SHA, 현재 대본 SHA와 컷 수
- 컷별 실제 이미지 버전·SHA·저장소 경로·검수 판정과 제외 사유
- 썸네일 파일·SHA, 성우 재사용/미지정 내역, 제작 지침 연결 수
- 저장소 다운로드 해시 검증, DB 재조회, 실제 웹 표시 근거/스크린샷
- 음성 생성·영상 생성·AE 실행·관리자 게시·YouTube 업로드 각각의 실제 요청/실행 여부
- 사실에 근거한 품질 기록, 보존한 기존 자료, 필요한 후속 사용자 결정

최종 보고는 현재 완료한 단계와 산출물을 먼저 말하고 유저웹 링크를 제공한다. 계획·원화 검수·실제 음성·실제 렌더를 구분한다. 배정되지 않은 후속 단계를 실패나 지연으로 표현하지 않는다. 제외 컷이 있으면 전 컷 정상 완료라고 쓰지 않는다.

## 다른 컴퓨터에서 적용

이 문서는 `worker.script_worker_guidance.load_production_guidance()`가 새 요청과 수동 단계의 제작 문맥에 직접 포함한다. 단순 링크에 의존하지 않는다. 다른 컴퓨터는 이 변경이 포함된 저장소를 업데이트하고 장기 실행 중인 대본워커를 재시작한 후 새 요청/단계를 실행한다. 기존 진행 중 작업의 저장 입력은 자동 재작성하지 않는다. 푸시 완료는 원격 컴퓨터의 업데이트·재시작 또는 모든 실행 결과 검증을 뜻하지 않는다.
