# Codex 워커 신규 생성 프로세스

기준일: 2026-09-12

신규 토픽을 처음부터 제작할 때의 작업 순서와 완료 기준이다. 기존 대본을 고치는 작업은 [리페어프로세스.md](리페어프로세스.md)를 따른다.

## 1. 작업 범위와 현재 자동화 경계

- YouTube API 조사 자료를 바탕으로 Codex가 토픽과 콘텐츠를 작성한다.
- 대본 작성·수정·독립 검수·대사 판별 단계는 Astra로 고정한다. 다른 단계까지 모두 같은 모델이라고 간주하지 않는다.
- 주요 캐릭터 참고 이미지 생성은 대본 파이프라인에 직접 연결돼 있다.
- 전체 장면 이미지와 썸네일 배경의 실제 생성·게시는 별도의 CoWork 이미지 제작 단계다. 대본 워커 종료만으로 이 단계까지 자동 완료됐다고 보고하지 않는다.
- 제작 범위는 전체 장면 이미지와 첫 12씬의 영상 프롬프트까지다. 영상클립을 생성하지 않는다.
- 썸네일은 글자 없는 배경과 편집 가능한 문구로 나누며, 사용자가 저장할 때 최종 이미지로 합성한다.

## 2. 정상 시작부터 제작 완료까지

| 순서 | 단계 | 수행 내용과 완료 기준 |
| --- | --- | --- |
| 1 | 워커 시작 | 실행 설정·연결·상태를 확인한다. 진행 중인 작업을 중복 실행하지 않고 작업 수신을 대기한다. |
| 2 | 토픽 선정 | YouTube API 조사 자료로 후보를 만들고 토픽을 선정한다. 조사 자료와 창작 내용을 혼동하지 않는다. |
| 3 | 기획 | 인물, 갈등, 결말, 장면 ID·순서·분량을 확정한다. 이후 단계는 이 장면 구조를 기준으로 한다. |
| 4 | 대본 작성 | Astra가 카테고리별 화법과 장면별 분량 기준을 적용해 대본을 작성한다. |
| 5 | 대본 검수 | 개연성, 시니어 청취 적합성, 자연스러움과 재미를 검수한다. 미해결 문제가 있으면 후속 제작을 중단한다. |
| 6 | 대사 판별 | Astra가 최종 대본 전체의 문맥을 읽고 실제 대사, 화자, 원문 위치, 불확실성을 저장한다. |
| 6-1 | 자동 효과음 구성 | 최종 대본 문맥으로 저장된 효과음을 선택하고 위치·볼륨·길이·이유를 별도 저장한다. 실패/재검토는 남은 작업에 표시한다. |
| 7 | 캐릭터 참고 이미지 | 확정 대본의 주요 인물 이미지를 생성하고 파일·업로드·접근을 검증한다. |
| 8 | 미디어 프롬프트 | 최종 장면별 이미지 프롬프트와 첫 12씬의 영상 프롬프트를 작성한다. 캐릭터 참고 이미지를 연결한다. |
| 9 | 태국어 자막 번역 | 최종 자막 블록을 기준으로 `subtitle_translations.th.blocks`를 생성한다. 번역은 블록별 1:1이어야 하며 병합·분할·요약을 금지한다. |
| 10 | 메타데이터·썸네일 기획 | 최종 대본에 맞는 제목·설명문 등, 썸네일 문구 후보, 선택 문구 레이어와 글자 없는 배경 프롬프트를 저장한다. |
| 11 | 실제 이미지 제작 | CoWork에서 전체 장면 이미지와 썸네일 배경을 생성·검수·업로드하고 정확한 장면 및 프로젝트에 연결한다. |
| 12 | 패키지·웹 검증 | 저장한 데이터를 다시 읽고 실제 이미지 접근 및 유저웹 표시를 확인한다. |
| 13 | 사용자 편집·저장 | 사용자가 썸네일 문구를 편집하고 저장하면 1280×720 PNG로 합성·업로드한다. 저장 성공 후 최종 완료 처리한다. |

## 3. 품질과 데이터 보존 원칙

- 대본 검수는 작성자의 자기평가만으로 통과시키지 않는다. 자연스러움·재미 검수는 제목과 최종 장면 텍스트를 받는 별도 검수로 수행한다.
- 현재 청취 품질 검수는 텍스트 기반 검수다. 실제 TTS 청취나 시니어 청중의 실측 평가라고 표현하지 않는다.
- 대사는 어미·따옴표 등의 단순 규칙으로 추측하지 않는다. 코드는 AI 판별 결과의 형식과 정확한 원문 위치를 검증한다.
- 확정 대사는 노란색으로 표시한다. 대사와 나레이션 또는 서로 다른 화자의 대사는 하나의 자막 블록에 섞지 않는다.
- 신규 토픽은 최종 자막 블록 생성 후 태국어 번역을 기본 산출물로 함께 저장한다. 저장 위치는 `project_payload.subtitle_translations.th.blocks`이며, 각 항목은 원문 자막의 `index`와 `source_text`를 그대로 보존하고 `translated_text`만 태국어로 채운다.
- 태국어 번역은 태국 작업자가 대사 여부를 검수하기 위한 보조 텍스트다. 전체 문장을 뭉뚱그려 해석하거나 자막 블록을 다시 나누지 않는다.
- 태국어 번역 블록 수가 원문 자막 블록 수와 다르거나 빈 번역이 있으면 토픽 완료로 처리하지 않는다.
- 장면 수는 기획에 따라 결정한다. 모든 토픽을 53씬으로 강제하지 않으며, 글자 수 초과 때문에 하위 단계에서 장면을 임의로 늘리지 않는다.
- 누락 이미지는 누락으로 표시한다. 다른 장면이나 다른 프로젝트의 이미지로 대체하지 않는다.
- URL 존재만으로 업로드 완료라고 판단하지 않는다. 실제 파일 접근과 장면 연결을 확인한다.
- 사용자 수정본·확정 썸네일·제출 프로젝트를 워커 결과로 무조건 덮어쓰지 않는다.

## 4. 썸네일 저장 규칙

1. 이미지 모델은 글자 없는 배경만 생성한다.
2. 문구 후보 세 개와 실제 배치할 문구 레이어를 구분한다. 후보를 전부 한 이미지에 겹쳐 넣지 않는다.
3. 배경에는 영구 저장 주소를 사용하고 `blob:` 주소를 저장하지 않는다.
4. 배경 생성 후에는 사용자 저장 대기 상태다. 아직 최종 썸네일 완료가 아니다.
5. 미리보기와 저장은 같은 렌더러를 사용한다.
6. 사용자 저장 시 최종 PNG를 별도 주소로 저장한다. 원본 배경과 편집 레이어도 유지한다.
7. 재접속하면 합성된 완성본이 아닌 원본 배경과 편집 레이어로 편집기를 복원한다.

## 5. 완료 보고 체크리스트

- [ ] 대본과 검수 결과 저장
- [ ] 최종 대본에 대응하는 대사 판별 결과 저장
- [ ] 최종 자막 블록과 1:1로 대응하는 태국어 번역 저장 및 빈 번역 없음 확인
- [ ] 캐릭터 참고 이미지 생성·접근 확인
- [ ] 전체 장면 이미지 프롬프트 및 첫 12씬 영상 프롬프트 저장
- [ ] 실제 장면 이미지 수와 장면별 내용·연결 확인
- [ ] 최신 대본 기반 메타데이터 저장
- [ ] 썸네일 원본 배경과 편집 문구 저장·웹 표시 확인
- [ ] 기존 토픽 패키지 저장 위치와 웹 연결 데이터 일치 확인
- [ ] 사용자 최종 썸네일 저장 여부 별도 표시

대본 완료, 프롬프트 완료, 이미지 완료, 웹 확인 완료, 사용자 최종 저장을 구분해 보고한다. 확인하지 못한 항목은 미확인으로 남긴다.


## 대본 완성 직후: 자동 효과음 구성 (필수 단계, 2026-09-18)

1. 최종 대본 검수와 대사·화자 판별이 끝나면 `06_sfx_plan`을 자동 실행한다. 신규 생성과 리페어 모두 기본 수행한다. 배경음악 프롬프트 옵션과 독립적이다.
2. Codex가 최종 장면 전체의 문맥을 읽고 저장된 Supabase 효과음 카탈로그에서만 파일을 선택한다. 파일을 새로 합성하지 않는다. 적절한 소리가 없거나 불확실하면 배치하지 않는다. 효과음 0개도 정상 결과다.
3. 효과음은 대본·자막 텍스트와 분리된 `sfx_plan`/`sfx_cues`로 저장한다. `structure.sfx_plan`에도 포함하고 로컬 결과 폴더에 `sfx-plan.json`을 남긴다. TTS 입력에 효과음 지시문을 넣지 않는다.
4. 리페어는 원본의 수동 배치·삭제 기록을 우선 보존한다. 동일한 원문 위치가 확정되는 AI 효과음은 재사용한다. 변경·삭제된 원문 위치를 추측해서 옮기지 않고 `needs_review`로 표시해 재생에서 제외한다. 사용자 원본 파일은 삭제하지 않는다.
5. 장면당 자동 효과음 최대 1개, 자동 배치 사이 최소 5초, 작은 볼륨을 사용한다. 최종 자막·음성 시간이 확정되면 기존 위치 해석기로 시간을 다시 계산한다. 단어 시간이 없으면 자막 시작을 기준으로 한다.
6. 기존 승인·게시 절차에서 대본과 같은 버전의 효과음 계획도 함께 전달한다. 신규 토픽은 `pregenerated_structure.sfx_plan`을 보존해 프로젝트 가져오기 단계가 Storage 파일 참조를 연결하게 한다. 기존 프로젝트 리페어는 최신 수동 배치를 재조회·병합하고 `project_payload.render_settings.sfx_cues`에 반영한 뒤 재조회한다. 로컬 수정안 생성만으로 운영 데이터 반영 완료라고 보고하지 않는다.
7. 자막의 보라색 별, 미리듣기, 새로고침 후 저장 상태와 렌더 결과를 검증한다. 배경음·효과음·음성은 별도 레이어로 겹쳐 재생하며 효과음 때문에 음성이 늦어지거나 다시 생성되면 안 된다.
8. 카탈로그 접근/분석 실패 시 완성된 대본은 보존하고 효과음 상태를 `failed` 또는 `no_library`로 기록한다. 남은 작업에 재시도를 표시하며 효과음 구성 완료로 보고하지 않는다.

완료 기록: 효과음 상태 / 자동 배치 개수 / 수동 유지·삭제 개수 / 재검토 개수 / 파일 연결·미리보기·렌더 확인 여부.
배경음악 생성 프롬프트는 별도 선택 옵션이며 **기본 꺼짐**이다. 효과음 자동 구성 때문에 음악 프롬프트나 음악 파일을 생성하지 않는다.
