# 1화 이동·줌·열기·씬 전환 적용 기록

대상: #3428 / `b45f00f7-fc8b-4d1a-9b72-f27c84fb0a02`.
사용자가 기존 1화 변경을 명시 요청한 범위에서 적용했다. 관리자 게시와 YouTube 업로드는 별도다.

## 저장 및 보존 확인

- 26씬의 효과와 실제 원화 검토 근거를 운영 DB에 저장하고 프로젝트·씬 양쪽에서 재조회했다.
- 이동/줌: 1씬 좌→우, 3씬 줌아웃, 6씬 우→좌, 7씬 위→아래, 9씬 줌인. 약 0.9초 이동 후 정지 유지한다.
- 열기: 8씬 `E01_S08_STATE_02`의 실제 횃불 상단 공기 영역만. 손·밧줄과 다른 상태는 변형하지 않는다.
- 전환: 방향 슬라이드, 짧은 플래시, 펀치 줌, 스냅 흔들림, 디졸브, 마지막 페이드. 전체 배치는 `direction-plan.json` 참조.
- 기존 원화 105장의 SHA, 대본, 자막 및 저장 음성 구간은 변경 전후 동일하다. 기존 타격 연출도 유지한다.
- 자막 크롭 방지를 위해 이동 폭을 원화별로 제한했다. 9씬 편집 효과음 ‘철컥’의 위치만 좌하단 여백으로 조정했으며 문구·스타일·시점은 보존했다.
- 직전 6씬의 이동 후 구도가 원본 정지 배경으로 튀지 않도록 7씬은 하드 컷으로 연결했다.

## 확인한 증거와 범위

- 실제 원화와 정식 웹 미리보기 컴포넌트, 저장 음성의 최종 타임라인으로 217개 화면을 캡처해 검토했다. 7·26씬 수정 후 22개 화면을 추가 확인했다. 이는 로컬 브라우저 컴포넌트 검증이며 실제 AE 출력 검증과 구분한다.
- 실제 손 영역 픽셀은 두 열기 위상 사이 동일하고, 횃불 주변 공기 영역 픽셀은 다름을 확인했다.
- 이동 전체 시각 샘플의 편집 글자 화면 밖 크롭 검사: 0건.
- 26개 동결 타임라인의 Python 네이티브 모션·전환 계약 검증 통과. 관련 Python 20개, JS 34개 테스트 및 웹 production build 통과.
- 코드 `0cf65ccc` 커밋·푸시. 운영 페이지 HTTP 200 및 배포 `dpl_DQmsYpqwVjWrKfLf2vVrtgzUGJWe` 식별자 확인.
- 운영 DB의 저장 내용이 검토한 후보와 일치함을 확인한 후 새 AE 작업을 정상 재제출했다. 이전 렌더 입력·출력은 유지한다.

## 실제 AE 및 유저웹 확인 상태

AE 재렌더 작업: `32a37792-6653-42dd-ab23-2eebd98f15e7`.
원화·실제 출력 검수 기능이 있는 `wuxia_motion_auto/v1` 워커를 요구한다. 최종 출력이라고 주장하지 않는다.
검수는 이동 시작/중간/종료/정지, 서로 다른 열기 위상, 짧은 전환의 중간·종료 및 최종 암전 프레임을 실제 디코딩 인덱스로 추출한다. 품질 우려는 사실대로 별도 기록하면서 조립을 진행한다.

이번 제어 시도에서 Chrome의 다른 확장 프로그램 화면 때문에 사용자 웹 재로드 확인과 AE 컴퓨터 접속 제어가 차단되었다. 사용자에게 팝업 해제를 요청했다. 원격 AE 워커의 새 소스 적용·실행 및 실제 완성 파일의 SHA/전체 디코딩/14,393프레임 확인은 연결 복구 후 수행해야 한다. 구버전 1화 출력은 이번 모션 적용본 증거로 사용하지 않는다.

원화 해부학/기존 타이포에 대한 전체 재승인은 이번 효과 적용 검수 범위가 아니다. 실제 AE 파일이 생성되면 해당 파일에 연결된 품질 메모를 이 기록에 추가한다.
