# 대본 생성 후 웹 등록 복구 수정

## 확인한 원인

- 5번 작업 `5a0bb74a8d8f4a2d943fa79bc79c7dcc/delivery/last-error.json`에 최종 생성 뒤 `ScriptStore.save`의 15초 DB 읽기 시간 초과가 기록됐다. 자동 감독 로그에는 `저장된 단계에서 생성 복구`가 반복됐다.
- 복구 결과를 저장하기 전 읽어 둔 저장 버전을 사용하면 장시간 생성 중 상태 갱신과 충돌할 수 있었다. 로컬 완성본을 DB 저장 이후에만 쓰면 응답 유실 시 생성 완료 사실을 복구하기 어려웠다.
- 감독 프로세스 잠금은 Windows에만 적용돼 Mac에서는 실행 중 감지와 중복 실행 방지가 동작하지 않았다.
- 등록 감독기가 콘솔 HTTP 조회와 Windows 전용 PowerShell 시작 스크립트에 의존했다.
- 등록에 성공해도 `approved_pending_repair`와 후속 대기 문구로 끝났다. 5번은 별도 완료 스크립트로 상태를 정리해야 했다.

## 수정

- 실제 파일 잠금을 전 플랫폼에 적용했다. 콘솔 HTTP 의존성을 제거하고 현재 저장 레코드에서 복구한다.
- 단계 알림은 로컬 상태만 쓰며 낡은 전체 DB 레코드를 저장하지 않는다. 취소는 로컬/DB 경계에서 보존한다.
- 생성 결과를 DB보다 먼저 보존하고 최신 저장 버전으로 병합한다. 준비 패키지는 전체 원본 후보·요청 지문과 결과 해시로 재사용한다. 번역은 원문 해시별 기존 캐시를 사용한다.
- 같은 원본 작업의 등록 확인서를 바탕으로 재시도한다. 이미 사용자가 가져간 토픽도 확인서와 대본이 일치하면 읽기 검증만 하며 기존 작업은 수정하지 않는다. 취소되거나 변경된 대본은 거부한다.
- 최초 등록 시 대본·씬 구조·메타데이터·번역 재조회 일치를 요구한다. 완료 상태와 최종 후보를 함께 저장하고 다시 읽어 확인한다.
- 기존 토픽·사용자 프로젝트·제출 후 레이어 정책은 변경하지 않았다. 완료 범위는 대본 패키지와 웹 등록으로 명시하고 이미지 파일 상태를 생성한 것처럼 바꾸지 않는다.

## 검증

DB에 도달하지 않은 저장, DB 커밋 후 응답 유실을 생성 결과 저장과 완료 저장 양쪽에서 모의 재현했다. 동일 ID 복구가 완료되고 생성·패키지 준비가 각 1회인 것을 검사한다. 중복 프로세스 잠금, 체크포인트 변경 감지, 등록 응답 유실, 사용자 할당 후 읽기 복구, 취소 보존, 잘못 저장된 본문 거부도 검사한다. 유료 생성과 새 실제 토픽 등록은 이 검증에서 실행하지 않는다.
