# AIR Studio 자동 후작업 파이프라인

이 문서는 대본 워커가 이미지를 확정한 시점부터 통합 워커가 최종 영상을 렌더링할 때까지의 실행 계약을 설명한다.

## 1. 대본 워커: 이미지 확정과 분석 데이터 저장

대본 워커는 각 씬 이미지를 GCS에 게시한 직후 다음 순서로 처리한다.

1. 게시된 원본 이미지의 SHA-256과 현재 대본·화자·캐스트 정보를 묶어 입력 지문을 만든다.
2. 로컬 Codex 이미지 분석으로 화면 속 화자의 얼굴과 입 영역을 찾는다.
3. 자막의 `dialogue_kind`와 `dialogue_speaker`를 기준으로 실제 대사와 화자를 연결한다.
4. 카메라 이동, 조명, 오디오 반응, 영역 모션을 포함하는 안전한 씬 연출 계획을 저장한다.
5. 얼굴·입 좌표, 레이어 패키지, 원본 해시, 분석 지문을 씬 메타데이터와 체크포인트에 저장한다.

분석 실패는 다른 씬의 성공 결과를 지우지 않는다. 좌표가 없는 씬은 이후 AE 입모양 작업 대상에서 제외되고 원본이 유지된다.

레이어 생성 범위가 설정된 경우에만 해당 씬을 `parallax_layered_scene` 패키지로 만든다. 이 패키지는 최소 `background`, `foreground` 레이어를 포함하며, `prop_focus`, `atmosphere`는 선택 사항이다. AE는 QA 상태가 `approved`인 PSD와 일치하는 SHA-256만 사용한다.

레이어가 확정되면 전경·배경 사이의 2.5D 패럴랙스, 독립 소품의 이동·회전·크기 변화, 승인된 머리카락·옷자락 레이어의 제한된 움직임, 조명·안개 레이어, 카메라 이동과 가림 순서를 안전하게 제어할 수 있다. 관절 리깅이나 가려진 신체 복원은 완성된 전용 레이어와 리그가 없으면 수행하지 않는다.

19번 이후 정지 이미지에는 사용자가 원하는 씬과 캐릭터를 선택해 양쪽 눈 영역을 직접 지정할 수 있다. 저장 레코드는 캐릭터, 두 눈의 정규화 좌표, 깜빡임 간격, 이미지 자산 ID·GCS 경로·SHA-256을 포함한다. 통합 워커는 동일한 원본에서 닫힌 눈 패치만 생성하고 시각 검수를 통과한 경우에만 AE 합성에 사용한다. 이미지가 바뀌면 기존 눈 좌표와 결과는 무효가 된다.

## 2. 유저 제출: 최종 데이터 고정

제출 API는 이미지, 영상, 확정 TTS, 자막, 썸네일을 검증한 뒤 `submitted_at`과 제출 레코드를 먼저 기록한다. 이 시점의 씬 수, 자산 수, AE 입모양 작업 ID와 입력 지문이 제출 메타데이터에 남는다. 백그라운드 워커는 제출이 고정된 뒤에만 후속 작업을 시작한다.

1~18번 영상 씬에 실제 캐릭터 대사가 있으면 제출된 원본 영상에서 대표 프레임과 시간축 얼굴·입 좌표를 분석한다. 내레이션 씬은 입모양 작업에서 제외한다. 19번 이후 이미지 씬은 대본 워커가 저장한 이미지 좌표를 재사용한다.

## 3. 통합 워커: 씬 단위 후작업

`render_only`와 `full` 프로필은 다음 프로세스를 기본 실행한다.

- `ae_mouth_worker`: 영상 좌표 분석, 대사 화자 확인, 입모양 레이어와 사용자가 지정한 눈 깜빡임 레이어 생성, 씬별 AE 렌더와 자동 검수
- `ae_highlight_worker`: 승인된 PSD의 영역 모션·패럴랙스, 카메라·조명·오디오 반응 효과, 영상 끝 고정 프레임 처리
- `premiere_final_worker`: 준비된 씬 결과를 최종 타임라인으로 조립하고 최종 영상을 렌더링
- `remote_drive_worker`: GCS 렌더 패키지 큐 처리와 결과 등록

통합 워커는 한 번에 하나의 무거운 미디어 작업만 실행하고, 각 씬 완료 시 체크포인트를 저장한다. 중단 후에는 완료된 씬을 다시 만들지 않고 남은 씬부터 재개한다.

## 4. 실패 격리와 원본 폴백

자동 작업은 프로젝트 전체를 한 씬의 실패로 막지 않는다.

- 화자 판별 불확실, 좌표 누락, 입모양 렌더 실패, 자동 검수 실패: 해당 씬을 `skipped`와 `fallback: original`로 기록한다.
- 영역 모션·패럴랙스가 재시도 중: 최종 렌더 등록을 잠시 기다린다.
- 영역 모션·패럴랙스가 `needs_attention`으로 종료: 해당 씬은 원본 이미지 또는 원본 영상을 사용한다.
- 승인되지 않은 PSD: 레이어 작업에 사용하지 않고 원본을 사용한다.
- 검수되지 않은 과거 AE 출력: 현재 입력과 해시가 일치하더라도 사용하지 않는다.
- 눈 좌표·원본 해시 불일치 또는 닫힌 눈 레이어 검수 실패: 해당 씬 후작업을 건너뛰고 원본을 사용한다.

입모양 결과가 승인된 씬은 승인된 AE 영상을 사용하고, `skipped` 씬은 현재 제출의 원본 자산을 사용한다. 모든 대상 씬에는 승인 또는 건너뜀 결과가 정확히 하나 있어야 최종 렌더가 등록된다.

### 안전 제한

- 자동 GrabCut/SAM 계열 외곽선 분리와 OpenCV 배경 인페인팅은 영역 모션 입력으로 사용하지 않는다.
- 영역 모션은 사용자가 검수한 정확 외곽선 또는 전체 캔버스 투명 PNG와, 별도로 올려 검수한 전체 캔버스 배경이 모두 있을 때만 큐에 넣는다.
- 가려지거나 잘린 신체는 자동 복원하지 않는다. 완성된 투명 PNG가 없으면 해당 영역을 건너뛴다.
- 저장된 레이어 패키지는 원본 이미지 해시와 각 PNG 해시가 모두 맞고 사용자가 승인한 경우에만 재사용한다.
- 대사 음성 RMS 조명은 확인된 대사 시간 안에서만 0~1로 정규화하며, AE 합성 밝기 변화는 최대 4%로 제한한다. 내레이션과 무음에서는 0으로 돌아간다.

## 5. 최종 렌더 자동 연결

입모양 검수가 끝나면 내부 continuation API가 현재 워커 임대와 작업 지문을 다시 검증한다. 레이어·영상 후작업이 아직 진행 중이면 5분 뒤 다시 확인한다. 준비된 GCS 후작업 자산은 원본보다 우선 사용한다. 터미널 실패나 승인되지 않은 레이어는 원본으로 대체한다.

최종 렌더 큐 ID는 AE 입모양 작업 ID에서 결정적으로 생성한다. 응답 유실로 같은 요청이 다시 와도 중복 최종 렌더가 만들어지지 않는다. 큐 등록 후 제출 레코드와 프로젝트 진행 데이터에 후작업 완료 시각, 입모양 작업 ID, 최종 렌더 큐 ID를 저장한다.

## 6. 핵심 저장 상태

| 단계 | 저장 상태 | 의미 |
| --- | --- | --- |
| 이미지 좌표 | `ready`, `needs_review` | 성공 씬 좌표는 부분 저장되고 실패 씬만 재검토한다. |
| 입모양 발견 | `direction_pending` | 씬별 연출 지시를 만들었다. |
| 입모양 렌더 | `review_pending` | 씬별 AE 결과가 생성되어 자동 검수 대기 중이다. |
| 입모양 완료 | `approved`, `skipped` | 승인 출력 또는 원본 폴백이 확정됐다. |
| 레이어 후작업 | `ready`, `retry_wait`, `needs_attention` | 승인 결과, 재시도 대기, 원본 폴백 상태다. |
| 최종 렌더 | `remote_render_queue` | 모든 후작업 게이트를 통과한 렌더 패키지다. |
