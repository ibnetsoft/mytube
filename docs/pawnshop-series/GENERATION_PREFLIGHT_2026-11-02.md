## 원인과 수정

1. 초안 글자 수가 한 글자 부족해도 대본 생성 전체가 중단됐다. 초안과 QA 응답의 씬 번호·순서·본문 자료형·글자 수를 검증하고 오류를 생성 단계에 전달해 최대 3회 시도한다. 검증 오류와 거부된 응답, 시도 번호가 캐시 키에 반영되므로 같은 잘못된 응답을 무한히 재사용하지 않는다. 기존 응답 파일은 덮어쓰지 않는다.
2. 청취 검수는 한 차례 수정 후 남은 지적이 있으면 즉시 수동 검토로 중단됐다. 검수 → 해당 씬만 수정 → 익명 비교 → 재검수를 최대 3라운드 수행한다. 각 라운드의 실제 판정과 근거를 보존하며 개선되지 않거나 퇴행한 수정본을 통과시키지 않는다. 잘못된 검수 JSON·원문에 없는 근거는 형식 검증 피드백으로 다시 요청한다.
3. 독립 검수 인용문이 떨어진 문단들을 묶으면 단일 부분문자열 비교가 실패했다. 실제 문단별 인용을 원문 순서대로 대조하며 CRLF와 빈 줄을 처리한다. 공백뿐인 인용·없는 문장·역순 인용은 거부한다. 필수 검수 항목은 개수뿐 아니라 이름과 boolean 판정도 검사한다.
4. 4분할 프롬프트 렌더러는 패널 위치를 표시하지만 저장 패널 객체에는 위치가 없을 수 있었다. 빌더가 누락된 위치를 동일한 순서로 채운 복사본을 반환한다. 명시된 잘못된 위치는 자동으로 숨기지 않는다. 전체 씬 집합이 같더라도 그리드 순서가 다르면 검증에서 거부한다.
5. 1화 마무리 도구는 잘못된 로컬 미디어 캐시에서 즉시 중단하고, 저장된 소개문은 재검증하지 않았다. 잘못된 캐시는 별도 보존하고 해당 묶음/소개문만 다시 생성한다. 레이어 ID 누락·중복, 잘못된 자료형도 검사한다.
6. 등록 재시도 때 기존 결과를 덮어쓸 수 있고 재조회는 씬 개수만 확인했다. 이미 선점됐거나 이미지가 연결된 주제는 교체를 거부한다. 등록 완료 기록 전에 대본·전체 씬 구조·언어·상태·작업 ID·본문 해시를 재대조한다. DB 스키마나 권한은 변경하지 않았다.

## 적용 범위와 남은 한계

- 현재 Mac의 로컬 대본 워커에 적용한다. 웹 앱 코드 변경과 Vercel 배포는 없다.
- 실제 2번 대본 생성·등록, 새 이미지·TTS·AE 렌더는 실행하지 않았다. 새 모델 출력에 오류가 없다는 보장은 아니며, 정해진 재시도 횟수 이후의 실패도 완료로 기록하지 않는다.
- 로컬 CLI/네트워크 실행 실패는 기존 실행기의 제한된 재시도 정책을 유지한다. 형식 오류 재생성 로직으로 무제한 실행 재시도를 추가하지 않는다.
- `_dev/pawnshop_episode01_finish.py`의 작업 ID·출력 경로·일부 검수 항목은 1화 전용이다. 2화 생성 시 이 파일을 그대로 실행하지 말고 2화의 독립 작업 ID·출력 경로·반지/부부 관계에 맞는 검수 항목을 설정해야 한다. 공용 생성·청취 검수·그리드 보완은 새 작업에도 적용된다.
