## 처리 기준

1. 이미지: 대본워커가 생성·게시한 원본 이미지의 실제 픽셀을 로컬 Codex로 분석한다. 이번 기존 토픽 보완도 동일한 분석·검증 함수를 사용했다.
2. 19씬 이후의 대사 씬에 얼굴·입 좌표, 화자, 신뢰도, 원본 이미지 SHA-256, 경로, 대본·캐릭터에 연결된 fingerprint를 저장했다. 나레이션 씬은 `not_required`로 기록했다.
3. 1~18씬은 이미지의 정적 좌표를 영상용으로 전용하지 않는다. 사용자가 실제 영상 클립을 제출한 뒤 영상 기준 분석·저장을 진행한다.
4. 프로젝트 제출 이후 통합워커의 자동 AE 검수 → 입모양 작업 → 결과 검수 → 최종 렌더 큐 연결을 사용한다. 좌표가 없거나 불확실한 씬은 사유를 남기고 다른 처리 가능한 씬을 계속한다.
5. `air_processing_policy`는 적용 기준을 기록하는 메타데이터다. 실제 자동화는 배포된 웹/워커 실행 코드에 구현되어 있으며 이 필드 자체가 별도 실행기를 생성하지는 않는다.

## 검증

- 세 토픽의 원본 구조를 수정 전 백업했다.
- 기존 로컬 이미지 전체 SHA-256과 게시된 content-addressed 파일명/해시를 대조했다. 이미지를 재생성하지 않았다.
- 모든 씬의 대사 annotation을 원문 부분문자열·위치·SHA-256으로 검증했다. 3376의 기존 annotation은 보존하고 대사 집계 정보를 보완했으며 3377/3378의 누락 annotation은 로컬 Codex로 생성했다.
- 운영 DB 갱신은 pending 상태, 프로젝트 미생성, 씬 수, 대본 MD5, 원본 경로, 캐릭터 설정, 이전 annotation이 백업과 같은 경우에만 적용했다.
- 실제 웹의 generatedSpeakerAssets → savedSpeakerGeometry 함수로 모든 ready 씬을 읽고 좌표·화자·원본 연결이 허용되는지 검증했다.
- DB 갱신 후 상태와 씬별 집계를 재조회했다.
