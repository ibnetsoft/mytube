# Codex 시니어 청취용 대본 기준 — senior_listening_v3

실행 지침 원본: `worker/senior_script_guard.py`의 `CATEGORY_RULES`와 `contract()`.
카테고리 ID가 일반 문체 프리셋(`story`)이나 제목의 단어보다 우선한다.
새 Codex 생성에 적용하며 기존 토픽을 자동으로 덮어쓰지 않는다.
기존 카테고리 사용 제한은 이 지침으로 해제하지 않는다.

## 작성 및 검수 흐름

1. 기획 단계부터 인물·관계·시간순서·물건의 소유 및 이동·인물별 지식·단서와 회수 계획을 작성한다.
2. 5초 이미지 컷이 바뀌어도 낭독은 이어지는 이야기로 쓴다. 인물의 역할을 이름보다 먼저 소개한다.
3. 완성 대본을 교정한다. 공백, 예시 문장, 언어 오류, 장면 번호, 동일 문장의 과도한 반복, 동일 문단을 코드로 검사한다.
4. 별도 Codex 호출 `02c_senior_review`가 완성 대본 전문과 기획을 비교 검수한다. 작성자의 자체 점수를 입력으로 신뢰하지 않는다.
5. 85점 이상, 치명적 문제 없음, 9개 항목 전부 통과 및 항목별 구체적 근거가 있어야 승인한다. 필드 누락도 실패다.
6. 실패 이유를 교정 단계에 전달하여 한 번 더 수정·검수한다. 여전히 실패하면 이미지 프롬프트 생성과 완료 패키지 저장 전에 중단한다.
7. 작업 ID뿐 아니라 지침 버전·입력·검수 피드백·단계 지시의 해시로 캐시를 구분한다. 수정 요청에 이전 실패 응답을 재사용하지 않는다.
8. 워커가 최종 결과를 저장하기 직전 본문·씬 본문·검수 결과를 다시 확인한다.

단일 호출 생성 경로에도 별도 검수와 패키지 검사를 적용한다. 이 경로의 실패는 호출자에게 오류로 반환된다.
작성·교정·검수는 설정된 Codex CLI 모델을 사용한다. Gemini/Claude API를 새로 호출하지 않는다.

## 검수 항목

`cast_introduction`, `relationships`, `chronology`, `object_tracking`, `causality`,
`title_payoff`, `repetition`, `spoken_language`, `factual_grounding`.

원문 인용 또는 장면 참조를 포함한 근거를 요구한다. 명백한 창작은 사실 근거 항목에서
해당 없음의 이유를 설명할 수 있지만 경제·금융의 실제 제도 설명은 해당하지 않는다.
정보가 부족하면 주장을 생략하거나 검수에서 실패시킨다. 조회수 높은 영상 제목은 사실의 증거가 아니다.

코드 검사는 명백한 형식/반복 오류를 차단한다. 인과관계와 사실성은 모델 검수이므로
무오류를 보장하지 않는다. 실제 음성의 속도·발음·쉼과 시니어 청취 반응은 별도 검증 대상이다.

검증: `python -m pytest tests/test_codex_content_runner.py tests/test_senior_script_guard.py -q`.

## 기존 대본 수정

`scripts/repair_existing_topic_scripts.py`도 동일한 독립 검수를 거친다.
본문의 모순을 바로잡을 때 낡은 `story_core`와 `narrative_blueprint`도 함께 수정한다.
기존 이미지·영상 프롬프트와 생성된 자산은 보존하고, 수정본과의 대응을 검수한다.
검수 통과 전에는 DB를 수정하지 않는다. 저장 직전에 토픽 및 연결된 STD 프로젝트를
`output/script_repairs/backups`에 보관하며, 다른 작업이 바꾼 토픽이나 사용자가 직접
편집한 프로젝트 대본은 덮어쓰지 않는다. 프로젝트 저장은 버전 조건으로 보호한다.
저장한 토픽/프로젝트 대본은 다시 조회해 일치 여부를 확인한다.
기존 자막 완료 표시는 해제하고 음성 재생성이 필요하다는 표시를 남긴다.

기존 장면별 시간이 없으면 알려진 전체 길이를 보존하며 누락분만 대본 길이에 비례해
복원한다. 기존 장면 배정을 신규 생성의 5초 도입부 규칙으로 덮어쓰지 않는다.
수정된 내레이션과 장면 설명도 함께 동기화하되 이미지·영상 프롬프트는 유지한다.
제공되지 않은 과거 지침을 추정해 검수하지 않으며, 작성자 자체 평가와 독립 검수를
분리한다. 생성된 이미지가 없는 경우 실제 이미지 검증 완료라고 주장하지 않는다.

일괄 실행 시 `--continue-on-error`를 주면 실패한 토픽을 기록하고 나머지를 계속한다.
`output/script_repairs/batch_*.json`에 건별 결과를 기록한다. 실패는 부분 저장 가능성까지
포함하므로 결과를 확인해야 하며, 전체 성공으로 취급하지 않는다.
