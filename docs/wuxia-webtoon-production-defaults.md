# 무협 웹툰 제작 기본 설정

## 상태 컷 영상 교체 — 2026-11-16 사용자 지정

- 기존 1~3화도 씬 내부의 선택한 상태 컷 구간을 영상클립으로 교체한다. 기존 대본·확정 음성·상태 원화는 보존한다.
- Codex는 실제 원화를 검토하고 원화 첨부용 생성 프롬프트를 준비한다. 사용자가 외부 도구에서 생성하고 웹에 업로드한다. 프롬프트 준비를 영상 제작 완료로 보고하지 않는다.
- 자막 편집의 `상태 컷 영상 교체`에서 정확한 STATE ID를 선택한다. 원본 시작·사용 길이·원화 내 시작을 지정하며 원본 속도를 유지한다. 영상 또는 실제 녹음의 상태 컷 구간을 넘으면 사용 구간을 수정한다. 반복·늘이기·끝 프레임 고정으로 길이를 채우지 않는다.
- 클립은 원화 SHA에 묶인 별도 자산이다. 원화가 바뀌면 다시 검토한다. 영상 음성은 사용하지 않으며 기존 확정 음성이 기준이다. 원화로 복원해도 파일은 보존하고 과거 클립이 자동으로 되살아나지 않게 한다.
- 영상 구간의 정지화용 입모양·보조 루프·흔들림·카메라·시네마틱 효과는 중복 적용하지 않는다. 말풍선은 기존 발화 타이밍을 유지하되 실제 영상에서 얼굴·손을 가리지 않는지 검토한다.
- 웹과 AE는 같은 원본 구간·편집 프레임 시계를 사용한다. 통합워커는 `wuxia_state_clip/v1` 지원을 명시적으로 확인하고 실제 파일 SHA·규격·길이·전체 디코드를 검사한다. 구형 워커가 영상을 무시한 채 정지화로 완료 처리하면 안 된다.
- 원화 검토·프롬프트·업로드·웹 재생·실제 AE 출력 검증은 구분한다. 사용자 생성·업로드가 다음 단계이며, 그 전에는 1~3화 영상 교체 완료로 보고하지 않는다.

무협 웹툰 카테고리의 새 작품에 아래 기본 방향을 제안하고 적용한다. 작품마다 사용자의 변경 요청이 우선한다. 새 대본은 최종 설정을 보여주고 명시적인 시작 지시를 받은 뒤에 생성한다.

## 이야기와 음성

- 기본 형식은 오리지널 무협 성장 이야기와 한국 웹툰 스타일의 무빙툰이다. 주제와 인물, 배경, 분량은 작품마다 확정한다. 한국어와 가상의 중국풍 강호를 기본 제안으로 삼는다.
- 내레이션이 상황, 사건의 흐름과 필요한 속마음을 설명한다. 갈등, 결단, 반전 등 중요한 순간은 캐릭터가 직접 대사로 말한다.
- 캐릭터 대사는 말풍선으로 표시하고, 준비된 말풍선 효과를 대사 음성의 발화와 타이밍에 맞춘다. 대본과 장면 지시에서 내레이션과 화자별 대사, 말풍선 문구를 구분한다. 캐릭터별 음성은 실제 사용 가능한 음성 중에서 제작 시 배정한다.
- 화자 라벨이 붙은 단락도 닫는 따옴표 뒤의 행동·상황 서술은 별도 내레이션 블록으로 분리한다. 원문을 보존한 뒤 실제 웹 미리보기에서 말풍선에 서술문이 섞이지 않는지 확인하며, 섞인 상태로 등록하지 않는다. 구간 분리로 검토 번역이 달라지면 바뀐 구간만 로컬 Codex 대본워커로 번역하고 기존 번역은 보존한다.
- 참고 영상은 이야기 전달과 연출 방향의 참고 자료로 사용한다. 특정 기존 작품의 인물, 장면, 대사나 줄거리를 그대로 복제하지 않고 독립적인 이야기를 만든다.

## 이미지와 연출

- 기본 이미지 스타일은 `wuxia_webtoon`(무협 웹툰)이다. 명확한 선, 웹툰식 채색, 무협 복식과 무기, 세계관에 맞는 배경을 사용한다. 인물별 얼굴을 확실히 구별하고 각 인물의 정체성을 작품 내에서 일관되게 유지한다.
- 영상 생성 및 업로드 영상 씬은 기본 0개다. 정지 이미지와 준비된 AE 효과로 제작한다.
- 빠른 컷과 장면 전환을 필수로 계획하되 대사와 감정이 읽힐 시간을 확보한다. 중요한 장면에서 검기, 잔상, 속도선 등 준비된 효과를 장면에 맞게 적극 활용한다. 모든 효과를 모든 장면에 억지로 중첩하지 않는다.
- 하나의 사건/음성 씬 안에서도 거리·시점·주 피사체가 다른 전체 화면 컷 원화를 준비한다. 같은 배경·구도의 표정/포즈 상태는 필요한 연속 동작 연결에만 사용하고 기본 구도로 반복하지 않는다. 컷별 원화·전환·타이밍을 명시하며 연속 캐릭터 애니메이션을 생성했다는 뜻으로 보고하지 않는다.
- 패럴럭스와 분리 레이어는 필요한 장면만 선택한다. 카메라는 고정 구도를 기본으로 하고 느린 줌을 사용하지 않는다. 필요할 때만 짧고 분명한 중간 속도 움직임과 전후 정지를 사용한다.
- 장면별로 내레이션, 화자별 대사와 말풍선, 정지 이미지 상태, 컷 전환, 필요한 AE 효과와 타이밍을 제작 지시에 포함한다. 이미지·말풍선은 인물의 얼굴과 중요한 정보를 가리지 않게 배치한다.

## 설정 확인과 제작

- 대본 작성 전 제작 형식, 주제·참고 자료, 분량·장 길이, 언어·국가·시대, 이미지·연출 스타일, 패럴럭스·레이어·영상 씬 범위, 장면 상태 변화, 음악 프롬프트 및 추가 요청을 확인하고 최종 설정에 대한 명시적인 시작 지시를 받는다. 이 문서는 확인을 대신하지 않는다.
- 배경음악 프롬프트 생성 여부는 작품마다 확인한다. 음악 파일 생성 여부는 별도다.
- 승인된 감독 제작은 실제 자료와 출력물을 확인하고 품질 우려를 별도 기록하면서 최종 조립까지 진행한다. 취소, 소유권, 파일 및 타이밍 검증을 유지하고, 관리자 게시와 YouTube 업로드는 별도 작업이다.

## 얼굴 보호·말풍선 종류·타이포그래피 필수 기준

- **말풍선의 중요도와 관계없이 화자를 포함한 모든 인물의 얼굴을 절대 가리지 않는다.** 말풍선 몸체뿐 아니라 꼬리, 글자, 테두리, 그림자와 등장·퇴장 효과까지 얼굴 보호 대상이다. 타이포그래피에도 같은 기준을 적용한다.
- 실제 원화와 최종 화면의 크롭·비율을 기준으로 얼굴 보호 영역을 확인한다. 표시 구간 전체와 상태 컷 전환 전후를 검사한다. 배치 지시에 “얼굴 보호”라고 쓰여 있다는 이유로 안전하다고 판정하지 않는다.
- 안전한 여백이 부족하면 배치·줄바꿈·크기·컷 구성을 조정한다. 얼굴을 덮거나 읽을 수 없을 만큼 글자를 줄여 해결하지 않는다. 확인되지 않은 배치를 검증 완료로 보고하지 않는다.
- 기존 말풍선 프리셋 8종을 확인하고 발화 의미에 맞게 구분한다: `dialogue` 일반 타원, `rounded` 부드러운 둥근 상자, `shout` 외침 톱니형, `whisper` 속삭임 점선형, `thought` 생각 구름형, `reaction` 짧은 반응형, `narration` 사각 설명형, `electronic` 전자통신형. 모든 대사를 타원 하나로 통일하지 않는다. 이 목록은 프리셋 정의이며 무협 내레이션을 화면 자막으로 출력하도록 허용하지 않는다.
- 타이포그래피는 반응·속마음·효과음·시스템 문구를 구분하고 저장된 연출의 글꼴, 크기, 색, 외곽선, 회전, 등장·퇴장 방식, 강조 크기 변화와 표시 타이밍을 확인하여 적용한다. 일부 색상·크기만 반영한 상태를 전체 연출 적용으로 보고하지 않는다.
- 무협 관련 생성·수정·검수 전에 이 절과 실제 사용되는 말풍선·타이포 구현을 읽는다. 웹 미리보기와 렌더 경로가 같은 종류·배치·스타일을 반영하는지 대조하며, 실제 화면에서 얼굴 비가림·말풍선 종류·타이포 표현을 확인한 증거를 남긴다. 구현, 웹 미리보기, 최종 렌더 검증의 완료 범위를 구분하여 보고한다.

## 유저웹 음성 편집과 화면 글자의 구분

- 음성 편집용으로 나눈 대본 행과 화자·성별 정보는 TTS 입력이다. 이를 옛날이야기 등 일반 카테고리의 하단 자막으로 출력하지 않는다.
- `wuxia_webtoon`의 편집 미리보기와 렌더 요청은 일반 자막 트랙을 끈다. 기존 내레이션·화자 정보·녹음·타이밍 데이터는 보존한다.
- 화면 글자는 저장된 `wuxia_still_ae_episode/v1` 연출의 실제 대사 말풍선 및 선택적인 반응·속말·효과음 타이포만 사용한다. 저장된 연출이 없을 때 내레이션 원문 자막으로 대신하지 않는다.
- 화자 표시가 노랗게 보이는 것만으로 무협 연출 적용을 완료했다고 보고하지 않는다. 실제 웹 캔버스의 내레이션 원문 미표시와 말풍선 표시를 각각 확인한다. 편집 프리뷰와 실제 녹음 기준 동기화·렌더 결과는 별도 검증이다.

- 말풍선 몸체와 꼬리는 하나의 닫힌 외곽선으로 연결하며 접합부 안쪽 선을 그리지 않는다. 꼬리는 짧게 유지하고 화자의 머리·얼굴에 닿기 전에 여백을 두고 끝낸다. 웹·HTML·AE 미리보기 모두 같은 기준을 적용한다.
- 보호 좌표를 기록한 패키지는 본체·꼬리뿐 아니라 회전·최대 강조 크기를 포함해 검사한다. 음성 행 분할로 말풍선이 사라지지 않도록 문장 전체를 연결한다. 정지 상태에서 대사를 선택하면 글자를 읽을 수 있게 유지하고, 재생 중에 저장된 등장·퇴장 연출을 적용한다.

## 선택적인 GIF 보조 움직임 (2026-11-07)

- PNG 원화·상태 컷·기존 AE 연출을 기본으로 유지한다. 별 반짝임, 나뭇가지·잎, 머리카락 끝·옷자락, 불꽃·연기·물결에만 선택적으로 짧은 루프를 덧붙인다. 첫 적용은 배경·머리카락·나뭇가지 세 유형을 비교한 뒤 회차당 3~5컷 정도부터 판단한다. 모든 컷에 적용하지 않는다.
- 얼굴·머리·몸 전체를 흔들거나 눈·입·부상·소품·배경 위치를 바꾸지 않는다. 고정 카메라를 기본으로 한다. 루프 전체 프레임에서 얼굴·말풍선·꼬리·타이포·중요 정보의 보호 영역과 움직임 영역이 겹치지 않아야 한다. 머리카락이 새로 눈·입을 덮는 연출도 금지한다.
- 원본 GIF를 화면 전체에 자동 재생하지 않는다. 로컬 준비 도구로 승인 영역만 투명 PNG 프레임으로 추출하고 GIF disposal과 실제 프레임별 지속시간을 보존한다. 원본 PNG, GIF, poster PNG, 프레임 및 `ambient_loop/v1` manifest를 함께 보관한다. GIF 제작 도구가 실제 제공되지 않을 때 생성했다고 보고하거나 다른 유료 모델을 임의로 호출하지 않는다.
- AIR Studio 미리보기는 편집 시간에서 씬 시작을 뺀 밀리초로 프레임을 선택한다. 일시정지는 현재 프레임을 유지하고 탐색은 즉시 해당 프레임을 선택한다. 상태 컷이 바뀌면 이전 패치를 제거한다. `start_ms/end_ms/phase_ms/repeat`를 명시하고 브라우저 자동 GIF 재생 시간에 의존하지 않는다.
- 보조 움직임은 원화 위, 편집 가능한 말풍선·타이포 아래에 둔다. 미리보기 프레임 로딩·체크섬 오류는 원본 PNG로 표시한다. 표시 오류를 조용히 완성 처리하지 말고 제작 검수에 기록한다.
- 실제 AE 제작은 통합워커의 동결된 제출 입력으로 실행한다. 원화 SHA, 프레임 SHA, 캔버스, 실제 알파 픽셀의 이동 영역을 확인하고 동일 프레임 시계를 출력 FPS로 샘플링하여 HOLD 키로 적용한다. 일반 업로드 영상의 반복·정지·리타이밍 금지 정책과 별개 계약이다. 원화·상태 연결이 다르거나 지원하지 않는 제작 경로면 움직임을 임의로 생략하지 않는다.
- 준비 및 등록 방법은 `docs/AMBIENT_LOOP_INTEGRATION.md`를 따른다. 원화 검수·미리보기 검증·실제 AE 출력 검증을 구분하여 기록한다.

## 선택적인 대사 입모양 (2026-11-07)

- 사용자는 1·2·3화에서도 조건이 맞는 컷에만 입모양을 적용하도록 지정했다. 최초 수동 적용 범위는 **1화만**이었다. 2·3화의 기존 산출물 수정은 별도 실행하며, 새 회차는 아래 자동 준비 정책을 따른다.
- 모든 대사 씬이나 최소 개수를 강제하지 않는다. 얼굴이 충분히 크고 입과 양쪽 입술 경계가 잘 보이는 경우만 원화별로 선택한다. 적합한 컷이 **0개인 토픽도 정상**이다. 원경·뒷모습·작은 얼굴, 손·머리카락·수염·소품 등에 가려진 입, 윤곽·화자가 불확실한 컷은 원화를 유지한다.
- 첫 적용의 보수적인 기술 기준은 얼굴 높이 원화의 20% 이상과 충분한 입 해상도이며, 이 수치만 통과했다고 선택하지 않는다. 실제 원화와 닫힘·반열림·열림 합성본을 확인한다. 모델 응답의 “보인다”만으로 승인하지 않는다. 입을 크게 보이게 만들기 위한 줌·크롭·얼굴 확대를 새로 추가하지 않는다.
- `wuxia_dialogue_mouth/v1`은 선택한 **상태 원화 SHA + 화자 + 대사 블록 + 확정 음성 ID/SHA + 자막 행 원문·성우·시각**에 묶는다. 입만 제한된 투명 패치로 교체하고 머리·턱·눈·코·부상·배경은 보존한다. 눈 깜빡임이나 음성 반응 조명은 함께 추가하지 않는다.
- 해당 원화가 표시되고 선택 화자가 실제로 말할 때만 녹음의 진폭과 쉼에 따라 세 포즈를 전환한다. 내레이션·상대방 대사·원화 전환·음성/대본 변경에는 오래된 패치를 적용하지 않는다. 파생 연기 원화에 원본의 입 좌표를 무조건 상속하지 않는다.
- AIR Studio 편집 시계와 통합워커가 같은 포즈 선택을 사용한다. 입 패치는 원화 위, 말풍선·타이포 아래다. AE 입력은 `wuxia_native_timeline/v2`로 동결해 구형 워커가 입모양을 조용히 생략하지 못하게 한다. 전체 영상의 기존 음성·대본 무결성 검사도 우회하지 않는다.
- 진폭에 맞춘 3단계 웹툰식 발화 연출이며 음소별 정밀 립싱크로 보고하지 않는다. 원화·포즈 합성·실제 녹음 대사 일치·저장 재조회·웹 재생·실제 AE 렌더의 검증 범위를 구분한다.

### 앞으로의 자동 준비·확정 음성 연결

- 새 무협 패키지는 `wuxia_mouth_policy.auto_prepare=true`로 기록한다. 명시적인 비활성화는 존중한다. 과거 수동 적용 회차를 자동으로 재작성하지 않는다.
- **대본워커**가 실제 게시된 모든 상태 원화를 검토한다. 19씬 이후 제한·회차당 개수 제한·최소 개수는 적용하지 않는다. 얼굴 높이 20% 이상, 입 너비 1.4% 이상, 식별 신뢰도 90% 이상이며 실제 입술 윤곽·가림·얼굴 방향을 검수한 컷만 선택한다. 다른 화자의 얼굴이나 파생 원화에 좌표를 상속하지 않는다.
- 확정 음성 없이도 닫힘·반열림·열림 이미지를 내장 이미지 생성 기능으로 준비한다. 원화 SHA와 검수 좌표에 묶인 투명 패치·합성 검수·캐시·저장 경로를 보존한다. 원화·말풍선·타이포·카메라는 변경하지 않는다. 외부 유료 이미지 API로 임의 전환하지 않는다.
- 확정 녹음 저장은 같은 DB 트랜잭션에서 후속 작업을 등록한다. 대본워커는 준비된 이미지를 재사용하고, 음성 ID/SHA 및 실제 녹음의 행 원문·성우·시간을 대조한 뒤 진폭·쉼에 맞춰 연결한다. 실제 PNG의 SHA·캔버스·알파 범위와 발화 구간 밖 움직임을 다시 검사한다. 음성·대사·원화 변경 시 이전 연결을 재사용하지 않는다.
- 모든 대상 검토를 끝내고 적합한 컷이 0개면 `not_required`로 **정상 완료**한다. 원화가 게시되기 전에는 `waiting_images`, 음성 확정 전에는 `waiting_audio`라는 정상 대기 단계다. 검수 도구·생성·다운로드 실패는 0개로 둔갑시키지 않고 원본·부분 산출물을 보존하며 재시도한다.
- 유저웹은 같은 편집 시계로 결과를 재조회·표시한다. 통합워커는 제출 시 동결된 연결을 사용해 AE 합성·출력과 출력물 검수를 수행한다. 대본워커의 입 이미지 준비·녹음 연결 검수와 최종 AE 영상 검수는 별도 증거로 기록한다.

## 이미지 행동 지시와 실제 낭독문 분리 (2026-11-07)

- 무협 웹툰은 그림과 대사가 이야기를 이끌고 나레이션은 필요한 연결을 맡는다. 자세·손 위치·이동·표정·부상·소품·컷 전환은 이미지 제작용 `visual_action`에 상세히 기록한다. 실제 들려줄 문장만 `spoken_blocks`에 `narration`/`dialogue`로 구분하고, 대사에는 화자를 기록한다. `scene_text`와 낭독용 `script`에는 발화 문장만 연결하며 행동 지시·화자 라벨을 섞지 않는다. `narration_text`는 나레이션 블록만 별도 보관한다.
- 화면에 이미 보이는 행동·감정을 그대로 설명하는 나레이션은 검수해 제거한다. 예: 바닥을 짚은 손이 보이는 컷에서 “손으로 바닥을 짚었습니다”를 다시 읽지 않는다. 동작 정보를 지우지 않고 이미지 지시에 보존한다. 새 사실·시간 변화·화면에 드러나지 않는 원인·꼭 필요한 의미를 더하는 문장은 유지한다. 특정 동사나 정규식만으로 의미를 추측해 삭제하지 않는다.
- 로컬 Codex 대본워커는 모든 나레이션 블록을 같은 컷의 행동 지시·인접 컷·대사와 대조한다. 삭제에는 정확한 원문과 같은 컷의 시각적 근거가 필요하고, 유지에는 새로 전달하는 정보가 명시되어야 한다. 삭제 후 전체 이야기의 인과·부상·소품 소유·인물 관계·결말을 다시 검수하고 기록한다. 대사를 임의 삭제하거나 설명 대사를 새로 채우지 않는다.
- 무협에는 공통 청취 전용 검수의 “이미지 없이 모든 행동을 이해” 기준이나 씬별 최소 글자 수를 강제하지 않는다. 무대사 컷(`spoken_blocks=[]`, `text=""`)도 정상이다. 컷의 이미지 지시·기획 길이·효과음/호흡/정지는 보존한다. 줄어든 낭독 분량을 행동 설명, 비슷한 표현, 감상적 독백으로 채우지 않는다. 실제 음성 길이와 기획 길이는 별도 확인한다.
- 이미지 프롬프트·장면 연출·캐릭터 배치는 `visual_action`과 발화 내용을 함께 사용한다. 제작용 묘사를 없애 이미지의 정보가 빈약해지게 하지 않는다. `wuxia_visual_narration/v1` 검수는 **기획 시각 정보와 낭독문**의 대조이며 실제 이미지·음성 검수 완료로 보고하지 않는다. 이미지 게시 후에는 실제 컷과 대사를 함께 보며 중복·정보 누락을 다시 확인하고, 원화가 지시와 다르면 우선 시각 연출을 보완한다.
- 기존 1·2·3화의 확정 대본·이미지·녹음은 자동 재작성하지 않는다. 이 정책은 앞으로 만드는 무협 웹툰 대본에 적용한다. 기존 회차 수정은 명시된 요청 범위와 음성·타이밍 영향 검증을 따른다.

## 충격·떨림 연출 (2026-11-07)

- 실제 원화 검수에서 손가락 개수만 확인하지 않는다. 인물 자신의 해부학적 좌우를 화면 좌우와 구분하고 어깨→팔꿈치→전완→손목→엄지 기저부→손가락으로 이어지는 구조, 손바닥·손등 및 전완 회전, 물체를 잡는 엄지 방향을 함께 확인한다. 반대 손을 붙인 형태는 원화를 수정한다.
- 익명의 치료자·부축자는 얼굴이 보인다고 새 주연이 되는 것이 아니다. 몸통이나 목선이 프레임 안에 보이면 머리·목·어깨가 자연스럽게 연결돼야 한다. 얼굴 생성을 피하려고 머리 없는 몸통을 그리지 않는다. 손·전완만 필요한 구도는 몸통이 실제 프레임 밖에 있도록 설계한다. 컷 내부의 빈 목선·떠 있는 몸통·출처 없는 팔을 허용하지 않는다. 같은 의원의 치료자는 컷마다 동일한 외형을 사용한다.

- 원화 프롬프트와 참조에는 해당 컷에 실제 등장하는 인물만 포함한다. 등장하지 않는 주인공의 외형을 부정문으로 반복해 배경에 인물이 추가되는 일을 피한다. 최종 원화에서 소품 소유·빈 칼집 입구·부상 좌우·환부 아래 붕대 위치를 직전 회차와 대조한다. 보정본은 원본을 보존하고 새 SHA로 재검수한 뒤 원화·말풍선·입모양의 참조를 함께 갱신한다.

- 실제 타격·충돌·낙하 순간에만 `impact_shake`, `impact_flash`, `debris_burst` 등을 선택한다. 긴 대화나 모든 컷에 일괄 적용하지 않는다. 원화에 없는 폭발·상처·무공을 만들지 않는다.
- 효과는 확정 음성의 정확한 앵커와 상태 원화 ID에 묶는다. 충격 후 카메라 흔들림은 `shake_hz:10`으로 **1초에 10회 완전 왕복**하는 속도를 유지한다. `shake_axis`는 장면의 힘 방향에 따라 `vertical` 또는 `horizontal`, `duration_seconds`는 장면별 독립 값으로 정한다. 3초는 30회, 5초는 50회이며 총 10회를 긴 시간에 늘여 재생하지 않는다. 지원 범위는 0초 초과~10초, 24fps 이상을 기본으로 하고 초당 20프레임 미만이면 동결을 거부한다. 두 축을 동시에 임의 흔들지 않는다.
- 낙하·내려찍기는 상하, 횡방향 충돌·측벽 파괴는 좌우를 우선 검토한다. 충격·잔진동이 이어지는 장면은 3·5초를 쓸 수 있고 작은 신체 충돌이나 짧은 원화 노출은 1·2초로 끝낼 수 있다. 앵커 시작 후 0.05초 지연, 얼굴·말풍선 보호, 실제 상태 노출 구간을 검수한다. 상태 컷에서 중단되어 반복 횟수가 줄거나 안전 검사에서 일부 프레임만 정지되는 설정은 게시하지 않는다. 카메라 진폭은 1920×1080 기준 가로 최대 16px, 세로 최대 12px이며 장면별로 조절한다. 종료 후 고정으로 복귀하고 느린 줌으로 분량을 채우지 않는다.
- 섬광·파편 등 다른 일회성 효과는 기존 0.8초 이하 제한을 유지한다. `shake_cycles`는 이전 1초 테스트의 호환 필드이며 새 제작에는 `shake_hz`를 쓰고 둘을 동시에 저장하지 않는다. 1·3·5초의 10Hz 샘플과 AE HOLD 키를 검사해 반복 속도가 같음을 확인한다.
- 실제 저장 원화와 SHA를 검수한다. 원화·입모양·보조 움직임은 함께 움직이며 말풍선·대사 글자는 고정한다. 이동 및 순간 확대 후에도 얼굴을 자르거나 말풍선에 가리지 않는다. 파편·섬광·집중선은 모든 머리와 문자 보호 영역을 피한다. 얼굴 핵심 영역의 별도 검수는 해당 원화 SHA에 귀속한다.
- 웹은 편집 재생 시계에서 결정론적으로 같은 효과를 계산한다. 통합워커 제출 시 `wuxia_native_timeline/v3`에 매 프레임 변환·도형을 동결하고 AE는 그 값을 그대로 실행한다. AE에서 별도 랜덤 흔들림이나 속도 재해석을 추가하지 않는다. 대본워커는 연출과 자산 준비, 통합워커는 확정 음성 연결 및 최종 합성을 맡는다.
- 효과만 수정할 때 기존 원화·대본·음성·입모양 자산을 재생성하지 않는다. 타이밍 앵커 누락·얼굴 검수 누락·잘못된 동결 계약은 오류로 기록하고 복구한다. 테스트 통과, 웹 재생 확인, AE 출력 파일 검수는 서로 다른 증거로 보고한다.
- 웹 배포만으로 AE PC의 실행 소스가 갱신되지 않는다. 무협 제출은 `required_worker_contract`를 기록하고 실제 점유 토큰에 묶인 워커 지원 확인 없이는 서버가 실행·완료 상태를 거부한다. 실제 작업 결과에서 원화 그대로 넘기기(`source_passthrough`)가 확인되면 효과 적용본으로 보고하지 않는다. 기존 원본·음성·실패 증거를 보존하고 실행 소스 갱신 후 다시 제작한다.
- 짧은 효과는 편집 화면 전체의 반올림된 시간 상태만으로 재생하지 않는다. 재생 중 원화 미리보기는 실제 최종 음성의 currentTime(구간 음성은 장면 시간으로 매핑)을 직접 읽고 렌더 프레임 단위로 갱신한다. 일시정지·탐색은 편집 시계로 복귀하며, 버퍼 대기 시간을 애니메이션 진행으로 계산하지 않는다.
- 발화가 없는 컷은 제작용 행동 지시를 TTS 문장으로 바꾸지 않는다. 원화 패키지에 명시적인 시작 시각·짧은 유지 시간을 저장하여 무발화 컷의 상태 전환과 작은 접촉 효과도 재생할 수 있게 한다. 이 프리뷰 시간과 확정 음성 시간표를 구분한다.

- 입술 표식이 얼굴 윤곽 또는 입 패치 밖에 놓인 수치 검증 실패도 같은 한 차례 복구 대상이다. 두 번째에도 확인되지 않으면 원화를 유지하고 실패한 좌표·원본 얼굴을 보존한다. 검수 응답 자체의 화자·순서·불리언 판정이 잘못된 경우는 정상적인 부적합 판정으로 바꾸지 않는다.
- 선택 입모양 검사에서 정상 형식의 낮은 신뢰도·불확실한 입 노출 판정은 해당 인물의 원화 유지로 처리하고 다른 컷 검사를 계속한다. 일반 AE의 엄격한 화자 확정 정책을 무협의 최소 적용 개수로 오해하지 않는다. 신뢰도를 올려 쓰거나 불확실한 입을 승인으로 바꾸지 않는다.

- 유저에게 예약 배정된 `pending` 주제도 원화 준비 대상이다. 실제 프로젝트로 가져간 `assigned_at` 여부와 예약 소유자를 구분한다. 준비 시작 시 예약 소유자를 고정해 매 작업과 저장 RPC에서 일치를 검사하고, 소유자·주제 상태·원화 지문이 바뀌면 기존 작업을 보존한 채 쓰기를 중단한다.

## 상황별 팝업 클로즈업 컷 (2026-11-07)

- 새 무협 웹툰 제작에서는 **기본 장면 위에 작은 클로즈업 컷이 빠르게 나타나는 연출을 자동으로 검토·선택**한다. 살기 감지·결심의 눈빛, 비웃음·의미심장한 입꼬리, 발검 직전 손·칼자루 등 이야기의 강조점에만 사용한다. 대본의 행동 지시에 후보와 이유를 기록하고 실제 원화가 나온 뒤 판단한다. 매 컷 적용하거나 숫자를 채우지 않는다. 적합한 순간이 없으면 `not_required`가 정상이다.
- 상한은 **전체 장면 6개당 1개 이하, 회차당 최대 5개**다. 짧은 회차는 더 적게 쓴다. 선택한 장면 사이에 최소 두 장면을 두고 팝업 종료부터 다음 등장까지 최소 20초를 확보한다. 기본 동시 표시 1개, 화면 면적 3~20%, 총 1.8~3.2초(기본 2.2초), 등장 0.12초 후 충분히 고정 유지한다. 기본 퇴장은 0.24초 페이드이며, 왼쪽 가장자리 컷은 `exit:"left"`, 아래쪽 가장자리 컷은 `exit:"down"`으로 0.32초 동안 화면 밖으로 빠져나갈 수 있다. 장면에 맞게 선택하고 모든 팝업에 같은 이동을 강제하지 않는다. `exit:"cut"`은 유지 후 컷 전환이 필요한 경우에만 쓴다. 전체 화면의 느린 줌은 넣지 않는다.
- 대본워커/제작 Codex는 원화 제작 후 실제 저장 PNG를 열어 눈·입·손의 대상과 정체성을 확인한다. 같은 원화의 크롭을 우선 재사용하며 해상도·구도가 부족하면 별도 상세 원화를 준비하고 검수한다. 다른 인물이나 다른 상태의 눈·입을 붙이지 않는다. 팝업용 얼굴 자체는 의도한 강조 이미지이지만, 기본 화면의 모든 얼굴·입 패치·말풍선·꼬리·타이포·중요 정보는 가리지 않는다. 안전한 여백이 없으면 해당 후보를 제외하고 이유를 남긴다.

- 이 도구는 팝업을 반복하지 않는 등장·고정 유지·선택 퇴장을 포함한 투명 PNG 최대 16프레임으로 준비해 **기존 `ambient_loop/v1` 패치 합성 경로**로 전달한다. `popup_cut` 메타데이터로 보조 환경 움직임과 구별한다. 원화·대본·음성을 바꾸지 않고 웹 `stdWuxiaPresentation`/`StdWuxiaScenePreview`와 통합워커 `wuxia_native_timeline`이 같은 편집 시계를 소비한다. 기본 배경의 자동 흐림·어둡게 처리는 하지 않는다.
- 로컬 준비는 등록이 아니다. `--upload-prefix`를 주면 설정된 저장소에 파일을 게시하고 `package.with-popups.json`을 별도로 만든다. 원본 패키지를 보존하고 새 패키지로 등록한 뒤 재조회한다. 빈 계획도 검토 결과를 `popup-review.json`에 남긴다. 원화 준비·생성·업로드 실패는 0개 성공으로 바꾸지 않는다.
- 원화 노출·음성 타이밍이 확정되거나 바뀌면 선택한 순간과 초 단위 창을 다시 대조한다. 상태가 바뀌면 팝업도 즉시 제거되므로, 최종 음성 기준으로 표시 창 전체가 같은 상태에 있는지 확인한다. 별도 상세 원화를 사용하는 경우에는 해당 원화를 검수된 상태로 등록한 뒤 준비하며 본 도구의 원본 크롭이라고 속이지 않는다. 현재 원본 크롭 팝업에는 별도 립싱크를 붙이지 않고, 발화 중 입을 정밀하게 따라야 하는 컷은 이 방식의 대상에서 제외한다.
- 납품 전 실제 합성 프레임에서 얼굴 비가림·가독성·빠른 등장·충분한 고정 유지·선택 퇴장·빈도·상태 전환을 확인하고 품질 기록에 남긴다. 테스트, 웹 재생, 실제 AE 출력 검증은 구분한다. 기존 확정 회차에는 일괄 추가하지 않는다.

### 팔과 손의 좌우 오류 재발 방지 (2026-11-07 사용자 정정)

- 왼팔에 오른손, 오른팔에 왼손을 붙이는 오류를 반복하지 않는다. 이미지 제작 지시에는 보이는 손마다 **인물 자신의 왼손/오른손**, 손바닥/손등 노출, 손목 회전과 접촉·파지 대상을 명시한다. 화면 좌우와 해부학적 좌우를 혼동하거나 엄지가 화면 어느 쪽에 있다는 이유만으로 판정하지 않는다.
- 실제 저장 원화를 전체 구도와 손 확대 양쪽으로 검수한다. 어깨→팔꿈치→전완→손목→엄지 기저부가 같은 팔에 연결되는지 양손을 각각 추적하고, 벽을 짚는 손과 무기를 쥔 손의 엄지·손바닥·관절 방향을 확인한다. `anatomy_review`에 원화 SHA, 인물별 좌우 손, 가시성, 판정과 근거를 남긴다. 보이지 않는 관절을 확인했다고 기록하지 않는다.
- 좌우가 바뀌거나 연결이 뒤틀린 손은 원화를 보정하고 새 SHA로 다시 검수한다. 단순 좌우 반전·손가락 수만 맞추기·팝업으로 가리기로 통과시키지 않는다. 보정 후 원화에 연결된 팝업·입모양 좌표와 자산 지문을 재검증하고 기존 음성·대본은 보존한다. 품질 문제로 전체 제작을 중단하지 않되, 오류를 정상 원화로 승인하거나 수정하지 않은 원화를 수정 완료로 보고하지 않는다.
- 이번 미리보기의 손은 사용자에게 좌우 오류가 지적된 자료다. 연출 예시 승인과 해부학적 원화 승인을 구분하며, 해당 원화를 손 검수 통과 사례로 재사용하지 않는다.

## 동작 타이포·속마음·깜빡이는 사선 (2026-11-07)

- 손을 쥔 모습이 보이는 컷에서 “손을 꾹 쥐었습니다”를 낭독하지 않는다. 동작과 손의 좌우·힘줄·파지 형태는 `visual_action`에 남기고, 강조가 필요하면 화면 타이포 **“꾸욱”**으로 표현한다. 인과·새 정보가 있는 내레이션은 유지한다. 이는 음성 효과음 생성 지시가 아니다. 화면 타이포를 `spoken_blocks`, 낭독 원문이나 TTS 행에 자동으로 넣지 않는다.
- “꾸욱”, “꽉”, “움찔”, “흠칫” 등은 장면의 실제 의미에 맞게 고른다. 모든 동작에 글자를 붙이거나 중복 낭독하지 않는다. `graphics`의 `kind:"typography"`에 실제 표시 문구, 상태 원화 ID, 노출 시각, 안전한 `layout`을 저장한다. `style`의 `font`(`DoHyeon-Regular`/`BlackHanSans-Regular` 등 실제 사용 가능 글꼴), `size`, `fill`, `stroke`, `stroke_width`, `rotation`, `entry:"settle"`, `scale_peak`를 사용한다. 예: 짙은 자주색 “꾸욱”, 밝은 가는 외곽선, -12도 기울기, 등장 시 112%에서 빠르게 안정, 1.5~2.2초 읽을 시간. 글꼴은 프리뷰/AE 양쪽 설치·표시를 확인한다. 손·얼굴·말풍선에 겹치지 않게 가까운 여백에 놓는다. 타이포와 원화가 합쳐진 이미지로 굽지 않고 기존 편집 가능한 글자 경로를 쓴다.
- 혼자 생각하는 말은 기존 **`bubble_style:"thought"` 구름형 속마음 말풍선**을 적극 구분해 사용한다. 이미 지원하는 종류이므로 새로운 미지원 이름을 만들지 않는다. 외치는 대사 `shout`, 일반 대사 `dialogue`, 짧은 반응 `reaction`과 섞어 통일하지 않는다. `thought`는 입으로 향하는 대사 꼬리 없이 표시된다. 첨부처럼 가는 선으로 둘러싼 강한 독백은 사선/집중선 강조와 조합할 수 있으나 구름형과 동일한 외곽선이라고 보고하지 않는다. 속마음도 소리로 들려줄 문장만 `spoken_blocks`에 넣으며, **화면 글자만 있는 생각을 화자의 실제 발화로 만들거나 입모양을 움직이지 않는다.**
- 실제 인물 움직임 없이도 긴장·힘주기·압박을 나타내는 **고정 사선 해칭**을 선택할 수 있다. 실제 이동을 암시하는 속도선과 구별한다. 선만 약하게 나타났다 사라지고 원화·카메라는 고정한다. 기본 1.4초, 범위 0.8~2.4초, 켜짐/꺼짐 각각 0.18~0.4초(기본 0.2초), 화면 일부의 제한된 영역에 적용한다. 전체 화면의 강한 점멸이나 모든 장면 일괄 적용을 하지 않는다. 얼굴·눈·입·손의 구조·말풍선·타이포를 가리지 않으며, 공간이 부족하면 제외한다.
- 준비 도구: `python3 -m worker.wuxia_hatch --source SOURCE.png --spec SPEC.json --output DIR`. spec에는 실제 원화 `source_sha256`, `source_reviewed:true`, `reason`, 정규화 `region`/`protected_regions`, 장면 기준 `start_ms`, `duration_ms`, `blink_interval_ms`, `direction:"rising"|"falling"`을 기록한다. 최대 영역·보호 구역 검사를 거쳐 반복하는 투명 PNG 2프레임과 `manifest.local.json`을 만든다. 생성된 프레임을 게시하고 프레임별 실제 저장 위치·URL·SHA로 바꾼 뒤 해당 상태의 `ambient_loops`에 붙인다(상태당 최대 4개). `prepared.invalid`/`pending`은 로컬 표식이며 등록용이 아니다. 원화 SHA와 상태 노출 창·최종 음성 시간을 재확인한다. 웹과 AE는 기존 공통 패치 시계로 동일하게 켜고 끈다. 로컬 준비·등록 재조회·실제 웹 재생·AE 출력 검증을 구분한다.

- 기본 전환은 명확한 **하드 컷**이다. 시선·행동 방향이 이어지는 상태 컷을 연결하고, 중요한 공격은 준비/이동 → 접촉 → 상대 반응/결과로 짧게 묶는다. 접촉 직전과 직후의 길이를 달리해 강약을 만들며 모든 컷을 같은 길이·같은 박자로 자르지 않는다. 음악 비트보다 사건·발화·접촉 시점을 우선한다.
- 강조가 필요한 순간만 짧은 펀치 인 또는 방향성 있는 빠른 팬·슬라이드를 선택한다. 카메라 이동 창은 약 0.15~0.35초를 검토 출발점으로 삼고 전후 정지를 둔다. 이는 기존의 느린 줌·장면 전체 완만한 확대 금지를 바꾸지 않는다. 원화 바깥 노출, 얼굴·손·소품 잘림, 말풍선 가림을 실제 이동 범위 전체에서 확인한다.
- 접촉 섬광은 국소적인 짧은 표현을 우선하고 기존 충격 계약의 지속시간·지연·보호 영역을 따른다. 전환용 화면 플래시는 큰 사건 전환에만 드물게 검토하며 반복 점멸을 기본으로 삼지 않는다. 흔들림은 실제 충격 이후에만 사용한다. 교차 편집은 실제로 병행되는 사건·반응에, 팝업은 기존 빈도·가독 시간 계약에 맞는 디테일 강조에 사용한다. 페이드는 시간 경과·여운·종결처럼 의미가 있을 때 선택한다.
- 컷별로 원화/상태 ID, 표시 시작·종료, 전환 이유·종류·이동 창, 동작/접촉/음성 앵커와 효과 시각을 기록한다. 필요한 상태 원화와 분리 자산을 제작 지시에 포함한다. 대본워커는 이 계획과 지시를 준비하며 실제 영상 생성·합성 완료로 보고하지 않는다.
- 미리보기와 실제 출력에서는 액션이 읽히는지, 대사 도중 글자가 사라지지 않는지, 접촉보다 효과가 먼저 나오지 않는지, 긴 정지와 과도한 전환이 반복되지 않는지 확인한다. 지원되지 않는 효과는 이름만 저장해 적용됐다고 하지 않는다. 웹·통합워커의 동일 시간표 적용과 실제 렌더 검증은 각각 증거를 남긴다. 기존 확정 회차는 일괄 재작성하지 않는다.


### 실제 씬 전환 저장과 실행

- 무협 전환은 기존 유저웹의 씬 선택 → 효과 → 화면 전환에서 저장한다. 새 패키지 제작 지시도 해당 씬의 `transition_effect`에 같은 ID를 기록한다: `none` 하드 컷, `wipe_left/right/up/down` 방향 슬라이드, `flash` 짧은 화이트 플래시, `punch` 펀치 줌, `snap_shake` 스냅 흔들림, `dissolve` 디졸브, `fade_out` 끝 페이드. 기존 `push`/`zoom`/`brighten`/`darken`은 각각 왼쪽 슬라이드/펀치/플래시/끝 페이드로 해석한다. 교차 편집은 별도 합성 효과가 아니라 인과가 있는 컷 순서로 계획한다.
- 시작 전환 기본 창은 0.24초, 플래시는 0.125초, 디졸브·끝 페이드는 0.32초이며 짧은 씬은 길이의 절반으로 제한한다. 펀치는 최대 106%에서 짧게 안정하고 유지 구간에 느린 확대를 추가하지 않는다. 스냅 흔들림은 의미 있는 충격/강한 진입에만 선택한다. 사건 의미를 확인해 컷별로 선택하며 반복 순환·전 씬 일괄 적용하지 않는다.
- 슬라이드·디졸브의 뒤 화면은 직전 씬 마지막 상태의 SHA가 확인된 **정지 원화**다. 직전 입모양·말풍선·보조 루프를 이어 재생하는 효과로 보고하지 않는다. 현재 씬의 원화·입 패치·말풍선·타이포는 같은 전환을 적용받는다. 씬 구간 내부에서 처리하므로 녹음 시간·전체 길이는 늘리지 않는다.
- 웹 미리보기의 프레임 값을 `wuxia_native_timeline/v4`로 동결해 AE 통합워커에 전달한다. 구형 워커는 v4를 조용히 생략할 수 없고 업데이트가 필요하다. 효과 없는 기존 씬은 종전 계약을 유지한다. 실제 회차 적용 전후 원화·얼굴·글자 가독성과 실제 출력은 별도 검수하고, 기존 확정 회차를 일괄 변경하지 않는다.


## 새 무협의 자동 카메라·열기 선택과 실제 AE 확인 (2026-11-07)

- 앞으로 만드는 무협 웹툰은 `docs/WUXIA_TRANSITIONS.md`의 자동 선택·실제 AE 검수 계약을 따른다. 로컬 대본워커가 씬의 시각 지시와 사건에서 이동·줌·열기를 선택하고 근거를 저장한다. 고정 화면도 정상이며 반복 순환·효과 할당량을 강제하지 않는다. 실제 원화·보호 좌표와 실제 AE 출력의 이동 구간·열기 위상을 각각 검수해 결과를 기록한다. 기획·테스트·웹 예시를 실제 AE 검수 완료로 보고하지 않는다. 기존 회차는 보존하고 새 회차 시작 확인을 유지한다.

## 검기·신체 기운 자동 준비

새 무협 제작물은 실제 게시 원화에서 검기·몸에서 방출되는 기운을 자동 검토해 적용한다. 인물 전체·검날·손잡이·말풍선은 고정하고 기운만 해당 상태의 마지막 프레임까지 반복한다. 원화 보호·합성 검수·소유권을 지키며 불확실성과 실행 실패를 무효과 성공으로 바꾸지 않는다. 기존 확정 회차는 보존한다. 구현·검증 절차는 [WUXIA_ENERGY_AUTOMATION.md](WUXIA_ENERGY_AUTOMATION.md)를 따른다.

## 선택적 비네팅·정보 패널·바운스·슬라이드 블러

앞으로 생성하는 무협 웹툰은 [WUXIA_CINEMATIC.md](WUXIA_CINEMATIC.md)의 `wuxia_cinematic/v1` 계약을 적용한다. 로컬 대본 워커가 장면 내용에 근거해 네 연출을 드물게 선택하며, 강제 할당이나 기존 효과 중복은 없다. 실제 원화 SHA·계획·문자에 연결된 보호 영역과 패널 전체 바운스 범위를 검토한 뒤 웹 편집 시계 샘플을 AE 네이티브 v6에 고정한다. 정보 패널은 대본의 명시된 정보를 정확히 인용하고 읽기 구간을 확보한다. 인물·무기·문자는 비네팅/패널에서 보호하고, 슬라이드 블러는 짧은 원화 노출에만 적용해 문자를 선명하게 유지한다. 기운만 움직이는 상태에서는 억제하고 기존 확정 회차를 자동 변경하지 않는다. 실제 출력 검토와 품질 노트를 별도로 보존한다.

## 선택적 흰색·노란색 전격과 공격 방향선

공격 방향의 속도선 → 실제 접촉의 짧은 플래시 → 근거 있는 흰색·노란색 전기 방전은 [WUXIA_ATTACK_ACCENTS.md](WUXIA_ATTACK_ACCENTS.md)의 `wuxia_attack_accent/v1` 계약과 준비 도구를 따른다. 실제 원화 SHA·이동/접촉 근거·얼굴/손/문자 보호를 검토하고 필요한 효과만 선택한다. 웹 편집 시계의 동일 도형을 AE에 동결하며 실제 AE 출력 검수는 별도로 남긴다. 기존 확정 회차를 일괄 변경하지 않는다.

## 다양한 촬영 구도와 3초 컷 상한 (2026-11-08 사용자 정정)

- **씬(scene)**은 같은 사건·장소·시간을 이루는 단위이며, **컷/숏(cut/shot)**은 한 구도로 화면에 표시되는 단위다. 프로그램의 기존 씬/음성 ID를 보존하면서 그 안에 여러 전체 화면 컷을 설계한다. 팝업과 작은 움직임은 보조 연출이며 기본 컷 분할을 대신하지 않는다.
- 새 무협 컷은 **최대 3.0초**다. 느린 줌으로 체류를 숨기지 않는다. 액션의 준비/이동, 접촉, 반응/결과를 서로 다른 컷으로 읽히게 연결한다. 모든 컷을 3초로 채우거나 일정 주기로 자르지 않는다. 기존 확정 회차를 자동 재편집하거나 진행 중인 회차를 이 설정으로 덮어쓰지 않는다.
- ‘고정 카메라’는 **컷 안에서의 정지**를 뜻한다. 컷 사이까지 같은 거리·각도를 유지하라는 뜻이 아니다. 3~4명을 적당한 거리에서 한꺼번에 보여주는 중경·눈높이 구도를 기본값처럼 반복하지 않는다. 설정용 원경/전경, 1인·2인 구도, 얼굴·눈 클로즈업, 손·무기·접촉부 디테일, 인물 없는 배경·소품, 뒷모습, 어깨 너머 역숏, 낮은 시점(올려다봄), 높은 시점(내려다봄)·탑숏, 인물 POV에서 사건에 맞는 구도를 선택한다. 정해진 목록 순환이나 효과/각도 할당량을 강제하지 않는다.
- 연속 컷을 검토할 때 거리·시점·주 피사체·인원수·프레임 점유율을 함께 본다. 동일한 인물 배열과 비슷한 중경/눈높이 그룹 구도가 반복되면 그림의 표정·효과만 바꾸지 말고 원화 구도를 다시 설계한다. 대화의 숏/역숏처럼 반복이 필요한 경우에는 화자·시선·반응·행동에 근거한 이유를 남긴다.
- **각도가 바뀌면 그 시점의 원화를 새로 준비한다.** 같은 평면 그림을 회전·확대해 로 앵글·하이 앵글·뒷모습이라고 부르지 않는다. 실제 원화에 충분한 해상도와 올바른 정보가 있는 얼굴·손 디테일만 의미 있는 크롭으로 재사용할 수 있다. 발화 정보·소품 소유·부상 좌우·이동 방향·공간 축/시선 연결을 유지한다. 인물 없는 컷에는 등장하지 않는 인물 참조를 억지로 붙이지 않는다.
- 접촉 디테일 컷은 **실제 충돌 순간 이후에만** 짧은 흔들림/방전을 선택한다. 얼굴 클로즈업이나 환경 컷까지 함께 흔드는 전체 씬 흔들림을 기본으로 삼지 않는다. 손·얼굴의 가림과 해부학, 새 구도에 맞는 광원·원근·앞뒤 가림을 실제 그림에서 검수한다.
- 대본·연출 계획에는 컷마다 `cut_id`, `scene_id`, 촬영 거리·시점, 주 피사체/실제 등장 인물, 서사 목적, 전환/접촉·음성 앵커, 계획 표시 길이(≤3초), 필요한 원화/사용 가능한 크롭 여부를 기록한다. 이미지 프롬프트에도 해당 컷의 구도를 명시하고 컷별 실제 원화를 준비한다. 이것은 음성 씬의 대사·내레이션을 무조건 3초 단위 문장으로 쪼개라는 뜻이 아니다.
- 최종 음성이 길어지면 전체 컷 시간표를 다시 검토하고 필요한 반응/환경/디테일 원화를 추가한다. 같은 원화를 늘려 잡거나 같은 그림을 복제해 새로운 컷인 것처럼 세지 않는다. 3초 초과 구간, 구도 반복, 가독성·연속성 문제는 정확한 원화/시간과 함께 품질 기록에 남긴다. 새 기준의 계획·원화 준비·웹 재생·실제 AE 출력 검증은 서로 구분한다.
- 10분 영상이면 컷 상한만으로 최소 약 200개의 화면 구간이 필요하다. 이것이 모두 새 그림 200장이라는 뜻은 아니나, 기존 소수 원화에 흔들림과 팝업만 붙여 충족했다고 보고하지 않는다. 새 제작의 컷/원화 수와 작업량을 이 기준에 맞춰 계획한다.

## 나레이션은 장면의 서기가 아니라 흐름의 지휘자 (2026-11-08 사용자 정정)

- 이 분리는 **대본 생성 단계**에서 무협 웹툰에 적용한다. `visual_action`은 보일 동작·표정·공간·소품·촬영/컷 지시이며 낭독하지 않는다. `spoken_blocks`의 narration/dialogue만 음성 원고로 연결한다. 나레이션 전용 `narration_text`와 나레이션+대사의 통합 `scene_text`/`script`를 구분한다. 그림 제작은 시각 지시와 발화를 함께 사용한다.
- 나레이션은 앞뒤 장면의 인과와 호흡, 시간·장소 전환, 근거 있는 대비/위험, 새 정보와 공개 순서를 조율한다. 그림으로 보이는 주먹·칼질·이동·부상·표정을 따라 읽는 행동 중계를 하지 않는다. 액션·타격은 원화와 소리만으로 읽힐 때 말을 비운다. 모든 컷에 나레이션을 채우지 않는다.
- `~했습니다/~었습니다/~였습니다`를 이어 붙이는 보고체를 반복하지 않는다. 어미만 바꾸거나 단문을 길게 붙이는 것이 수정이 아니다. 남길 정보와 장면 내 기능을 먼저 정하고, 일관된 이야기 목소리 안에서 길이·쉼·강세를 조절한다. ‘그때/하지만/아직 몰랐다’ 같은 접속·예고 문구를 매번 붙이는 습관도 피한다.
- 경고·요구·거절·선택·관계 변화·발견처럼 실제 다음 행동을 바꾸는 순간에는 해당 캐릭터가 자기 말로 말하게 한다. 나레이터가 그 결정을 대신 요약하지 않는다. 보이는 행동 설명을 대사로 옮겨 쿼터를 채우지 않는다. 필요 없는 해설 대사나 생각 낭독을 늘리지 않는다.
- 나레이터는 전체 흐름을 알아야 하지만 후속 발견을 성급히 스포일러하거나, 원문에 없는 동기·위험·설정을 만들어 말을 정당화해서는 안 된다. 장면의 목적과 정보 공개 순서에 맞게 개입하거나 침묵한다.

- 3D 자산을 합성할 때도 승인된 2D 화풍에 맞춘 선화·셀 채색 렌더/마감 결과를 사용한다. 이전 절의 '동일 자산의 렌더/픽셀 유지'는 형태·상태 연속성을 위한 것이며, 원시 3D 렌더의 재질·광택·명암을 최종 화면에 그대로 남기라는 뜻이 아니다. 2D 마감 후에도 실루엣·비율·접촉·가림이 유지되는지 확인한다.
- 화풍 기준 이미지를 캐릭터 정체성/복장 참조와 역할을 분리하여 생성·마감 입력에 실제 연결하고 파일/SHA를 기록한다. 스타일 이미지 속 인물의 얼굴·머리·복장·소품은 해당 컷에 복사하지 않는다. 'webtoon', 'cel shading', 'no 3D' 같은 문구만으로 스타일이 고정됐다고 간주하지 않는다. 기존 스타일 샘플 자체에 사실적 질감/입체 명암이 강하면 이를 무조건 정답으로 삼지 말고 승인된 2D 기준과 대조한다.
- 연속 컷 검수에 화풍 일치를 포함한다. 인물만 만화풍이고 배경/철창/검은 사실적인 3D처럼 보이는 혼합, 수정할수록 재질과 입체 명암이 강해지는 누적 변화를 확인한다. 원화 재생성·국소 수정 이후에도 같은 기준을 적용한다. 문서 보완을 기존 원화 수정·파이프라인 구현·회차 검증 완료로 보고하지 않는다.

## 해부학 불합격 원화 사용 금지 — 2026-11-18 사용자 우선 지시

- 손·손가락·손목·팔·어깨·몸통·골반·다리·무릎·발목·발·발가락·머리/목의 연결·좌우·관절 회전·체중 지지를 실제 원본과 세부 픽셀에서 검수한다. 가려진 손가락을 무조건 결손으로 간주하지 않으며 판단이 불가능하면 불확실로 남긴다.
- 실패/불확실/필수 검수 대기 원화는 웹 미리보기와 AE 출력에 사용하지 않는다. '효과만 끄고 불량 원본을 정지 화면으로 사용'하는 종전 처리와, 해당 해부학 결함을 품질 노트만 남기고 사용하는 처리는 이번 지시로 대체한다. 다른 정상 자산 제작은 계속하되 해당 컷은 수정·재생성·재검수 대상으로 유지한다.
- 결함 좌표와 관찰 근거로 프롬프트를 다시 작성한다. 손의 주인/해부학적 좌우와 어깨-팔꿈치-손목-엄지 연결, 골반-무릎-발목-발 연결을 구체적으로 고친다. 신체 구조가 무너졌으면 같은 사건을 유지하는 단순한 자세로 바꾸며, 흐림·효과·말풍선·크롭으로 오류를 숨기지 않는다. 승인된 얼굴·복장·소품 상태와 최종 2D 웹툰 화풍을 보존한다.
- 실제 내장 image_gen 재생성 결과를 별도 버전/SHA로 보존하고 전체 그림과 세부를 다시 검수한다. 변경된 파일은 이전 합격·입모양·효과 좌표를 승계하지 않는다. 통과한 새 파일만 저장 검증 후 원본 SHA에 연결된 교체 후보로 사용한다. 같은 실패의 자동 재시도는 제한하며 한도 소진/도구 불가/안전 거절을 성공으로 바꾸거나 불량 원본 사용으로 우회하지 않는다. 안전 거절은 재문구/다른 도구로 반복하지 않는다.
- 자동 흐름의 코드·계약 테스트와 실제 이미지 재생성/시각 검수·운영 워커 실행은 다른 증거다. 자동 판별이 모든 오류를 발견한다고 보장하지 않으며 실제 발견된 오류는 합격 표시를 취소하고 새 검수를 요구한다. 기존 대본·음성은 보존한다.

## 실행 가능한 개선 지침·재발 검사 — 2026-11-24

문서 확인만으로 적용 완료를 보고하지 않는다. `docs/wuxia-generation-rules.json`의 현재 규칙과 로컬 운영자가 명시적으로 적용한 개선 지침을 매 생성 단계에서 다시 읽고 그 SHA를 결과에 기록한다. 사용자 수정 저장은 자동 지침 검수 통과가 아니다. 지침 버전이 바뀐 프롬프트·생성 계획·원화는 해당 범위의 재검토 대상으로 표시한다.

수동 무협 원화의 실제 도구 입력은 `worker.wuxia_generation_gate.prepare_scene_imagegen_arguments`로 준비한다. 직전 실제 그림/SHA/관찰 부위, 현재 대본 해시, 인물과 적의 위치·방향·동작 단계, 고정 자산과 사건 상태, 화풍과 공간·자세 자료, 재사용 영역, 접촉의 구조·작동·결과·선행 컷이 없으면 도구 인자를 내주지 않는다. 경로/SHA 확인은 시각적 정답 보증이 아니므로 실제 픽셀 검수를 별도로 수행한다.

이번 2화 재발 검사 사례: 석상 소매를 관절로 단정, 단도 형태 변경, 오른팔에 왼손 접합, 공격 중인 석상의 진열/착석 상태 초기화, 연청색 천의 다리 좌우 변경. 실패 기록은 장면 및 실제 원본 SHA에 연결하고 사용 제외한다. 문제를 해결했다는 문장이나 이전 버전의 검수로 새 원화를 승인하지 않는다. 기존 1~5씬 시안의 종전 검수 완료 주장은 철회하고 사용자 지적을 우선 반영한다.


## 2026-11-25 화면·내레이션·대사 분리
공통 실행 기준은 `worker/wuxia_script_style.py`의 `wuxia_three_channel/v1`. 수동 생성/독립 검토와 무협 자동 작성/수정에 함께 포함한다.
- 화면은 구도·동선·접촉·검기/파편을 구체적으로 쓰고 추상 감정은 보이는 행동으로 바꾼다. 한순간을 여러 컷으로 강제하지 않는다.
- 내레이션은 화면 밖 인과·과거·심리·무공 맥락만. 각 문장을 같은 컷과 대조해 행동 중계를 제거한다.
- 대사는 인물별 말투로 짧게. 두 자막 줄을 지향하되 실제 줄바꿈은 최종 화면에서 확인한다. 고어체를 일괄 강제하지 않는다.
- 무음/내레이션 중심/대사 중심으로 호흡을 조절한다. 3~5초는 참고이고 고정 길이·발화 할당량이 아니다.
- `sfx:[문자열]`, `screen_text:[문자열]`는 낭독 제외. `spoken_blocks`만 실제 음성 순서로 보존한다.
- 예시 문파/초식을 복사하지 않고 확정 세계관을 따른다. 확정본은 요청 없이 수정하지 않는다.
