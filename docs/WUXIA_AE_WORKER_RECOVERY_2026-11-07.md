# 무협 AE 워커 소스 복구

1·2·3화 제출 입력은 실제 상태 원화와 말풍선·입모양 및 `wuxia_native_timeline/v3` 효과를 포함한다. 그러나 2026-11-07 현재 AE PC의 실제 1화 결과 26개는 `unchanged_source_passthrough/v1` PNG였다. 큐의 제작·검수 진행 표시는 무협 연출 실행의 증거가 아니었다. 이 출력은 완성 효과본으로 인정하지 않는다.

세 작업은 `awaiting_worker_update`, `enabled=false`로 보존했다. 원본·음성·동결 입력과 이전 출력 증거를 유지한다. 웹 배포와 AE PC의 Python 프로세스 갱신을 구분한다. 서버는 `required_worker_contract` 및 현재 점유 토큰에 묶인 지원 확인이 없는 구형 실행·완료를 거부한다. 구형 차단과 유효한 지원 확인을 실제 DB 트랜잭션으로 검사하고 롤백했다.

## AE PC에서 이어갈 순서

1. `python worker/local_media_supervisor.py --stop`으로 현재 작업 종료 후 새 점유를 멈춘다. `--status`에서 실제 중지를 확인한다. 다른 사용자 작업을 강제 종료하지 않는다.
2. `git status --short --branch`와 원격을 확인한다. 로컬 변경을 보존한 상태에서 `git fetch origin`, `git merge --ff-only origin/main`을 각각 실행한다. 충돌 시 자동 삭제·강제 초기화하지 않는다.
3. 기존 환경·자격 증명으로 감독 프로세스를 재시작해 최신 모듈을 읽게 한다. Windows 설치 프로그램이나 릴리스 태그는 만들지 않는다.
4. `python scripts/std_resume_wuxia_native.py`로 세 지정 작업의 소유권·상태·지원 계약을 검사한다. 실제 AE와 aerender가 있는 갱신 호스트에서만 `--enqueue`로 재개한다. 원화 그대로 넘긴 이전 결과는 증거로 보관하고 새 렌더 캐시로 쓰지 않는다.
5. 실제 결과의 `ambient_renderer`와 `adobe_flat_renderer`, 동결 계약 및 최종 MP4 SHA·길이·디코딩·효과 프레임을 확인한다. 등록 성공이나 JSX 준비만으로 실제 출력 완료를 보고하지 않는다.

작업 ID: 1화 `a05142f9-e6f6-4a94-b3c1-fd3188bd97e1`, 2화 `29ed803a-ffbd-4cfa-85ac-122bcba8f5e1`, 3화 `c2dd33e5-5920-4261-b372-106d3815efaa`.

로컬 근거는 `output/wuxia-effects-episodes01-03/AE_WORKER_VERSION_REPAIR.json`, `before-worker-version-hold-*.json`과 `QUALITY_NOTES.md`다. 실제 브라우저 재생 검사는 Chrome의 확장 UI 차단이 해제된 뒤 이어간다.

검증: 무협·워커 계약 Python 34개, 입모양 런타임·형상·준비 레이어 27개, 웹 회귀 36개가 통과했고 웹 프로덕션 빌드도 완료했다. 구형 일반 입모양 큐 테스트 3개는 변경 전 소스를 별도 프로세스에서 로드해도 동일하게 실패했다. 해당 테스트의 작업 fixture에 현재 필수 `pipeline_version=2`가 없어 점유 전에 거부되며 이번 무협의 선택 입모양 변경과 구분한다. 관련 원본 테스트는 임의로 고치지 않았다.

유저웹 진행 표시는 네이티브 무협 합성 증거가 있는 출력만 집계한다. 지원하지 않는 워커가 원화만 넘긴 결과는 합성 출력 수에 포함하지 않으며, 업데이트 필요 상태를 한국어로 표시한다.

3화 11씬 두 번째 상태의 손 해부학 보정 후 새 원화 지문으로 다시 동결했다. 기존 3화 작업 `59cbfd69-526b-4613-86b0-7ea17be6b1df`는 새 작업 `c2dd33e5-5920-4261-b372-106d3815efaa`로 대체되어 옛 원화를 렌더하지 않는다. 확정 음성·자막·기존 입모양은 보존했다.

## 초당 10회 흔들림 입력 갱신

2026-11-07 사용자 승인으로 흔들림 속도를 초당 10회 완전 왕복으로 고정하고 지속 시간을 독립화했다. 새 작업은 다음과 같으며 이전 작업은 `superseded`다. 원화·확정 음성·입모양은 보존했다.

- 1화: `91c265fe-12cf-4788-ba1d-e3eae9a3b2fe` (이전 `a05142f9-e6f6-4a94-b3c1-fd3188bd97e1`)
- 2화: `13f6e0a5-ab9f-4750-aa3e-0d5b895694dc` (이전 `29ed803a-ffbd-4cfa-85ac-122bcba8f5e1`)
- 3화: `9df7ce21-e660-4553-8577-778fc02b02f9` (이전 `c2dd33e5-5920-4261-b372-106d3815efaa`)

웹과 AE 제출 입력의 전체 44,016프레임 효과 값이 일치한다. AE는 HOLD 키로 이 값을 그대로 사용한다. 실제 AE 출력 완료와 구분한다. 새 작업은 AE 호스트 소스 갱신 후 위 재개 도구로 실행하며 `awaiting_worker_update`, `enabled=false` 상태다. 이전 입력의 재개 명령은 실행하지 않는다.

## 로컬 변경사항이 있는 AE 호스트

호스트 체크아웃이 분기되었거나 워커에 미커밋 변경이 있으면 강제 초기화·덮어쓰기를 하지 않는다. 최신 원격 소스로 별도의 detached worktree를 만들고 기존 자격 증명·Python·공용 상태 저장소를 사용한다. 유휴 감독 프로세스를 정상 종료한 뒤 최신 소스에서 재시작한다. 디스크 여유와 AE 중간 파일 용량을 먼저 확인한다.

`python worker/motion_automation_worker.py --once --job-id JOB_UUID`는 지정한 기존 작업 하나만 점유한다. 일반 큐의 제출 상태·활성화·재시도·워크플로·현재 lease 및 원화/음성 지문 검사는 그대로 유지한다. 다른 프로젝트를 대신 점유하거나 기존 작업을 강제 종료하지 않는다.

## 저용량 호스트의 무협 임시 영상

`AIR_WUXIA_RELEASE_NATIVE_TEMP=1`은 해당 렌더 시도가 새로 만든 `native.*`와 `base.mp4` 임시 영상에만 적용한다. 변환 영상의 전체 디코딩·해상도·길이 검증을 마친 뒤 SHA 및 검증 영수증을 남기고 임시본을 정리한다. 업로드 원본·원화·확정 음성·`voice-synced.mp4` 완료 씬·AE 프로젝트·JSX와 검수 기록은 대상이 아니다. 검증 실패 시 임시본을 보존한다. 다른 카테고리의 제작에는 적용하지 않는다.

실제 AE 2026 사전 출력에서 도형의 빈 `Shape.vertices` 배열 할당이 거부되었다. 파편과 말풍선 경로의 꼭짓점·접선을 일반 배열로 완성한 뒤 한 번에 설정하도록 수정했다. 수정 후 3화 11씬 실제 네이티브 출력 7초(24fps, 168프레임)를 디코딩해 5초 구간의 100회 방향 반전, 즉 50회 완전 왕복을 측정했다. 계획된 위치와 최대 차이는 0.055px 미만이다. 이 짧은 사전 출력과 회차 전체 완료는 구분한다.
