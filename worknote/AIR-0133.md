# AIR-0133: Per-Request Language Architecture

## Problem
`app_lang` was a global singleton mutated by each incoming request's language cookie.
In concurrent requests, the last writer won — cross-contaminating language for other users.

## Solution
Replaced global mutation with per-request `request.state.current_lang` injected in middleware.

## Priority chain (unchanged)
1. Cookie `language` (set on login / settings change)
2. Server default (`app_lang` loaded from `language.pref` / DB on startup)
3. Fallback `"en"`

## Files Changed

### main.py
- Added `_LANG_ALLOWED` constant
- Added `_resolve_request_lang(request)` helper
- Middleware: sets `request.state.current_lang` for every request
- Removed: `translator.set_lang()`, `app_lang = cookie_lang`, `templates.env.globals` mutation, `_live_app_state.switch_language()` from middleware

### app/routers/pages.py
- `_render()`: reads `request.state.current_lang`, injects `current_lang`, `window_lang`, `t` into context
- `page_video_upload` (2 calls), `page_subtitle_gen`, `page_settings`: same injection added

### app/routers/repository.py
- Replaced `templates.env.globals['t']` / `['current_lang']` manual update with context injection
- Removed stale `_app_state` import and `env.globals` module-level assignments

### app/routers/auth.py
- `_apply_login_language()`: removed `app_state.switch_language()` call
- SQLite save + `language.pref` write kept (server default for next startup)

### app/routers/settings.py
- `set_language()`: removed `app_state.switch_language()` block
- SQLite + `language.pref` + Set-Cookie kept

### services/app_state.py
- `switch_language()`: marked as Deprecated Wrapper (returns True, no-op)
- Kept for backward compatibility — no callers need updating

## CTO Decisions Applied
- `language.pref` → kept, write-only (server default seed)
- `global_settings.language` → kept as server default source
- `app_state.switch_language()` → kept as no-op deprecated wrapper
