# AIR-0134: Repository Templates Unification

Date: 2026-07-05
Branch: feature/AIR-0134-repository-templates-unification
Status: COMPLETE

## Problem

`repository.py` had a standalone `Jinja2Templates(directory=config.TEMPLATES_DIR)` instance
created at module level. This instance was separate from main.py's `templates` instance.

Because main.py's `env.globals` registrations (app_mode, user_email, is_independent, t_all,
AUTH_SERVER_URL, get_license_key, format_currency filter) only apply to the main.py instance,
the `/repository` page was rendering base.html with missing nav variables:
- `app_mode` → sidebar nav menu visibility broken
- `user_email` → user email not shown in sidebar
- `is_independent` → upload/reserve label wrong
- `t_all` → language-switch JS translations missing
- `AUTH_SERVER_URL` → admin link broken
- `get_license_key` → license display broken
- `format_currency` filter → token balance format broken

All other page routers (pages.py) receive main.py's templates via `init_pages(templates)`.
repository.py was the only router with its own separate instance.

## Solution

Applied the same `init_*(templates)` pattern used by pages.py.

## Changes

### app/routers/repository.py
- Removed: `templates = Jinja2Templates(directory=config.TEMPLATES_DIR)` (module-level)
- Added: `from typing import Optional`
- Added: `_templates: Optional[Jinja2Templates] = None`
- Added: `init_repository(templates: Jinja2Templates)` function
- Changed: `templates.TemplateResponse(...)` → `_templates.TemplateResponse(...)`
- Kept: all per-request context injections (current_lang, window_lang, t, membership, token_balance)

### main.py
- Added: `repository_router.init_repository(templates)` immediately after `pages_router.init_pages(templates)` (line 358)

## Not Changed (out of scope)

- POST /api/repository/create-plan duplicate endpoint in main.py — pre-existing, out of scope
- repository feature logic, Gemini calls, API structure
- AIR-0133 per-request language injection in repository_page() — kept as-is

## Architecture Note

After this fix, repository.py's `_templates` is the same object as main.py's `templates`.
All `env.globals` registered at startup (app_mode, user_email, is_independent, t_all,
AUTH_SERVER_URL, get_license_key, format_currency) are now available in repository.html
and its base.html inheritance chain.

Per-request context values (current_lang, window_lang, t, membership, token_balance)
continue to override env.globals at render time — same behavior as all other pages.
