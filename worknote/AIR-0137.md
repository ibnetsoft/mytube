# AIR-0137: /output 파일 접근 보안 복원

Date: 2026-07-05
Branch: feature/AIR-0137-output-security
Status: COMPLETE

## Problem

`GET /output/{file_path:path}`가 main.py에 2개 정의되어 있었다.

- **Line 185** (선등록, ACTIVE): `external/` 경로 + 일반 OUTPUT_DIR 서빙. auth 없음.
- **Line 365** (후등록, DEAD): OUTPUT_DIR만 서빙. `.mp4` → admin-only check 있음.

FastAPI 등록 순서로 인해 line 185가 항상 실행됨. line 365의 `.mp4 admin-only` 체크는 절대 실행되지 않았다. 결과: 인증된 모든 사용자가 렌더링 영상(.mp4)에 자유 접근 가능.

## CTO 결정 (최종 정책)

- `.mp4` 파일: **로그인 사용자만 접근 허용** (admin-only는 아님)
- `.mp4` 외 파일(이미지, 오디오, 자막, JSON 등): 기존과 동일 (auth 없이 서빙)
- `external/` 경로 `.mp4`: 동일하게 로그인 필수
- Path traversal 방어: normpath + base directory containment check 추가
- 더 정밀한 project ownership 기반 권한 체계는 별도 AIR에서 처리

변경 후:
```python
# [AIR-0137] /output 파일 서빙 — .mp4는 로그인 필수, path traversal 차단
@app.get("/output/{file_path:path}")
async def serve_output_file(file_path: str):
    from services.auth_service import auth_service

    if file_path.startswith("external/"):
        rel = file_path.replace("external/", "", 1)
        appdata_base = config.LOCAL_APP_DATA_DIR
        abs_path = os.path.normpath(os.path.join(appdata_base, rel))
        norm_base = os.path.normpath(appdata_base)
        if not (abs_path == norm_base or abs_path.startswith(norm_base + os.sep)):
            raise HTTPException(status_code=403, detail="Access denied.")
        if not os.path.exists(abs_path):
            raise HTTPException(status_code=404, detail="File not found")
        if abs_path.lower().endswith(".mp4"):
            if not auth_service.get_user_email():
                raise HTTPException(status_code=403, detail="Login required to access video files.")
        return FileResponse(abs_path)

    full_path = os.path.join(config.OUTPUT_DIR, file_path)
    norm_output = os.path.normpath(config.OUTPUT_DIR)
    norm_full = os.path.normpath(full_path)
    if not (norm_full == norm_output or norm_full.startswith(norm_output + os.sep)):
        raise HTTPException(status_code=403, detail="Access denied.")
    if not os.path.exists(full_path):
        raise HTTPException(status_code=404, detail="File not found")
    if full_path.lower().endswith(".mp4"):
        if not auth_service.get_user_email():
            raise HTTPException(status_code=403, detail="Login required to access video files.")
    return FileResponse(full_path)
```

## 최종 /output 보안 정책

| 경로 | 확장자 | 결과 |
|------|--------|------|
| `/output/external/*.mp4` | `.mp4` | 비로그인 → 403 / 로그인 → 200 |
| `/output/external/*` | 기타 | path traversal 통과 시 200 |
| `/output/*.mp4` | `.mp4` | 비로그인 → 403 / 로그인 → 200 |
| `/output/*` | 기타 (.png, .mp3, .json ...) | path traversal 통과 시 200 |
| path traversal 시도 | any | 403 (Access denied) |
| 존재하지 않는 파일 | any | 404 |

로그인 판정: `auth_service.get_user_email()` 반환값이 truthy이면 로그인.

## Path Traversal 방어

두 경로 모두 동일한 패턴 적용:
```python
norm_base = os.path.normpath(base_dir)
if not (abs_path == norm_base or abs_path.startswith(norm_base + os.sep)):
    raise HTTPException(status_code=403, detail="Access denied.")
```

- `../../etc/passwd` 시도 → normpath 후 base_dir 밖 → 403
- `../MyAppExtra/secret.mp4` 식의 prefix 충돌 → `+ os.sep` 로 차단
- 기존: normpath만 있고 containment check 없었음 (external/ 경로) / normpath 자체 없었음 (output 경로)

## 남은 보안 과제

1. **Project ownership 기반 .mp4 접근 제어** — "자신의 프로젝트 영상만 볼 수 있다" 정책
   → 별도 AIR에서 project_id 기반 소유권 검증으로 구현 예정
2. **비로그인 썸네일/이미지 노출** — 현재 로그인 없이 이미지 접근 가능
   → 현재 앱 구조에서 허용 범위. 필요 시 별도 AIR.
3. **`external/` 경로 비-mp4 파일 auth 없음** — 현재 유지
   → 로컬 파일이므로 외부 노출 위험 낮음. 단, 서버가 공개될 경우 재검토 필요.
