# AIR-0132 — Per-User Preferred Language + Browser Language Detection

Date: 2026-07-05
Branch: feature/AIR-0132-preferred-language
Status: COMPLETE (pending Supabase migration + PR)

## Summary

Fixes always-Korean-on-login bug. Adds per-user `preferred_language` stored in Supabase profiles,
with browser language auto-detection for new/unset users.

## Language Decision Priority (login)

1. `req.lang` — user explicitly selected on login page
2. `profile.preferred_language` — saved from previous session (Supabase)
3. `req.browser_lang` — navigator.language from client
4. `Accept-Language` header — server-side fallback
5. `en` — final fallback

## Migration Note (CRITICAL)
`preferred_language` column does NOT exist in Supabase yet.
Until migration is applied:
- update_preferred_language() calls will return HTTP 400 (column unknown) → logged as warning, not fatal
- Language priority still works via req.lang + browser detection (steps 1, 3, 4, 5)

## Known Limitation (out of scope)
- app_lang is a global singleton — in multi-user environments the last login user's language
  affects all concurrent sessions until next request. Full fix requires per-request language
  injection (separate AIR).
