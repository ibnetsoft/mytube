# AIR-0221B: Remove Instant Referral Reward

## Goal
Remove the $20 flat-bonus "instant referral reward" side-channel (Gen 4, identified during the AIR-0221 audit) that bypasses `referral_commissions` and conflicts with the CTO-approved 2-level referral model. Code removal only — table not dropped yet, per instruction.

## Root cause / why this existed
A separate reward path bolted onto `auth-web/app/api/admin/publishing/route.ts`'s publish-approval endpoint: when a user's *second* video got approved, and that user had a referrer (`profiles.referred_by`), the referrer got a flat $20 credited via `increment_usdt_balance`, logged to `referral_rewards_log`. This ran entirely outside the `referral_commissions` ledger — a second, parallel payout mechanism with no relationship to the level-based commission percentages.

**Already known broken before this ticket** (found during AIR-0221A): `increment_usdt_balance` references a nonexistent `profiles.updated_at` column (`42703`, confirmed live), so the $20 credit has been silently failing — while the `referral_rewards_log` insert still ran unconditionally afterward, regardless of whether the credit above it actually succeeded. Consistent with `referral_rewards_log` having 0 rows in production (confirmed during Stage 1 pre-flight): if this had ever worked, and any 2nd-approval events had occurred, rows would exist.

## Actions taken

**`auth-web/app/api/admin/publishing/route.ts`** — removed the entire `// [NEW] Referral Reward Logic` block (previously lines 206–252) from the `PATCH` handler:
- The `profiles.referred_by` lookup.
- The "2nd approved video" count check.
- The `increment_usdt_balance` RPC call.
- The `referral_rewards_log` dedup check and insert.

Nothing else in `PATCH` was touched — the publish-approval status/metadata update (`publishing_requests` update, the `project_id` validation guard, the response shape `{ success: true, data: data[0] }`) is unchanged, byte-for-byte, before and after this block.

**`referral_rewards_log` table** — **not dropped**, per instruction. Marked shelved/deprecated below.

## `referral_rewards_log` — shelved / deprecated

- **Status**: deprecated, unused as of this ticket. No application code reads or writes it anymore (the only writer, `publishing/route.ts`, was just removed; nothing else in the codebase references this table).
- **Row count**: 0 (confirmed during AIR-0221 Stage 1 pre-flight) — no historical data exists to migrate, archive, or preserve.
- **Not dropped now**, per explicit instruction. Recommend actual `DROP TABLE public.referral_rewards_log` be bundled into the same later cleanup pass as the Gen 2/3 shelved-object removal (`CONSOLIDATION_PLAN.md` §10.2's eventual cleanup stage), not as its own migration — it's a single small table with zero data and zero remaining callers, so there's no reason to fast-track or delay it independently of that pass.
- Schema (for reference, unchanged): `id, referrer_id, referred_user_id, amount, created_at`.
