## Problem
Worker UI language switches triggered live AI translation calls on every language change.
The translation chain (Google Translate HTTP → Gemini → Claude) ran for all visible
recommended topic cards on every language icon click. In-memory cache `_TOPIC_TRANSLATION_CACHE`
was lost on server restart, so the first switch after any restart always paid full AI cost.

The root cause: Supabase `topics_queue` had no translation columns. Translations existed
only in memory.

## Solution
Add six nullable TEXT columns to `topics_queue` and use them as a persistent cache.

### New DB columns (topics_queue)
- `topic_vi`, `topic_en`, `topic_th`
- `category_name_vi`, `category_name_en`, `category_name_th`

### New functions in user_topics.py
- `_fetch_stored_translations(supabase_url, headers, topic_ids, lang_code) -> dict`
  Reads translation columns for a list of topic IDs. Returns {} on pre-migration state
  (non-200 response) or any network error — callers fall through to AI gracefully.
- `_save_translations_to_db(supabase_url, headers, translations, lang_code) -> None`
  Persists AI-translated results back to topics_queue via PATCH. Fire-and-forget
  (asyncio.create_task); does not block the HTTP response.

### Modified endpoint
`POST /api/user/recommended-topics/translations`:
1. Fetch stored translations from DB for all requested topic IDs.
2. Identify topics still missing a stored translation.
3. Call `_translate_topics_batch()` (existing AI chain) only for the missing subset.
4. Save new AI translations to DB via `asyncio.create_task` (non-blocking).
5. Merge stored + AI results. DB value wins on conflict.
6. Return same response structure as before (`{"status": "ok", "translations": {...}}`).

### In-memory cache
`_TOPIC_TRANSLATION_CACHE` retained as secondary layer for individual `_translate_text_via_google()`
calls (Google Translate HTTP fallback for single-text lookups). DB is checked first at
the API level before any individual text lookup is triggered.

### auth-web PUT handler
`auth-web/app/api/admin/topics-queue/route.ts` — When an admin edits a topic title,
all six translation columns are now reset to null so workers see fresh translations on
next language switch. Uses the existing `isMissingColumnError` guard to fall back to
topic-only update when migration has not yet been applied.

## Deployment Sequence
1. Merge PR #31.
2. Apply `migrations/air_0128_topics_queue_translation_columns.sql` to Supabase SQL Editor.
3. Run backfill (order: vi first, then en, then th):
   ```
   python scripts/backfill_topic_translations.py --lang vi --dry-run
   python scripts/backfill_topic_translations.py --lang vi
   python scripts/backfill_topic_translations.py --lang en
   python scripts/backfill_topic_translations.py --lang th
   ```
4. Verify: a worker language switch should return translations instantly with no AI call in logs.

## Remaining Risks
- Backfill must be run manually after migration; until then, runtime AI fallback still runs.
- Admin topic edits that race with an in-flight translation request may briefly serve stale
  translations (self-corrects on next language switch).
- scripts/backfill_topic_translations.py uses Google Translate free tier — rate limit
  (~100 req/min). Use `--batch 30` for large queues.
