## What Was Built

File: `.github/workflows/windows-release.yml` (full rewrite of existing stub)

### Triggers
- **Push tag**: `git tag v1.0.0 && git push origin v1.0.0`
- **Manual dispatch**: GitHub Actions UI with `version`, `channel`, `draft`, `prerelease` inputs

### Workflow Steps

1. Checkout full history
2. Resolve version/channel from tag or manual input; compute `next_build = counter + 1`
3. Set up Python 3.13 (cached pip)
4. Install Inno Setup via Chocolatey
5. `build_windows.ps1 -Version $ver -Build $build -Channel $channel`
   → produces all artifacts + SHA256 sidecars
6. `upload-artifact` → workflow run artifacts (30-day retention)
7. `release_github.ps1` → creates GitHub Release, uploads all artifacts
8. Commits updated `build_counter.txt` back to repo with `[skip ci]` tag

### Build Number Auto-Increment in CI

```yaml
# CI reads current counter, computes next
$current = [int](Get-Content build_counter.txt)
$next = $current + 1
# Passes to build script; build script writes $next back to file
# Post-build: git commit "chore: increment build counter to $next [skip ci]"
```

### Artifacts uploaded to each GitHub Release

- `AIRStudio-{version}-win-x64.zip`
- `AIRStudio-{version}-win-x64.zip.sha256`
- `AIRStudioSetup-{version}.exe`
- `AIRStudioSetup-{version}.exe.sha256`
- `latest.json`
- `latest.json.sha256`

### Required GitHub settings

| Setting | Value |
|---------|-------|
| `GITHUB_TOKEN` permissions | `contents: write` (in workflow `permissions:` block) |
| Branch protection | Allow `github-actions[bot]` to push counter update |

## Notes

- The workflow pushes the counter commit to the triggering branch/tag ref.
  If that fails (protected branch), it falls back to `main`. A warning is logged.
- `[skip ci]` in the commit message prevents an infinite CI loop.
