# AIR-0122: Referral 2.0 Foundation & Default Sponsor

## Goal
Implement the foundation for the Referral 2.0 lifetime revenue sharing system. Shift from optional but unmanaged referral codes to a strictly managed UUID-based Default Sponsor system, ensuring every new user is connected to the referral tree. 

## Actions Taken
- Modified `app/routers/auth.py` to strictly validate inputted referral codes before registration proceeds, blocking invalid ones.
- Modified `app/routers/auth.py` and `services/web_admin_client.py` to query the `global_settings` table for `referral_default_sponsor_uuid` and inject it into the user's `raw_user_meta_data` if no referral code is provided.
- Updated the Supabase SQL trigger `on_auth_user_created` to correctly parse `referred_by_id` as a fallback when `referred_by_code` is absent, permanently fixing the user's `referred_by` value.
- Created `auth-web/app/api/admin/settings/referral/route.ts` API with strict server-side validation for `referral_mode` and `settlement_cycle` Enums.
- Created Next.js Admin UI (`auth-web/app/admin/settings/referral/page.tsx`) to easily manage global settings, including a user search field to assign the Default Sponsor.
- Added `migration_referral_2.0.sql` to connect all existing users who have `referred_by IS NULL` to the Default Sponsor.

## Status
- `main` merged.
- E2E flow verified.
- The next step is to implement the Settlement Worker that relies on this established tree.
