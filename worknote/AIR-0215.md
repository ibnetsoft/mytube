## Objectives

## Implemented

### Item 1 & 2 — SHA256 in AIRUpdater + abort on mismatch

`AIRUpdater.py` now accepts `--sha256 <hex>` CLI arg.
If provided, SHA256 is verified **before extraction**. On mismatch:
- Temp package is deleted
- `ValueError` is raised — no extraction, no swap
- Exit code 1

`AIRLauncher.py` passes `--sha256 <hash>` to AIRUpdater when spawning.
SHA256 is verified twice: once in Launcher (before spawn), once in Updater (before extract).

### Item 3 — current.json schema hardening

Both `current.json` and `app/version.json` now use the canonical schema:
```json
{"version": "1.2.3", "installed_at": "2026-07-08T12:00:00Z", "build": 215}
```
`AIRUpdater.update()` calls `_version_record(version, build)` to write both files.
`build_windows.ps1` writes the same schema at initial install time.

### Item 4 — build field in build_windows.ps1

`-Build <int>` parameter added (default 0).
`$VersionRecord` object written to both `current.json` and `app/version.json` with `installed_at` (UTC) and `build`.
`latest.json` manifest now includes `"build": $Build`.

### Item 5 — exe Version Resource fallback

`AIRLauncher.py: _exe_version(exe_path)` reads PE FileVersion via PowerShell:
```
powershell -NoProfile -NonInteractive -Command "(Get-Item '...').VersionInfo.FileVersion"
```
Normalises 4-part "2.0.0.0" → 3-part "2.0.0".

Priority chain in `current_version(root)`:
1. `current.json.version`
2. `app/version.json.version`
3. exe VersionInfo
4. `"0.0.0"`

### Item 6 — Startup auto-recovery (app/ absent + app_backup/ present)

`AIRLauncher.py: _recover_app_if_needed(root)` added.
Called **before** `cleanup_update_artifacts()` in `main()`.
If `app/` missing and `app_backup/` exists → `os.rename(app_backup, app_dir)`.

`cleanup_update_artifacts()` updated: only removes `app_backup/` if `app/` exists
(prevents accidentally deleting the only remaining copy).

Boot order in `main()`:
```
_recover_app_if_needed(root)   ← restore if needed
cleanup_update_artifacts(root) ← clean app_new/, extract/; app_backup/ only if safe
check_for_update(root)
launch_app(root)
```

### Item 7 — Launcher guard

`AIRUpdater.py: _guard_launcher_not_overwritten(app_new, root)`:
- Guard 1: `app_new` must not be inside `Launcher/` — raises `ValueError`
- Guard 2: if `AIRLauncher.exe` exists in payload root, it is removed (defensive)
  - If removal fails → `ValueError` raised, swap aborted

### Item 8 — Structured [EVENT] log markers

`_event(name, **kwargs)` helper added to both files.
All 8 mandatory events implemented:

| Event | File | Location |
|-------|------|----------|
| `update_check_started` | Launcher + Updater | Before manifest fetch / before extraction |
| `download_started`     | Launcher | Before `download_file()` |
| `download_completed`   | Launcher | After file written |
| `sha256_verified`      | Launcher + Updater | After hash passes |
| `extract_completed`    | Updater | After `extractall()` |
| `swap_completed`       | Updater | After step 5 rename |
| `rollback_executed`    | Updater | In except block |
| `app_launched`         | Updater | After `subprocess.Popen` |

### Item 9 — E2E QA document

`project_status/QA_AIR_0215_E2E.md` — 7 scenarios:
1. Normal update (happy path)
2. Already up to date
3. SHA256 mismatch
4. Swap failure → rollback
5. Launcher startup recovery
6. Launcher guard (AIRLauncher.exe in payload)
7. Version detection priority chain

## Remaining Risks

| Risk | Severity | Notes |
|------|----------|-------|
| `_exe_version()` depends on PowerShell path | Low | PowerShell always present on Windows 10+ |
| GitHub CDN unavailable at launch | Low | Handled: update check fails gracefully, app launches |
| NTFS rename across volumes (unlikely) | Low | `os.rename` fails if src/dst on different drives; user would need custom install location |
| App holds lock on `app_new/` during cleanup | Low | `_safe_rmtree` logs warning and continues |
| Installer creates `current.json` with `build=0` if -Build not passed | Low | Correct behaviour for manual/dev builds; prod CI must pass `-Build` |
