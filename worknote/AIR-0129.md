# AIR-0129 — Admin Auto-Translation Pipeline

Date: 2026-07-04
Branch: `air-0129-admin-auto-translation`
Base: `air-0128-db-persistent-translation`

## Problem

AIR-0128 solved the User App runtime AI translation cost by checking Supabase columns first.
However, the columns were still NULL at first access — the User App remained the first entity
to call AI and fill them. For topics created or edited after AIR-0128 deployment, the first
worker to open the language switcher still paid the full AI translation latency.

## Solution

The admin API (route.ts) now triggers translation proactively:
- **POST** (generate topics): fires background translation immediately after the 200 OK response
- **PUT** (edit topic text): resets 6 translation columns to NULL, sets `translation_status=pending`,
  fires background translation immediately after the 200 OK response

This guarantees that by the time any worker switches language, translations are already in DB.

## Background Task Structure (TypeScript)

```
POST/PUT handler
  → DB save → 200 OK returned immediately
  ↓ (void, non-blocking)
translateAndSaveTopics(topicIds, supabase, geminiApiKey)
  1. UPDATE translation_status = 'running'
  2. SELECT id, topic, categories(name) for topicIds
  3. for lang in [vi, en, th]:
       buildTranslationPrompt(topics, lang.code, lang.name)
       Gemini generateContent (responseMimeType: application/json)
       parseTranslationResponse → accumulate allTranslations[id][column]
  4. for each topic with ≥1 translation:
       UPDATE topic_vi, topic_en, topic_th,
              category_name_vi, category_name_en, category_name_th,
              translated_at = now, translation_status = 'completed'
  5. for each topic with 0 translations:
       UPDATE translation_status = 'failed'
  catch any outer error:
       UPDATE translation_status = 'failed' for all topicIds
```

**Background task pattern**: void Promise (Next.js 14). Vercel keeps the function alive
until all Promises resolve. `after()` requires Next.js 15.1+ which is not in use here.

## Migration SQL (apply after AIR-0128 migration)

```sql
ALTER TABLE topics_queue
    ADD COLUMN IF NOT EXISTS translated_at      TIMESTAMPTZ DEFAULT NULL;

ALTER TABLE topics_queue
    ADD COLUMN IF NOT EXISTS translation_status TEXT        DEFAULT NULL
        CHECK (translation_status IS NULL
               OR translation_status IN ('pending', 'running', 'completed', 'failed'));
```
