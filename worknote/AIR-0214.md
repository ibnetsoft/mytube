# AIR-0214 Windows Installer + Auto-Update System

**Date**: 2026-07-08
**Branch**: feature/AIR-0214-windows-installer
**Status**: CONDITIONAL APPROVAL — pending AIR-0215 follow-up

## Objectives

1. Fix critical bug in AIRUpdater.py: `copy_tree()` deletes `app/` before copying,
   leaving no recovery path if the copy fails mid-way.
2. Replace with atomic swap: `app/ → app_backup/ → app_new/ → app/`.
3. Add structured logging to both launcher and updater.
4. Embed `version.json` in the app payload (build script change).
5. Clean up leftover update artefacts on every launcher startup.
6. Document the full bootstrap system in BOOTSTRAP.md.

## Key Technical Notes

### Atomic Swap (AIRUpdater.py)
- `os.rename(src, dst)` on NTFS within the same volume is atomic (MoveFileEx).
- Destination must NOT exist before rename — assert with FileExistsError.
- Swap sequence: `app_new/` ready → `app/ → app_backup/` → `app_new/ → app/`.
- Rollback: if step 2 rename fails and `app/` is absent but `app_backup/` exists, restore immediately.

### Version Detection Priority (AIRLauncher.py)
1. `<root>/current.json` → `version`
2. `<root>/app/version.json` → `version`  (new fallback — written by build + updater)
3. `"0.0.0"` default

### check_for_update() return value
- Now returns `bool`: `True` = updater spawned (caller must exit), `False` = no update or error.
- Previous version returned `None` and called `sys.exit(0)` internally — opaque side-effect.

### Logging
- `%APPDATA%\AIRStudio\logs\launcher.log` — written by AIRLauncher
- `%APPDATA%\AIRStudio\logs\updater.log`  — written by AIRUpdater
- Both use `logging.FileHandler` + `logging.StreamHandler` so output is visible when run manually.
